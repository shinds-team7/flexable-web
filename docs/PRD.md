> 개발 기준 요약이다. 근거·숫자·경쟁 분석은 [01 기획서](product/01-product.md), 화면은 [02 디자인](product/02-design.md), 구조는 [03 아키텍처](product/03-architecture.md)·[04 서비스 경계](product/04-service-boundaries.md)에 있다. 이 문서를 바꾸는 PR에는 `spec-change` 라벨과 [CHANGELOG](CHANGELOG.md) 한 줄이 필요하다.

## 1. 서비스 목표

**"첫 금융 선택 전에, 내가 아낀 돈으로 먼저 연습하는 입구."**

청년은 돈을 모으지만(76.5%가 매달 평균 94만 원) 저축은 적금에 머물고, 주식은 무섭거나 감으로 시작한다. 웹은 앱에서 모은 시드머니로 지난 주식·적금을 실험해 보고, 목표를 세우고, 청년 금융 소식을 챙기는 곳이다. 앱(하루 예산 관리, [flexable-app](https://github.com/shinds-team7/flexable-app))에서 매일 기록하고, 남긴 돈이 시드머니가 되어 웹에서 연습하고, 다시 앱으로 돌아가 절약하는 흐름을 만든다.

## 2. 사용자

| 순위 | 누구 | 원하는 것 |
|---|---|---|
| 1 | 첫 취업 3년 안의 사회초년생(23~29세), 월 실수령 200만~300만 원대 | 매달 얼마 남는지, 남은 돈을 어디 둘지 |
| 2 | 30~34세 직장인, 적금만 있고 주식은 쉬는 중 | 다시 시작하기 전 연습, 적금과 주식 비교 |
| 3(채널) | 대학 3~4학년·취업준비생(금융 강좌·특강) | 수업에서 쓰는 연습 도구 |

추가 스펙: 기존 F1 `/invest`는 **투자 인사이트**로 메뉴 이름을 바꾼다(메뉴 이름은 반영됨, 화면 개편은 #89 구현 PR. 기간은 3개월·6개월·1년·3년). 화면은 [개편 결정](decisions/2026-10-26-invest-insight-redesign.md)에 따라 주가를 보는 화면으로 바꾸고, `POST /simulations/run` 계산·응답은 유지한다. 신규 `/simulation`은 업종별 무작위 종목, 과거 일봉 캔들 재생, 공시 시점의 방향 예상·가상 매매 선택을 제공한다. [분리 결정과 데이터 보충 계획](decisions/2026-10-26-investment-practice.md), [정책 §5](policies.md#5-사건-퀴즈-투자-시뮬레이션), 계약의 `/practice/*`가 기준이다. 화면·API·OHLC·업종 수집은 #88로 구현됐다(실제 키움 자료로 하는 운영 검증은 HANDOFF). 같은 화면의 **가상 시뮬레이션** 탭은 AI(Gemini)가 만든 가상 종목·사건 글(자동 검사 후 공개, 뉴스 입력 없음, 제목은 실제 공시 제목 형식·본문은 중립 사실)과 수집 종목의 5년 공시 전체·시세에서 뽑은 룰셋으로 서버가 만든 가상 시세(세션 시작 연도 + 10년의 평일 날짜, 120~250거래일, 문제 3~5개)로 사건 매매를 연습하고, 채점 없이 사건마다 이후 5거래일 가상 등락과 그 유형 공시의 과거 통계를 보인다(#253, 11-05). [결정](decisions/2026-11-04-virtual-simulation.md), [정책 §8](policies.md#8-가상-시뮬레이션virtual-sim), 계약의 `/virtual-sim/*`가 기준이며 #235로 구현·병합됐다. 가상 시뮬레이션에는 **회원 월간 대회**(#252)를 더한다: 시즌마다 배치고사(가상 사건 10문제, 과거 경향 채점)로 1천만·5천만·1억 판 중 시작 판을 정하고, 같은 판 안에서 잔액을 이어 가며(사건 4개·대회 판 채점 없음·하루 10판), 하루 목표(그날 판들의 유지 대비 초과 수익률 평균 +1%)를 넘으면 +100·못 넘으면 −100을 주마다 더해 +400이면 승급·−400이면 강등한다(100점 단위, #308). 랭킹은 판별 점수 순(익명 별명·상위 100위)이다. 판별 상위권 앱 전용 스킨·코인 보상은 방향만 정했고 지급은 후속이다. [대회 결정](decisions/2026-11-05-virtual-sim-contest.md), [정책 §8-8](policies.md#8-8-대회배치고사하루-목표주간-점수판별-랭킹), 계약의 `/virtual-sim/contests/*`·`/me/virtual-sim/contests`가 기준이며 구현 전이다. 결제는 없다.

정기예금(`/deposit`)은 finlife 수집·서버 만기 계산·실제 API 화면 연결까지 병합됐다(#140, #236). 파킹(`/parking`)·CMA(`/cma`)는 공시 금리·조건 조회와 최대 3개 비교를 제공한다(#218·#221·#227·#236). 로컬 공식 출처 검증 범위는 파킹 211개·CMA 12개이며 전체 시장 수집이나 운영 반영 완료를 뜻하지 않는다. 우대조건 분류·로고 #143, 미연결 출처 #245, 운영 확인 #246, 금액별 계산·추가 유형 #247은 남아 있다. 전체 열린 이슈의 미완료 이유와 착수 조건은 [HANDOFF](product/HANDOFF.md#2026-11-05-최신-상태main-b73bcb1)를 따른다.

## 4. 개발 범위

- **11/1(일) 기능 동결**, 11/2~11/4 실측·시연. 남은 Must와 담당은 [HANDOFF](product/HANDOFF.md) "남은 개발 작업과 완료 조건"에 있다.
- Must: F0·F1·F5·F6과 고지·데이터 권리, F2 실제 공시·정책 적금 계산 차이 해소, F4 매일 갱신되는 실제 소식(자동 게시·AI 요약).
- Should: F8 이벤트 3종(체험 시작·첫 결과·핀 열기), F9 상품 카드. 공유 링크는 F3와 함께 뺐다.
- 서버·DB·계정은 앱과 따로 둔다. 앱 정보는 사용자가 [앱 연동하기]를 했을 때만 서버끼리 받는다(04).

## 5. 하지 않는 것(무료·유료 모두)

실제 매매·자동 주문·계좌 운용, 계좌 연결(구현 전에는 화면에 쓰지 않음, 발표에서는 향후 계획으로만), 사용자 간 수익률 순위, 가입 중개, 개인 데이터 판매, 앱 안 가격·결제 링크, 수익·목표 달성 보장.

**맞춤 금융상품·종목·배분 비중 제안은 새 F7에서 허용한다.** 기존의 전역 제외 항목은 이 기능에 적용하지 않는다. F10 상품 나열과 다른 화면은 기존 범위를 유지하며, 별도의 자유 대화형 종목 상담을 추가하는 결정은 아니다. 추정 고지와 계산 근거를 표시하고, 공개 운영 방식의 투자자문·중개 해당 여부는 별도로 확인한다([10-29 결정](decisions/2026-10-29-goal-scenarios.md)).
