# 투자 인사이트 화면 개편: 주가 차트·시장 띠·랭킹·모션

- 날짜: 2026-10-26 · 결정한 사람: 리드(SXXNHU) · 관련: Issue #89, PR #90
- 상태: #90으로 병합. 2026-10-27 구현 리뷰 피드백으로 ③·④·⑧ 일부를, 2026-10-29 #94 조사로 ⑤ 시장 띠 칸·제공처를 바꿨다(아래 "변경 기록").
- 영향: 웹 프론트(`/invest`), 웹 백엔드(market·ingest), API 계약. 시장 띠 수집 일부는 #94. 앱·시연(`mobile-demo/`)은 범위 밖이다.
- 기준: PRD F1·F5·§5, [투자 인사이트 분리 결정](2026-10-26-investment-practice.md), [10-24 결정 ①](../product/decisions.md), 02 §5-4·§6·§7-3, web-api.yaml `/market/*`.

## 결정

1. **`/invest`(투자 인사이트)는 주가를 보는 화면이 된다.** 차트의 세로축을 내 돈 평가액에서 **주가(원)**로 바꾼다. 사건 핀·상세 패널은 그대로 쓰되, 내 돈 금액 항목은 뺀다(②). 기본은 시가총액 1위 종목 하나, 기간 3개월이다. 기간은 3개월·6개월·1년·3년이다. 시작 시점 칩([1년 전]·[3년 전]·[5년 전]·[직접])은 두지 않는다([화면 기본값 결정](2026-10-27-screen-defaults.md) ①을 대체, 2026-10-28).
2. **금액 계산 UI를 이 화면에서 뺀다.** 넣는 방식·금액·시드머니 입력과 넣은 돈·평가액·차이 숫자 칸을 없앤다. 금액을 넣어 보는 연습은 투자 시뮬레이션(`/simulation`)이 맡는다. 사건 핀 툴팁·상세 패널의 "이 기간 내 돈 변화(넣은 돈 제외)"와 차트 십자선의 내 자산·넣은 돈·차이도 빼고, 십자선은 날짜·종가만 보인다. `POST /simulations/run`과 계산 규칙(policies §2)은 바꾸지 않고 API로 남긴다.
3. **주가 차트는 하나다. 여러 종목은 기간 첫날 높이를 맞춰 한 차트에 겹친다.** 종목을 최대 3개 고를 수 있다.
   - 하나면 세로축은 종가(원)이고, 선 아래를 브랜드 색 그라데이션으로 채울 수 있다(시험 중, 화면 상수로 끄고 켬).
   - 둘 이상이면 한 차트에 계열색과 표식 모양(●■◆)으로 겹쳐 그린다. 가격대가 달라도 낮은 가격 종목이 평평해지지 않게, 보이는 기간의 첫날 종가를 모두 같은 높이에 맞춰 그린다(같은 비율로 움직이면 같은 높이만큼 움직인다).
   - 이 높이 맞춤 비율은 선을 그리는 데만 쓰고 %·배수 같은 숫자로 보이지 않는다(수익률은 서버 계산, ADR-3). 세로축은 원 단위 눈금 대신 "첫날" 기준선만 두고, 차트 아래에 "세로 높이는 가격이 아니다"를 안내한다. 툴팁·끝 이름표·범례는 실제 종가(원)를 보인다.
   - 세로축은 하나뿐이라 두 개의 세로축을 한 차트에 쓰지 않는다는 규칙(02 §6-1)은 지킨다. 핀을 누르면 공통 상세 패널 하나가 열린다.
   - 종목마다 높이를 자기 최저~최고로 늘리는 방식은 쓰지 않는다. 2% 움직인 종목과 50% 움직인 종목이 똑같이 출렁여 보여 비교가 왜곡된다.
4. **화면 그래프용 주가 제공을 허용한다(10-24 결정 ①의 일부 변경).** `/market` API는 지금까지 원본 시세를 내려 주지 않았다. 앞으로는 아래 조건에서 **차트를 그리는 데 필요한 일별 종가**만 내려 준다.
   - 종목은 수집 대상(시장별 시가총액 상위 100), 기간은 최근 3년까지로 한정한다. 일별 종가 하나만 주고 시가·고가·저가·거래량은 주지 않는다.
   - 다운로드·CSV·복사용 내보내기 버튼을 두지 않는다. "표로 보기"는 두지 않는다(2026-10-27 변경). 날짜별 종가 툴팁은 마우스를 올릴 때만 뜨고 차트 `aria-label`에는 숫자가 없다. 키보드·스크린리더로는 범례의 마지막 종가, 사건 핀(←/→), 사건 목록만 읽힌다(알려진 한계, 2026-10-28).
   - 차트 아래에 서버가 준 제공처 이름과 과거 시세 고지(`PRICE_PAST`)를 늘 보인다. 고지 문구: "지난 시세를 그대로 보여 줘요. 앞으로의 주가를 뜻하지 않고 이 종목을 사거나 팔라는 뜻이 아니에요."
   - 이전에도 `/simulations/run` 응답의 `series[].legs[].close`(주별 종가)가 브라우저에 갔다. 이번 변경은 그 범위를 일별로 넓힌다. 약관의 화면 표시·상업 이용 조건은 유료화 전에 확인한다는 원칙은 그대로다.
5. **상단 시장 띠는 8칸이고, 흐르는 띠로 보인다.** 순서는 코스피·코스닥·KRX 채권지수·금·원/달러·원/엔(100엔)·원/유로·원/위안으로 고정한다(2026-10-29 변경, 아래 "변경 기록").
   - 코스피·코스닥은 키움 업종일봉조회(`ka20006`, `inds_cd` 001=코스피 종합, 101=코스닥 종합)로 받는다. 공식 가이드에서 필드는 확인했다(지수×100 정수). 인증된 실제 응답은 아직 검증하지 않았다. 수집은 이 Issue에서 한다.
   - KRX 채권지수는 KRX Open API 채권지수 시세정보(`idx/bon_dd_trd`)의 종합 지수 총수익지수(`TOT_EARNG_IDX`), 금은 KRX Open API 금시장 일별매매정보(`gen/gold_bydd_trd`)로 받는다. 둘 다 기존 KRX 키를 쓰고 API별 이용 신청이 필요하며, 지수 그룹 이름·금 종목 코드는 설정값이다.
   - 환율 4개는 한국수출입은행 현재환율 API(`AP01`, 매매기준율 `deal_bas_r`, 통화 `USD`·`JPY(100)`·`EUR`·`CNH`)로 받는다. 공공데이터포털의 이용허락범위는 "제한 없음"이다. 한 번 호출에 모든 통화가 오므로 날짜마다 한 번 부른다.
   - 해외 지수(나스닥100·S&P500·다우존스·니케이225)는 보류한다. 지수 값의 권리가 지수 회사(S&P DJI·Nasdaq·닛케이)에 있어, 어느 제공처(KIS·FRED·TradingView 위젯 등)를 거쳐도 제3자에게 보이려면 지수 회사의 허락이 필요하다. 허락을 받으면 칸과 계약을 다시 더한다.
   - 수집은 별도 Issue(#94)에서 한다. 수집 전이거나 성공한 값이 없는 칸은 띠에서 뺀다. 빈 칸·"준비 중"을 보이지 않고, 대용 ETF·CFD로 몰래 바꾸지 않는다.
   - 칸마다 마지막 값·전일 대비·등락률(▲▼·부호)과 기준일을 보인다. 등락률로 줄을 세우지 않는다(PRD §5 수익률 순위 금지).
6. **주식 랭킹은 시가총액 순위다.** 로고는 출처와 상표 이용 조건을 확인하기 전까지 이름 첫 글자 아바타로 대신한다. 이 PR에서는 로고 이미지와 외부 로고 API를 쓰지 않는다.
7. **"테마별"은 "업종별"로 표기한다.** 키움 종목정보 리스트(`ka10099`)의 `upName`을 그대로 쓰고, #88에서 정한 분류 규칙 `KIWOOM_UPNAME_V1`을 다시 쓴다. 반도체·AI 같은 테마 자동 분류는 계속 범위 밖이다. 업종 수집은 이 화면 담당이 맡고, 지금 `PracticeSyncJob`이 받는 목록 결과를 `instruments`에도 저장하도록 넓힌다. 업종은 업종 안 시가총액 합이 큰 순서로 보이고, 각 업종 안의 종목은 시가총액 순서로 보인다. 현재 업종을 과거 기간에 적용한다는 점과 수집 대상 상위 100 안에서만 묶었다는 점을 안내한다.
8. **스크롤 모션과 흐르는 시장 띠를 투자 인사이트 화면에 한해 허용한다.** 02 §7-3의 "사용자가 누른 것에만 반응"에 예외를 둔다. 영역이 화면에 처음 들어올 때 한 번 차례로 나타나고(투명도 + 짧은 이동, 280ms), 다시 숨기지 않는다. `prefers-reduced-motion`이면 모션 없이 바로 보인다. 숫자가 올라가는 표시는 스크린리더에 최종값만 읽히게 한다.
   - 차트는 처음 그릴 때와 기간·종목을 바꿀 때 왼쪽부터 그린다(`RevealClip`과 같은 방식, 1.6초·고른 속도). 그다음 선 아래 그라데이션이 위에서 아래로 펼쳐지고(0.6초), 사건 핀은 마지막에 나타난다. 핀은 나타나기 전에는 누르거나 포커스할 수 없다. 주가와 사건 응답이 모두 온 뒤 한 번만 그려 모션이 끊기지 않게 한다.
   - 시장 띠는 저절로 흐른다(오른쪽 → 왼쪽, 끝까지 가면 이어서 반복). 다음 경우에는 멈춘다.
     - 마우스를 띠 위에 올렸을 때
     - 키보드 포커스가 띠 안에 있을 때
     - 탭이 숨겨졌을 때
   - [멈춤/재생] 버튼은 두지 않는다(2026-10-27 변경). 터치 사용자는 띠를 멈출 수 없다는 한계를 알고 뺐다. 움직임 줄이기 설정이면 띠가 흐르지 않는다.
   - `prefers-reduced-motion`이면 흐르지 않고 고정해서 보여 주고, 넘치는 칸은 가로 스크롤로 본다.
   - 이어 붙이려고 복제한 칸은 `aria-hidden`으로 숨겨, 스크린리더는 칸 목록을 한 번만 읽는다.
9. **F5 첫 방문 안내를 새 화면에 맞춘다.**
   - 모달 한 장: 한 줄 설명 + 과거 시세 고지 + **[차트 보기] 하나**. 금액 입력은 없다. 이 버튼이 고지 확인을 겸하며, Esc로 닫은 것만으로는 확인으로 치지 않는다.
   - 마지막 단계의 투자 성향 선택([투자 성향 결정](2026-10-26-investor-type.md), 아직 고르지 않았을 때만, 건너뛰기 가능)은 그대로 둔다. [차트 보기] 뒤에 한 번 묻는다.
   - 둘러보기(`/invest?tour=1`, 내 정보의 [사용법 다시 보기])는 ① 시장 띠 ② 종목 고르기(랭킹) ③ 기간·차트 ④ 사건 핀·상세 순서다.
   - 북극성 지표의 `first_result`(01 §8, F8 이벤트, 아직 미구현)는 이 화면에서 "첫 주가 차트가 그려짐"으로 읽는다. 01 §8 문구는 F8을 구현할 때 고친다.

## 이유

- 같은 "넣었다면 지금 얼마" 계산이 `/invest`와 `/simulation` 두 곳에 있으면 메뉴 이름과 역할이 겹친다. `/invest`는 시장과 종목을 보는 화면, `/simulation`은 금액을 넣어 연습하는 화면으로 나눈다.
- 가격대가 다른 종목(수천 원 ~ 수십만 원)을 한 원 단위 축에 그리면, 낮은 가격 종목은 평평한 선이 된다. 처음에는 종목마다 축을 따로 둔 작은 차트로 풀었지만, 리뷰에서 차트를 하나로 보자는 의견이 나와 기간 첫날 높이를 맞추는 보정으로 바꿨다. 퍼센트 눈금을 보이면 화면이 수익률을 계산하게 되므로(ADR-3) 비율은 그리기에만 쓰고, 실제 가격은 툴팁·범례로 보인다. 퍼센트 눈금이 필요해지면 서버가 비율을 내려 주도록 계약을 바꾼다.
- 시장 띠는 주식·채권·금·환율을 함께 보여 줘야 "시장을 한눈에"라는 목표에 맞는다. 국내 상장 ETF로 대신하면 ETF 가격(원)이 지수나 환율처럼 읽혀 혼동을 준다. 그래서 실제 값을 받는 제공처(KRX·한국수출입은행)를 쓰고, 새 키가 필요한 수집은 별도 Issue로 나눠 화면 개편이 막히지 않게 한다. 국채 금리는 대안 수집처(ECOS·FRED)까지 늘어나 이번 범위에서 빼고, 채권은 KRX 채권지수로 보인다.
- 처음에는 해외 지수·환율을 KIS Open API로 받기로 했으나, 03 §4-1 조사 기록대로 KIS는 핀테크사의 제3자 서비스 제휴가 불가하다. FRED도 S&P500·다우존스 설명에 "prior written permission" 없이 재현 금지, 니케이225는 재배포 전 닛케이 허락을 요구하고, FRED API 약관은 제3자 소유 데이터를 개인 용도 밖에 쓰려면 소유자 허락을 받으라고 한다. TradingView 무료 위젯은 S&P500 같은 실제 지수 대신 CFD 기호를 보인다. 그래서 해외 지수는 허락 전까지 보류하고, 같은 제공처에서 추가 비용 없이 받는 원/유로·원/위안과 KRX 채권지수로 칸을 채운다.
- 저절로 움직이는 내용에는 멈출 방법이 있어야 한다(WCAG 2.2.2). 처음에는 포커스 정지와 [멈춤/재생] 버튼을 함께 뒀으나, 리뷰에서 화면을 단순하게 하려고 버튼을 뺐다. 마우스·키보드 포커스·탭 숨김 정지와 움직임 줄이기 고정은 남긴다. 터치 사용자의 멈춤 수단이 없다는 점은 알려진 한계다.
- "표로 보기"도 리뷰에서 뺐다. 그래서 키보드·스크린리더로 날짜별 종가를 읽을 수단이 없다. 차트에 포커스를 두고 ←/→로 날짜를 옮기는 방식은 작업량이 커서 이번에는 하지 않고 알려진 한계로 둔다.
- `upName`은 업종이지 테마가 아니다. #86 결정과 같은 용어를 써야 문서와 화면이 어긋나지 않는다.
