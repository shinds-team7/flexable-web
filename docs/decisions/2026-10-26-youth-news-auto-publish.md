# 청년 소식 자동 게시와 AI 요약(Gemini)

- 날짜: 2026-10-26 · 결정한 사람: seon00(F4 담당) · 관련: Issue #48, #34(PR #47)
- 영향: 프론트 / 백엔드

## 결정

- 온통청년에서 매일 06:00 수집한 청년 정책을 **사람 검수 없이** `/news`에 게시한다. 분야는 지금처럼 규칙(대분류 + 정책명 금융 낱말)으로 자동 분류한다. 반려(`REJECTED`)한 소식만 뺀다.
- 카드에 보이는 것: 제목 · 요약(1~3문장) · 기간 · 분야 · 지역 · 나이 · 기관 · 마감 D-day, 그리고 공고문(원문) 링크·저장·공유.
- **AI는 요약 한 칸에만 쓴다.** worker가 수집 뒤 Gemini API(무료 등급)로 원문의 정책설명·지원내용을 1~3문장으로 줄이고, 화면에 "AI 요약"으로 표시한다. 나머지 칸은 원문 값·규칙으로 채운다.
- 요약은 검사를 통과한 것만 쓴다: 160자·3문장 이내, 금지어("추천"·"투자 권유"·"계좌 연결" 등) 없음, **요약에 나온 숫자·금액이 모두 원문에 있을 것**(단위만 바꾼 같은 금액은 허용, 예: 20만 원 = 200,000원). 통과하지 못하면 요약 없이 게시한다.
- 사람이 쓰던 "나에게 얼마"(`benefit`)·"오늘 할 일"(`action`)은 화면에서 뺀다. API 필드는 남기고 null이다.
- 키가 없거나 호출이 실패해도 수집·게시는 그대로 하고 요약만 비운다. 무료 등급 한도 때문에 한 번에 20건씩 묶고, 한 번 실행에 호출 수 상한을 둔다(남은 것은 다음 날).

## 이유

- 검수자·검수 화면(#48 원안)이 없어 운영 화면에는 예시 소식만 보였다. 검수 인력 없이 매일 갱신되는 실제 소식을 보여 주는 쪽을 택했다.
- 원문 문장은 길고 공고문 형식이라 카드에 그대로 넣기 어렵다. 금액을 지어내는 위험은 숫자 검사로 막고, AI가 쓴 문장임을 화면에 밝힌다.

## 바뀌는 것(문서·코드·설정)

- 계약 `docs/contracts/web-api.yaml`: `summary` 추가, `benefit`·`action` null 허용, `preview` 삭제(로컬 미리보기 기능 제거). `ContractTest`가 검사한다.
- 백엔드: `NewsService`(승인 조건 제거·요약 대상/저장), `ingest.gemini.GeminiNewsSummarizer`, `YouthNewsSyncJob` 요약 단계(`ingest_runs` job `youth-summary`), Flyway V15(`youth_news.summary`·`summary_hash`·`summarized_at`), 환경 변수 `GEMINI_API_KEY`·`GEMINI_MODEL`(선택 `GEMINI_BATCH_SIZE`·`GEMINI_MAX_CALLS`·`GEMINI_CALL_DELAY`), `NEWS_PREVIEW_DRAFTS` 삭제.
- 화면: 카드·오늘의 한 장·저장함이 요약을 보여 주고 "AI 요약"을 붙인다. 나에게 얼마·오늘 할 일 칸을 뺀다.
- 문서: `docs/PRD.md` F4, 01 §F4, 03 ADR-6(소식 요약은 사람 검수 없이 공개하는 예외), backend·news·ingest README, HANDOFF.
- 개인정보: Gemini에는 공개 정책 문장(정책명·정책설명·지원내용)만 보낸다. 담당자 이름은 수집 때 지우고, 회원 정보는 보내지 않는다. 그래서 개인정보처리방침은 바꾸지 않는다.
