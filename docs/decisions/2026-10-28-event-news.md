# 투자 인사이트 사건 상세에 그때 뉴스 기사(네이버 뉴스 검색 중계)

- 날짜: 2026-10-28 · 결정한 사람: 사용자(rhkrqkq) · 관련: Issue #121, PR #122
- 상태: 이 PR로 제안·구현. 실제 키로 하는 호출 확인은 사람이 서버 환경 변수에 키를 넣은 뒤 한다.
- 영향: 웹 프론트(`/invest` 사건 상세), 웹 백엔드(market·신규 `newssearch`), API 계약. 투자 시뮬레이션(`/simulation`)·앱·시연은 범위 밖이다.
- 기준: [투자 인사이트 개편 결정](2026-10-26-invest-insight-redesign.md), 03 §4-2(네이버 검색 API 행), 04 §8, 05 §4, web-api.yaml `/market/events/*`.

## 결정

1. **투자 인사이트(`/invest`) 사건 상세에 "그때 뉴스" 기사 목록을 붙인다.** 처음 Issue는 투자 시뮬레이션(`/simulation`) 공시 옆에 붙이는 안이었지만, 사용자가 투자 인사이트에서 보는 쪽으로 바꿨다. 투자 시뮬레이션 묶음(`practice_datasets`)과 [사건 퀴즈 결정](2026-10-26-investment-practice.md)의 "공시만" 규칙은 그대로다.
2. **미리 모아 저장하지 않고, 상세를 열 때 서버가 NAVER API HUB 뉴스 검색을 불러 그대로 중계한다.** 새 API `GET /market/events/{id}/news`. DB·서버 메모리 캐시에 기사를 두지 않고 응답에 `Cache-Control: no-store`를 붙인다.
   - 이유: 네이버 검색 API 특약(개발자센터 2026-09-07, API HUB 2026-09-20 시행) 2.3이 검색 결과·가공물의 저장·캐싱을 금지한다(아래 "확인 상태"). Issue의 "worker가 미리 수집·저장" 안은 이 조항과 부딪힌다.
3. **04 §8 외부 호출 예외에 ④를 더한다.** "④ 투자 인사이트 사건 상세의 뉴스 기사(NAVER API HUB 뉴스 검색)는 사용자가 사건 상세를 연 요청 중". 브라우저가 네이버를 직접 부르지 않는다(키 보호).
4. **기사 고르기.** 검색에 날짜 조건이 없으므로 **검색어에 사건 날짜("10월 12일")를 넣어** 정확도순 100건씩 최대 4번 부르고(5건이 차면 멈춤), 발행 시각(`pubDate`)이 **사건 시작일 3일 전 ~ 마지막 날 3일 뒤(KST, 날짜 포함)** 인 기사만 남긴다. 원문 링크 기준 중복을 빼고 발행 순으로 최대 5건.
   - 종목 사건: ① `"{종목명} 주가 {M월 D일}"`(시작일) ② `"{종목명} {M월 D일}"` ③ 여러 날 사건이면 `"{종목명} 주가 {M월 D일}"`(마지막 날), 하루 사건이면 `"{종목명} {M월 D일} {급등|급락}"`.
   - 시장 사건: ① `"{M월 D일} 마감시황"`(시작일) ② `"{M월 D일} 증시"` ③ 여러 날 사건이면 `"{M월 D일} 마감시황"`(마지막 날), 하루 사건이면 `"{M월 D일} 코스피 마감"`.
   - 사건 마지막 날이 30일 안이면 ④ `"{종목명 또는 코스피}"` 날짜순을 더한다.
   - 검색어는 실제 키로 비교해 골랐다(2026-10-28). 처음 안(`"{이름} {급등|급락}"`·`"{이름} 주가"`)은 최근 사건 14개 중 2개에서만 기사를 찾았다. `"코스피 {M월 D일}"`은 범위 안 기사가 정확도순 301번째 뒤에야 나왔고, `"{M월 D일} 마감시황"`은 첫 100건 안에 있었다. 지금 순서로 7개 종목 화면의 사건 32개를 다시 돌리자 32개 모두 기사를 찾았고(30개는 5건), 사건당 평균 1.3번 불렀다.
   - 기사를 찾지 못하면 화면은 기존 "그때 뉴스 검색" 외부 링크(`newsSearchUrl`)를 안내한다. 날짜순으로 1,000건까지 넘겨 보며 찾지는 않는다(대형주는 1,000건이 며칠 치라 효과에 비해 호출이 많다).
5. **보여 주는 것.** 제목·원문 링크(`originallink`, 없으면 `link`)·발행 시각·언론사 주소(원문 링크의 호스트, 없으면 null)만. 요약(`description`)은 쓰지 않는다. 제목은 검색어 강조 `<b>` 태그와 HTML 엔티티만 풀고 다른 글자는 바꾸지 않는다. 출처 "네이버 뉴스 검색"과 고지("기사 제목과 원문 링크를 그대로 보여 줘요. 주가가 움직인 원인이라는 뜻은 아니에요.")를 늘 함께 보인다. AI 입력·요약·원인 추정에 쓰지 않는다.
6. **실패해도 상세는 그대로.** 키 없음·인증 오류·하루 한도(429)·네이버 오류(SE01~SE06·SE99)·시간 초과면 200 `status: UNAVAILABLE`, `items: []`. 검색 도중(두 번째 이후 호출)에 실패하거나 서버 하루 상한에 닿아도 같다. 앞서 찾은 기사가 있어도 보이지 않는다(부분 결과 없음). 사건 상세(`/market/events/{id}`)와 따로 불러 서로 막지 않는다. 429를 받으면 그 호출을 센 날(KST)의 남은 요청은 부르지 않는다. 자정 직전에 시작한 호출이 다음 날 429로 끝나도 다음 날은 막지 않는다(PR #122 리뷰).
7. **호출 상한.** 하루 호출 수를 서버가 세어 `NAVER_NEWS_DAILY_CAP`(기본 20,000, 하루 한도 25,000보다 낮게)을 넘으면 부르지 않는다. 키는 환경 변수 `NAVER_API_HUB_KEY_ID`·`NAVER_API_HUB_KEY`에만 두고 로그·응답·오류 메시지에 남기지 않는다.
8. **예시 자료.** `NEWS_SEARCH_SOURCE=fake`면 키 없이 사건 기간 안 예시 기사 2건(+기간 밖 1건은 걸러짐)을 돌려주고 `isSample: true`, 출처 "네이버 뉴스 검색(예시)"로 보인다. 테스트·`dev:mock`·로컬 확인용이다.

## 확인 상태

| 무엇 | 상태 |
|---|---|
| API 형식(GET `https://naverapihub.apigw.ntruss.com/search/v1/news`, 헤더 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY`, query·display 1~100·start 1~1000·sort sim/date, 응답 items의 title·originallink·link·description·pubDate, 오류 SE01~SE06·SE99, 하루 25,000회) | [뉴스 검색](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)·[개요](https://api.ncloud-docs.com/docs/naver-api-hub-overview) 확인(2026-10-28). 개요: 검색 API 오류는 `{errorCode, errorMessage}`, 게이트웨이 오류는 `{error:{errorCode,message,details}}`, 401 인증·429 하루 한도 |
| 특약 2.1 네이버 검색 결과임을 표시 · 2.2 가공 없이 노출, 출처·원본 링크 · 2.3 저장·캐싱 금지 · 2.4 일시 저장 예외(장애 대응·개인화 24시간, 서버 이력 조회 최대 21일) · AI 입력·요약 금지 | **2차 자료로만 확인**(03 §4-2 출처, 다른 저장소의 약관 대응 Issue). 원문 약관은 운영 공개 전 사람이 NAVER API HUB 콘솔에서 확인한다. 원문이 다르면 이 결정을 다시 본다 |
| 날짜 범위 검색 | 없음. 그래서 결정 4처럼 검색어에 날짜를 넣고 발행일로 거른다. 날짜순 최신 100건은 "코스피"·"삼성전자" 기준 하루 치뿐이었다(2026-10-28). 확인한 사건은 최근 1년 안 32개뿐이라, 더 오래된 사건이나 기사가 적은 종목은 못 찾을 수 있다 |
| 개인정보 | 네이버로 보내는 값은 종목명·검색어뿐이고 서버가 부르므로 사용자 IP·계정 정보가 나가지 않는다. 저장 항목·브라우저 저장·로그가 바뀌지 않아 `Privacy.tsx`·`privacy-web.md`는 고치지 않는다 |

## 이유

- 저장 없는 중계만이 특약 2.3과 Issue 목표(그때 기사를 화면에서 보기)를 함께 만족한다. 대신 상세를 열 때마다 1~4회 호출이 생기므로 하루 상한과 429 처리로 한도를 지킨다.
- 투자 인사이트는 지난 일을 보는 화면이라, 사건 마지막 날 뒤 기사도 보여도 된다(퀴즈처럼 답이 새는 문제가 없다). 그래서 기간을 사건 앞뒤 3일로 잡는다. 투자 시뮬레이션에 붙이려면 재생 기준일 이전 기사만 골라야 하고 퀴즈 결정을 바꿔야 해서 이번 범위에서 뺐다.
- 기사 목록은 "원인"이 아니라 "그 무렵 나온 기사"다. 사건 근거(공시) 칸과 나눠 보여 주고, 원인을 단정하지 않는다는 고지를 붙인다.
