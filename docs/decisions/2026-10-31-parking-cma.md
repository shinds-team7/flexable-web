## 현재 상태 (2026-10-31 `main`)

- `/deposit`·`/parking`·`/cma` 화면은 있고, 서버 API는 정기예금만 구현됐다(#150·#151). 파킹·CMA는 `VITE_LUMP_SAMPLE`에 따라 **예시 데이터**를 보여 준다(`isSample`·"실제 상품과 금리가 아니에요" 고지).
- 예시를 운영 화면에 계속 두면 "실제처럼 보이는 가짜 금리"를 노출하게 된다. 11/2에 예금만 실데이터로 켜면 파킹·CMA만 예시로 남는다.

## 출처 조사 결과 (2026-11-01, 기관 페이지를 직접 읽음)

**한 줄 결론: 지금 확인된 범위에서는 파킹·CMA를 합법적으로 자동 수집할 수 있는 공식 API가 없다.** 아래 "확인 못 한 것"은 사람이 마저 확인해야 한다.

### 금융감독원 금융상품한눈에(finlife) — 지금 쓰는 출처

- 오픈API는 8종이다: 금융회사개요, 정기예금, 적금, 연금저축, 주택담보대출, 전세자금대출, 개인신용대출, 개인사업자대출. REST, XML·JSON. ([소개](https://finlife.fss.or.kr/finlife/main/contents.do?menuNo=700029))
- **입출금자유예금(파킹)·CMA API는 목록에 없다.** 같은 사이트 메뉴에는 "입출금자유예금" 화면(`menuNo=700074`)이 있지만 오픈API로는 제공되지 않는 것으로 보인다(확인한 소개 페이지 기준).
- 확인 못 한 것: 엔드포인트 파일명 목록("상세 및 테스트" `menuNo=700051`), 이용 조건·호출 한도·출처 표기(`menuNo=700030`·`700031`, 저작권보호정책). → 금감원에 "입출금자유예금 오픈API 제공 계획"을 문의할 만하다.

### 파킹통장

| 출처 | 확인한 것 | 확인 못 한 것 |
|---|---|---|
| 은행연합회 소비자포털 ([입출금자유예금](https://portal.kfb.or.kr/compare/receiving_deposit.php)) | 조회는 JavaScript(`ReceivingDepositSearch`)로 불러오고, 페이지에 오픈API·엑셀 안내는 보이지 않았다. 저작권 표기만 있다 | 데이터를 불러오는 실제 주소·응답, 이용약관(응답 한글이 깨져 읽지 못함), 기준일·갱신 주기 |
| 저축은행중앙회 소비자포털 ([입출금자유예금](https://www.fsb.or.kr/mobratanym_0100.act)) | "총 297개 상품"을 보여 주고, 기본·최고금리 정렬, 최고금리 기준·이자 지급방식(수시·월·분기·반기·연)·가입방식 필터가 있다. "엑셀다운로드" 버튼이 있다(JS). 자동 수집을 허용·금지한다는 문구는 없다("이메일 무단 수집 거부"만 있음) | 상품 값을 불러오는 주소·응답, 엑셀 파일 형식, 기준일 표시(페이지에 없음), 하단 이용약관·robots.txt |

- 두 곳 모두 **공식 API·데이터 제공 안내를 찾지 못했다.** 화면 데이터는 스크립트로 불러오는 구조라 단순 HTML 수집은 안 되고, 주소를 알아내 호출하는 것은 이용 조건을 확인하기 전에는 하지 않는다("하지 않는 것").
- 저축은행 쪽 필드(기본금리·최고금리·이자지급방식·최고금리 적용 가능 금액)는 우리 화면 필드(`baseRate`·`maxRate`·`rateLimit`)와 잘 맞는다.

### CMA

- 금융투자협회 종합통계(FreeSIS)에는 `일자별 CMA현황`·`운용대상별 CMA잔고 추이`가 있지만 **업권 전체 계좌 수·잔고** 통계이고, 증권사별 CMA 금리·수익률 메뉴는 찾지 못했다(상세 표는 JS 로딩이라 열어 보지 못함). 금투협 전자공시(dis.kofia.or.kr)는 빈 화면으로 읽혀 메뉴를 확인하지 못했다.
- 공공데이터포털에는 금융투자협회 기반 API가 있다: [금융투자협회종합통계정보](https://www.data.go.kr/data/15094809/openapi.do)(`GetKofiaStatisticsInfoService`, 일자별CMA현황: 계좌 수·잔액, 증권사별 금리 파라미터 없음), [금융투자회사공시정보](https://www.data.go.kr/data/15094795/openapi.do)(증권사 퇴직연금 수익률·주식거래 수수료만), [펀드상품기본정보](https://www.data.go.kr/data/15094792/openapi.do)(수익률 없음). 이용허락범위 "제한 없음", 무료, `serviceKey` 필요.
- 결론: **증권사별 CMA 금리를 모아 주는 공식 출처는 확인되지 않았다.** 금리는 각 증권사가 자기 홈페이지에 공시한다(한국투자증권처럼 입금 후 1~30일과 31일 이후 금리가 다르거나, 신규 입금분부터 적용하는 곳이 있어 증권사마다 구조가 다르다). 증권사 8곳을 따로 수집하면 약관·화면 구조가 제각각이라 유지가 어렵다.

### 현실적인 길 (제안)

1. **공식 데이터 제공 문의(가장 먼저)**: 저축은행중앙회·은행연합회에 소비자포털 입출금자유예금 공시를 파일·API로 받을 수 있는지와 이용 조건(상업적 이용·출처 표기)을, 금융투자협회에 증권사별 CMA 금리 공시·제공 방식을, 금융감독원에 finlife 입출금자유예금 오픈API 제공 계획을 묻는다. 답이 오기 전에는 수집 코드를 만들지 않는다.
2. **공공데이터포털에서 직접 검색**: "입출금", "수시입출금", "CMA", "MMF"로 제공기관별 API·파일데이터를 찾는다(이번에는 금융투자협회 키워드 위주로만 확인했다).
3. **제공 방식이 확인되면**: 파일·API는 finlife와 같은 구조로 `*SnapshotJob`을 만들어 자동 수집한다(결정 ③). 스크래핑은 이용 조건에서 허용을 확인한 경우에만 한다.
4. **그 사이**: 파킹·CMA는 예시 데이터로 공개한다(결정 ①②). "예시" 표시와 고지를 유지한다.

### 사람이 확인할 목록

- [ ] finlife 이용 조건(`menuNo=700030`·`700031`)과 "상세 및 테스트"(`menuNo=700051`)의 엔드포인트 목록
- [ ] 저축은행중앙회·은행연합회 소비자포털 이용약관·저작권 안내, 엑셀 다운로드 파일의 형식
- [ ] 금융투자협회 전자공시(dis.kofia.or.kr)를 브라우저로 열어 CMA 관련 메뉴 확인(빈 화면으로만 읽혔다)
- [ ] 공공데이터포털 검색: "입출금자유예금"·"수시입출금"·"CMA"
- [ ] 위 4곳에 공식 제공 방식 문의, 답변을 이 문서나 #144·#145에 기록

## 결정할 것 (제안과 이유)

### ① 범위: 11/1 기능 동결 이후에 파킹·CMA를 넣을까?
- (a) 11/2에는 예금만. 파킹·CMA는 출처 확정 뒤 별도 일정. **← 제안**
- (b) 11/2에 파킹·CMA도 운영자가 확인한 값을 넣어 공개.
- 이유: PRD에서 파킹은 "이후", CMA는 범위 밖이다. 출처·약관이 확인되지 않은 값을 사람이 옮겨 적어 공개하면 정확성·갱신 책임이 생긴다.

### ② 출처가 확정되기 전, 운영 화면의 파킹·CMA는 어떻게 보일까?
- (a) 메뉴·탭에서 숨기고 직접 주소로 들어오면 "준비 중" 안내. **← 제안**
- (b) 지금처럼 예시 데이터를 계속 보인다("예시" 표시 유지).
- (c) 파킹은 가져오기 표(③)로 채우고 CMA만 숨김.
- 이유: 예시 금리를 운영에 계속 두면 오해 소지가 크다. (b)는 시연 목적일 때만 맞다.

### ③ 1단계 데이터 방식: 운영자가 확인해 넣는 표(`lump_products`)로 시작할까?
- 제안 구조: kind(`PARKING`|`CMA`), 회사, 상품명, 기본·최고금리, 최고금리 적용 한도, 가입 한도, 예금자보호, 종류(CMA), **출처 이름·URL·기준일(필수)**. 가져오기 파일(JSON)로 넣고, 출처·기준일이 없는 행은 거부한다. 청년미래적금 `policy_savings`와 같은 방식이다.
- (a) 이 표로 시작, 자동 수집은 출처가 확정되면 교체. **← 제안(①의 (b)를 고를 때만 필요)**
- (b) 자동 수집 출처가 확정될 때까지 구현하지 않는다. **← ①의 (a)를 고르면 이쪽**

### ④ CMA 금리를 숫자로 보여 줄까?
- 현재 제안 문서는 "금리는 화면에 숫자로 쓰지 않는다"이고, 현재 CMA 화면은 숫자 금리로 정렬·비교한다. 둘이 충돌한다.
- (a) 숫자를 보이지 않고 종류(RP형·MMF형·종금형·발행어음형)·예금자보호·가입 조건만 비교.
- (b) 숫자를 보이되 "수익은 운용 실적에 따라 변하는 지난 기준이며 확정 금리가 아니다" 고지를 단다.
- (c) CMA 비교 자체를 하지 않는다. **← 출처가 없는 지금은 제안**
- 이유: CMA는 확정 금리가 아니라 실적배당 성격(RP·MMF)이 있고 종류별로 예금자보호 여부가 다르다. 증권사 공시 출처도 없다.

### ⑤ 계산 규칙 (파킹·CMA를 공개하는 경우)
- 제안: 현재 금리가 1년 동안 이어진다고 가정하고 **월 지급 단리**(재투자 없음)로 12개월 `series`를 만든다. 기간은 12개월 고정. 구간 금리(최고금리 적용 한도 초과분)는 1단계에서 기본금리로 통일해 계산하고 한도는 표시만 한다. 세금은 정기예금과 같이 floor(세전×15.4%). 이 가정은 `assumptions`로 응답에 내려 준다.
- 승인되면 `docs/policies.md`에 §7로 옮기고 `tests/policy/`에 예시 표를 만든다.
- 구간 금리를 정확히 계산하려면 한도·초과분 금리 필드가 더 필요하다(출처에 있는지 확인 후).

### ⑥ 금융권(`sector`) 값
- 지금 계약의 `SavingsSector`는 `BANK`·`SAVINGS_BANK`뿐이다. 화면은 증권사를 임시로 `BANK`로 쓴다.
- CMA를 공개한다면 `SECURITIES`를 추가하고, 공개하지 않으면 추가하지 않는다. **← ④가 (c)면 불필요**

## 승인 뒤 할 일 (제안 순서)

1. 결정 칸을 채우고 이 문서 상태를 "결정됨"으로 고친다.
2. 출처 확인 결과(제공 방식·이용 조건·호출 한도)를 이 문서나 #144·#145에 기록한다.
3. ①②에 따라 프론트 변경(메뉴 숨김·준비 중 안내)을 먼저 한다 — 계약 변경 없음.
4. 공개하기로 한 상품만 계약 PR(`/parking/*` 또는 `/cma/*`, spec-change) → 정책 PR(§7) → 가져오기 표·API 구현 순으로 올린다. 순서는 정기예금(#150 → #151 → #153)과 같다.
5. `VITE_LUMP_SAMPLE`에서 해당 종류를 뺀다(사람이 운영 환경 변수에 설정).

## 하지 않는 것

- 출처·약관 확인 없이 소비자포털을 긁어 오는 수집 코드를 만들지 않는다.
- 가입 연결·추천·순위를 만들지 않는다.
- 이 제안이 승인되기 전에는 `docs/contracts/web-api.yaml`에 `/parking/*`·`/cma/*`를 넣지 않는다.

### 남은 질문 (⑤)

- CMA 재투자: 수익이 하루 단위로 쌓여 다시 투자되는지(일복리), 월 단위로 정산돼 재투자되는지는 상품·증권사마다 다를 수 있어 **출처 공시로 확인이 필요**하다. 확인 전 임시 가정은 정기예금과 같은 **월복리**(`DepositCalculator` 월복리 규칙, 수익을 매월 원금에 합산)로 하고, 12개월 `series`와 `assumptions`에 "수익을 재투자한다고 가정" 문구를 단다. 이 가정으로 구현해도 되는지 확인이 필요하다.
- 파킹: 미정. 결정 전에는 현재 예시 구현(단리)을 유지하고, 파킹 계산 규칙은 정책(`docs/policies.md` §7)에 넣지 않는다.
- 위 가정이 정해지면 `docs/policies.md` §7과 `tests/policy/`를 올린다(정기예금 §6과 같은 순서).
