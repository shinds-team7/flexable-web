# 소식 30초 진단(맞춤 판별·빠른 검색)과 신청 대상 조건

- 날짜: 2026-11-03 · 결정한 사람: 사용자(웹 담당)가 채팅에서 요청·승인 · 관련: 청년 금융 소식(F4), [소식 리디자인](2026-11-03-news-hot.md)
- 영향: 프론트 / 백엔드 / 계약(`GET /youth-news`)

## 결정

- `/news` 하단을 [조건으로 찾기 · 맞춤 판별 · 빠른 검색] 3탭 한 상자로 합친다. 히어로의 "30초 진단"은 맞춤 판별 탭, "내 지원금 찾기"의 "조건으로 찾기"는 조건으로 찾기 탭을 연다.
- **맞춤 판별**은 나이→지역→취업(세부)→가구원·소득·혼인→분야·학력·전공·특화(·키워드) 5단계다. 결과는 "신청 가능성이 높아요"와 "추가 확인이 필요해요"로 나눈다. **빠른 검색**은 신청 기간이 지나지 않은 소식 중 하나를 무작위로 뽑는다. 정렬은 마감 임박순·새로운 순만 둔다(01 §7, 추천순 없음).
- 입력값은 화면 메모리에만 두고 저장·전송하지 않는다(개인정보처리방침 변경 없음).
- `GET /youth-news`의 `audience`에 `employment`·`marital`·`schools`·`majors`·`special`을 더한다. 온통청년 `jobCd`·`mrgSttsCd`·`schoolCd`·`plcyMajorCd`·`sbizCd`를 이름으로 바꾼 값이고, **null = 원문에서 확인 못 함, [] = 제한 없음, 값이 있으면 그중 하나에 해당해야 한다**. DB는 `youth_news` 열 5개(V21, 'ANY' = 제한 없음). 다음 수집(06:00)부터 채워진다. 코드표는 공식 `API코드정보.xlsx`와 대조했다(2026-11-03, 학력 `0049006`은 "대졸 예정").
- 판별 규칙: 나이·지역·분야가 안 맞으면 뺀다. 고른 취업·혼인·학력·전공이 소식의 대상 조건과 다르면 뺀다. 확인 못 한 조건(null)·소득 기준이 있는 소식·특화 대상 소식(특화를 고르지 않았을 때)은 제외하지 않고 "추가 확인"으로 보낸다. 고르지 않은 조건은 따지지 않는다.
- 소득은 금액으로 따지지 않는다(중위소득 비교는 서버 계산 영역, ADR-3). 소득 기준이 있는 소식은 항상 "추가 확인"이다.

## 남은 일

- 운영 VM의 worker를 새 이미지로 다시 띄워 수집 뒤 조건값이 채워지는지 확인한다(이슈로 추적).

## 2026-11-04 변경

- 빠른 검색 탭과 "건너뛰고 바로 결과 보기"를 없앴다. `/news` 하단은 [조건으로 찾기 · 맞춤 판별] 2탭이다.
- 맞춤 판별은 5단계 대신 모든 조건을 한 화면에 보이고 [검색하기]를 누르면 결과를 낸다. 찾는 동안 점이 도는 로딩을 잠깐 보인다.
