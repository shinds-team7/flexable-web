# 소식 화면 리디자인과 "요즘 핫한 지원금" 열람 집계

- 날짜: 2026-11-03 · 결정한 사람: 사용자(웹 담당)가 채팅에서 요청·승인 · 관련: 청년 금융 소식(F4)
- 영향: 프론트 / 백엔드

## 결정

- `/news`를 검색 히어로 → [내 지원금 찾기 · 요즘 핫한 지원금] → 지원금 분석(이번 달 분야별 건수 카드 + 입력 요령 글) → 조건으로 찾기 → 소식 목록(3열)로 바꾼다. 저장한 소식 레일은 없애고 `/mypage` 오른쪽의 "오늘의 시장" 카드 자리로 옮긴다(저장은 이 브라우저에만 한다).
- 조건으로 찾기는 지역·만 나이·관심 주제를 여러 개 고른 뒤 [검색하기]를 누르면 **합집합**으로 거른다. 고른 값은 서버로 보내거나 저장하지 않는다. 나이는 19·24·30·34·39세, 주제는 기존 분야 8개(교통·주거·금융·일자리·교육·생활·문화·세금·기타)다. 온통청년 데이터에 없는 분류(생애주기 전 구간, 신체건강 등)는 만들지 않는다.
- "요즘 핫한 지원금"은 소식의 [공고문 보기]를 연 **서로 다른 방문자 수(최근 7일)** 순이다. 브라우저가 만든 임의 UUID(`fx.news.viewer`)를 `POST /youth-news/{id}/views`로 보내 (소식·방문자·날짜)당 한 건을 센다. 계정·IP와 연결하지 않고 30일 뒤 지운다. 방문자 한 명이 하루에 셀 수 있는 소식은 40개다.
- 구글 검색량은 공식 API·키가 없어 이번에는 쓰지 않는다. `GET /youth-news/hot`의 `basis`는 `SITE`뿐이고, 검색량을 붙일 때 값을 늘린다. 열람이 모자라면 화면이 마감 임박 순으로 채우고 그렇게 안내한다.
- "얼마인지 계산하기" 칸은 만들지 않는다. "내 지원금 찾기"의 30초 진단은 아직 없으므로 버튼은 조건으로 찾기·마감 임박 정렬로 잇는다.
- 오늘의 한 장(`slot=MAIN`) 화면 표시는 빠진다(API 필드는 그대로).

## 이유

- 사용자 전체 열람을 집계하려면 서버 저장이 필요해 계약·DB·개인정보 방침을 같이 바꾼다. 임의 UUID만 쓰고 보관 기간을 짧게 해 개인정보 부담을 줄였다.

## 바뀌는 것

- `docs/contracts/web-api.yaml`(`/youth-news/hot`, `/youth-news/{id}/views`), `V20__youth_news_view.sql`, `Privacy.tsx`·`privacy-web.md`, `docs/CHANGELOG.md`.

## 2026-11-04 변경

- 이름을 "요즘 핫한 지원금"에서 "요즘 핫한 청년 소식"으로 바꿨다(집계 방식·저장 항목은 그대로).
- 분석 카드는 "지금 신청할 수 있는 청년 소식"(상시 모집 + 마감일이 확인되고 지나지 않은 소식, 마감일 미확인 제외) 기준으로 전 분야 건수와 이번 달 신청 시작·마감·상시 모집 건수를 보인다.
- 소식 카드의 [공고문 보기] 버튼을 없애고 카드 전체를 눌러 공고문을 연다(열람 집계는 그대로). 목록은 무한 스크롤이고 우측 하단에 맨 위로 버튼이 있다.
- 기본 정렬은 "새로운 순"이다. 브라우저 저장 키는 `fx.news.filter.v2`로 바꿔 예전 저장 값을 쓰지 않는다.
