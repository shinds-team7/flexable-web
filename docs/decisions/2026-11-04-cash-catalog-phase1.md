# 파킹·CMA 1차: 공시 금리·조건 조회와 비교

- 날짜: 2026-11-04 · 결정: 사용자(세 질문 모두 권장안 승인) · 관련: #144·#145·#148, 선행 #216
- 범위: 웹 프론트·백엔드·API. 앱·시연·개인정보 저장 변경 없음.

## 결정

1. 파킹·CMA는 금리·조건 조회와 나란히 비교부터 구현한다. 금액 입력·1년 추정·이자 계산·시뮬레이션 API는 상품별 계산 정책 확정 후 추가한다. 예금 `/deposit/*`와 F7 CMA 예시는 유지한다.
2. 자동 취득·서비스 재사용 조건을 확인한 공식 API·파일·웹 자료를 수집 대상으로 채택한다. 운영자 수기 입력·공개 업로드 API는 만들지 않는다. 실제 허가가 없는 출처는 수집기를 활성화하지 않는다. 사용자 승인은 제3자의 이용 허가를 대신하지 않는다.
3. CMA는 RP형·발행어음형부터 시작한다. 공시 약정수익률을 과거 실적이라고 부르지 않으며, 기준일·적용일·금액/기간 구간·지급·재투자 조건을 함께 표시한다. MMF·MMW는 후속이다.

이 결정은 [11-01 결정](2026-10-31-parking-cma.md)의 ③(API만이 아닌 허용된 공식 자료)·④(CMA 약정/실적 고지 구분)·⑤(계산을 후속으로 분리)를 위 범위에서 대체한다. [#216 조사](2026-11-04-parking-cma-data-sources.md)의 미확인 이용 조건은 여전히 미확인이다.

## 계약과 저장

- 공개 API: `GET /parking/products`, `GET /cma/products`. 새 `CashCatalogList`·`CashCatalogProduct` 사용. 기존 `DepositProductList`의 계산 필드를 흉내 내거나 0원 계산값을 넣지 않는다.
- 1차는 전체 목록을 회사명·상품명·id 순으로 제공한다. 금융회사·상품 종류·검색 필터와 최대 3개 조건 비교는 브라우저에서 수행한다. 금리 산술 계산은 하지 않는다.
- 증권사는 새 카탈로그의 별도 sector에서 `SECURITIES`로 표현한다. 기존 `SavingsSector`를 확장해 적금·예금에 증권사가 노출되는 변경은 하지 않는다.
- 저장은 출처·종류별 전체 스냅샷이다. 허용 근거(URL 또는 문서 식별자), 검증 시각과 공시 데이터를 보관한다. 조건 누락·잘못된 유형·중복 상품·빈 스냅샷은 거부하고 기존 정상본을 유지한다. 다른 출처를 삭제하지 않는다. 판매 종료·허가 철회는 출처별 명시적 철회로 처리한다.
- 신규 출처가 아직 없으면 `items=[]`, `isSample=false`와 미적재 안내를 제공한다. 프론트가 예시로 자동 대체하지 않는다. 파킹·CMA의 기존 예시 계산 화면은 이 조회 화면으로 전환한다.
- 금리·보호 여부·한도·공시 기준일·적용일이 미확인인 경우 null로 보존하고 화면에 미확인으로 표시한다. 금액/기간 구간은 공시 조건 원문으로 우선 보관하며 계산에 사용하지 않는다.

## 구현 순서·확인 범위

계약 PR 병합 → 출처별 원자적 저장·목록 API·조건 비교 화면 → 실제 허용 출처 수집기 순서다. 수집기가 없는 상태를 실데이터 적재 완료라고 보고하지 않는다. 출처 조건 확보 여부는 별도 사용자 질문과 공식 자료 조사로 확인한다.

저축은행중앙회의 공개 JS를 추가 확인한 결과 엑셀 버튼은 조회 조건으로 표 HTML을 받은 뒤 헤더·본문을 엑셀 생성 폼에 전달한다. 따라서 고정 CSV/XLSX 피드를 확인한 것은 아니다. 다운로드용 표 응답에서 회사·상품·기본/최고금리·최고금리 적용 가능 금액·비교공시일 열을 확인했지만 이번 응답은 데이터가 없어 유효 상품 표본은 확보하지 못했다. 재사용 허가도 미확인이다. [공식 공시](https://www.fsb.or.kr/ratanym_0100.act), [이용 안내](https://www.fsb.or.kr/ratuserguide_0100.act).

검증은 계약 파싱·타입 생성, 서버 실제 응답의 OpenAPI 검사, 출처별 갱신/잘못된 입력 보존/철회, 비로그인 접근, 빈 목록·실제 타입의 합성 데이터로 화면 필터·조건 비교를 확인한다. 테스트의 합성 상품은 운영 DB에 넣지 않는다.
