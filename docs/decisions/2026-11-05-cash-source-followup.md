## KDB: 개인뱅킹의 개인 입출금 분류

[공식 상품 목록](https://banking.kdb.co.kr/bp/BMDEWP01N00.act)에서 입출금자유상품 분류 `1010300`, 개인 `10`, 개인뱅킹 노출 `20`을 사용한다. `banking.kdb.co.kr/robots.txt`는 일반 봇에 `/search*/`만 제한하며 조회 경로는 해당하지 않는다. 다른 호스트의 robots를 대신 적용하지 않는다.

공식 화면이 쓰는 공개 폼 POST의 `_JSON_` 이중 인코딩을 사용한다. `BMDEWP01R00.jct`의 10개 단위 전체 페이지·전체 건수·다음 페이지·상품 코드 중복을 대조하고, 각 상품의 `BMDEWP01R10.jct` 상세와 `BMDEWP01R12.jct` 현재 금리를 모두 확인한 뒤 한 스냅샷으로 반영한다. 하나라도 실패하면 기존 출처 전체를 유지한다. 최초 기본 목록의 정기예금·적금·외화는 혼합하지 않는다.

11-05 독립 확인 범위는 6개다: KDB Hi 비대면 입출금통장, KDB Hi 입출금통장, KDBdream Account, 행복지킴이 통장, KDB 호국보훈지킴이통장, KDB 생계비계좌. 이 개인뱅킹 분류의 전체이며 은행 전체 또는 전국 전체 모집단을 뜻하지 않는다. 실제 코드는 건수 6을 고정하지 않는다.

- `IRT_LIST` 중 해당 `PRD_C`만 사용한다. `HI_FIVE_LIST`는 다른 상품 추천 목록이므로 제외한다.
- 목록의 조회용 금리 코드와 응답의 현재 세부 금리 코드는 다를 수 있다(행복지킴이 표본). 상세의 상품/조회 코드와 실제 금리 행의 상품 연결을 확인한다.
- 화면이 표시하는 `MNG_PRD_IRT_STG_NM1/2` 구간을 사용한다. 내부의 이전 단계 명칭을 화면 조건처럼 게시하지 않는다.
- 구간별 금리와 우대/추가이율 이벤트·가입·이자 계산·지급 조건은 원문으로 보존한다. 금리 행이 모두 같은 경우만 공통 금리를 표시하며, 다른 금리는 단일 기본금리로 요약하지 않는다. 최고금리·한도·적용일·재투자는 확정 근거가 없으면 null이다. 이벤트 금리를 임의로 더하지 않는다.
- 금리 응답의 `BSE_DT`는 공시 기준일이다. 수정 시각을 적용 시작일로 바꾸지 않는다.
- 공개 출처 링크는 실제로 열리는 공식 상품 목록이다. 상세는 화면의 폼 이동으로 열리므로 불완전한 GET 상세 링크를 만들지 않는다.
- 응답 중 상품 조건에 필요한 필드만 보관한다. 내부 수정자 ID·직원 정보·익명 요청 토큰·쿠키는 저장하지 않는다.

## 부산: 전체 목록 확인, 연결은 보류

[입출금 목록](https://www.busanbank.co.kr/ib20/mnu/FPMDPO012001001)의 `QTY_CHO=36` 공개 조회에서 표시 전체 29개와 서로 다른 상품 코드 29개를 대조했다. 각 상세는 공식 화면의 `/ib20/wgt/FPMPDT012INQV1CM` 폼 POST로 확인했다. 회원 인증이나 설치 프로그램 없이 공개 조회했으며 익명 토큰/쿠키를 저장하지 않는다.

28개는 디지털 안내장 데이터가 있었으나 `0100000162` 뱅크라인통장은 `F9999` 오류였다. 일반 익명 페이지 이동으로도 동일했다. 법인·사업자 전용 상품도 섞여 있어 29개를 개인 상품 수라고 발표하지 않는다. 오류 상세를 무시하고 나머지만 전체 스냅샷으로 반영하지 않는다. 상세가 정상화되거나 공식적으로 판매 종료/다른 정본을 확인하면 다시 연결한다. 28개 금리·개인 자격 확인만으로 전체 수집 완료를 선언하지 않는다.

미래에셋 발행어음 및 나머지 제한 출처도 계속 미연결이다. 과거 공지의 수익률을 현재 금리로 대체하거나 기존 robots 제한을 우회하지 않는다.

## #143: 조건 원문 검색

기존 `conditions`·지급·재투자 원문에서 문구를 찾는 입력을 추가한다. 회사/상품명 검색·금융권·CMA 종류 필터와 함께 적용한다. 우대 충족 여부를 판정하거나 임의 분류 태그를 만들지 않으며 API 응답은 바뀌지 않는다. 분류형 우대/상품 유형 필터와 이용 조건이 확인된 로고는 #143의 미완료 범위다.

## 검증과 운영

`KdbCashParserTest`는 다른 유형·일부 페이지·중복·상품 불일치·구간·추천 혼입·미확인 필드·내부 필드 제외를 검사한다. `KdbCashSimulationTest`는 Postman 로컬 합성 응답의 2페이지/11상품을 실제 HTTP→수집 작업→H2로 실행하고 마지막 상세 503·두 번째 페이지 누락·다른 상품 금리·robots 제한 때 기존 전체 스냅샷 보존을 확인한다. 기관 소유 mock은 없으며 관측한 공개 조회 구조의 합성 자료다.

실제 KDB 공개 조회→격리 H2→API는 6개·`isSample=false`로 확인했다. 최초 검증에서 조회용 금리 코드와 현재 세부 코드의 차이를 과하게 차단해 실패했고, 상품 연결 검증을 유지하면서 바로잡은 뒤 통과했다. 로컬 성공은 운영 배포·적재 성공이 아니다. 기존 파킹 211개에 이번 6개를 단순 합한 값을 새 운영 전체 건수로 표시하지 않는다. 다른 출처의 같은 날 재수집 없이 총건수를 보증하지 않는다.

이 API 응답을 임시 파일로 내보내 로컬 화면에 연결했다. 실제 조건 6개에 대해 390/1280px·라이트/다크 4개 조합에서 구간/비대면/지급 원문 검색, 기본금리 미확인 표시, 3개 비교와 문서 가로 넘침 없음(20개 확인)을 검증했다. 합성 자료의 파킹/CMA 8개 조합에서도 기존 필터와 조건 검색 조합·빈 결과·키보드 지우기·3개 제한을 확인했다(72개 확인, pageerror 0). 배포·CORS·실제 휴대폰 검증은 아니다.

Java 21 + `CASH_SIMULATION_URL` 전체 build는 505개·실패 0·오류 0·건너뜀 4로 통과했다. 별도 실제 KDB opt-in 및 API 응답 내보내기도 통과했다. `npm ci`·시연 ci(`--no-audit --no-fund`), check:api·typecheck·build·시연 lint가 통과했고 웹 JS 901.05kB의 기존 크기 경고와 시연 의존성 deprecated/설치 스크립트 미승인 경고는 남는다. Postman CLI 1.73.0의 `status` 미지원·Orbit 공개 API 탐색 403으로 외부 소유자 검색은 수행하지 못했으며 공식 공개 화면과 로컬 simulation을 검증 근거로 썼다.
