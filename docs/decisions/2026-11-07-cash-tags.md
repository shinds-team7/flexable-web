# 파킹·CMA 분류 태그: 서버가 원문 낱말로 붙인다

- 날짜: 2026-11-07 · 결정: 리드(필터 분류를 서버 필드로) · 관련: Issue #297, #143
- 영향: 웹 백엔드(`cashcatalog`) / 계약(`CashCatalogProduct.tags`) / 웹 프론트(`CashCatalog.tsx` 필터) / 정책 §10

## 배경

#297은 파킹·CMA 비교 화면에 상품 유형(특판·청년·군인 등)과 우대조건(비대면 가입·급여 연동 등) 필터를 요구한다. 이슈는 finlife `join_way`·`spcl_cnd`의 분류를 가정했지만, 파킹·CMA 목록은 은행·증권사 공식 페이지와 저축은행중앙회 표에서 모으며 그런 구조화 값이 없다. 목록 API는 자유 문장 `conditions`만 준다. 운영 웹 서버(`solpa.shinhanacademy.co.kr`)의 실제 목록(2026-11-07, 파킹 217개·CMA 12개)으로 낱말을 대 봤다.

## 결정

1. 선택지 중 **서버 분류 필드**를 골랐다. 서버가 `tags`(열거형 배열)를 계산해 내린다. 화면의 낱말 필터(기존 "금액·우대조건 검색")는 그대로 둔다.
2. 분류는 **상품명과 `conditions` 원문에 정해 둔 낱말이 있는지**로 한다(policies §10, 낱말 표 `cash-tags-v1`). 판정이 아니라 "원문에 이 문구가 있다"는 뜻이다.
3. 저장하지 않고 조회 때 계산한다. 수집 데이터·DB는 바뀌지 않고 낱말 표를 고치면 바로 반영된다.
4. 로고는 이 결정 밖이다. 은행 로고 이미지는 쓰지 않고 글자 아이콘을 유지한다(2026-11-08: 사용 허락을 구하지 않기로 했고 `BankBadge.tsx`의 `LOGOS` 자리를 없앴다).

## 실제 목록으로 확인한 결과(2026-11-07)

| 태그 | 걸린 상품 | 판단 |
|---|---|---|
| 비대면 가입 | 28 | 가입 방식 문구, 맞음 |
| 카드 사용 | 21 | 카드 실적 우대 문구, 맞음 |
| 자동이체 | 19 | 우대 조건 문구, 맞음 |
| 급여 연동 | 13 | 급여이체 우대(제주은행의 "급여, 월급, 봉급…" 적요 안내 포함), 맞음 |
| 청년 | 1 | 교보SBI저축은행 생활파킹통장의 "청년층(만39세 이하) 우대", 맞음(청년 전용 상품은 아님) |
| 군인 | 1 | 제주은행 제주군인연금평생안심통장의 "군인연금을 수령하는 고객", 현역 군인 상품은 아님 |
| 특판 | 2 | 삼성증권 CMA 두 상품 모두 "특판·일반약정식 발행어음과 구분해요" 설명으로 **오탐**, 진짜 특판은 0 |

그래서 **특판 태그는 뺐다**(`SPECIAL_OFFER` 삭제, 이슈의 예시였지만 현재 데이터에는 없고 틀린 표시만 만든다). 군인·청년은 "원문에 이 문구가 있다"는 말 그대로만 보인다.

## 한계와 후속

- 문맥을 보지 않아 "청년이 아닌" 같은 문장에도 `YOUTH`가 붙을 수 있다. 낱말 표는 목록이 늘 때마다 다시 대 보고 다듬는다.
- 주택청약 같은 유형은 파킹·CMA 원문에서 나온 적이 없어 넣지 않았다. 실제 문구가 확인되면 낱말 표에 더한다.
- 태그 종류·낱말을 바꾸면 policies §10, `tests/policy/cash-tags.json`, 계약 열거형을 같은 PR에서 고친다.
