# CMA·ISA 범위 확대 제안 (미승인)

- 날짜: 2026-11-07 · 상태: **제안, 승인 전**. 병합해도 정책·계약이 되지 않는다. · 관련: #245, #144, #145, [1차 범위](2026-11-04-cash-catalog-phase1.md), [수집 결정](2026-11-04-official-cash-ingest.md)
- 요청(리드, 11-07): 법적으로 문제가 생기는 부분(robots 제한 우회 등)은 하지 않고, 가능한 범위에서 CMA 상품(ISA 등)을 최대한 많이 보인다.
- 근거: 11-07에 각 호스트 `robots.txt`를 한 번씩 읽은 결과(수집기와 같은 `User-Agent: FlexableWebCatalog/1.0`, `*` 그룹만 판독). 상품 화면의 데이터 위치는 아직 확인하지 않았다.

## 1. 새로 연결할 수 있는 후보 (robots가 일반 봇을 막지 않음)

robots가 허용해도 **데이터가 어디에 있는지, 금리가 공개되는지, 로그인 없이 읽히는지**는 따로 확인해야 한다. 아래는 "다음 확인 대상"이지 연결 확정이 아니다.

| 후보 | 11-07 robots | 확인할 것 |
|---|---|---|
| 키움증권 `www.kiwoom.com` | `Allow: /` | CMA·RP 상품 안내 화면의 공개 금리 조회 경로 |
| 카카오페이증권 `www.kakaopaysec.com` | `Allow: /` | CMA 금리가 화면에 공개되는지(웹 검색에서는 금리 안내 페이지를 못 찾음) |
| 토스증권 `www.tossinvest.com` | `/_ul/`만 제한 | CMA 금리·발행어음 공개 화면. 데이터 API 호스트의 robots는 따로 확인 |
| 교보증권 `www.iprovest.com` | 제한 없음 | 11-04에 "비정상 요청 제한" 화면이 나온 상품 화면이 지금도 그런지 |

| 부산은행 입출금 | 일부 경로(`/ib20/mnu/SMHONB*`, `*.pdf`)만 제한 | 상세 `F9999` 오류가 풀렸는지. 새 파서·수집 필요 |

## 2. 하지 않는 곳 (robots 제한 또는 확인 실패, 우회하지 않음)

NH투자증권(리다이렉트 대상 `www.nhsec.com`도 `User-agent: *`에 `Disallow: /`), 한국투자, 하나증권, 신영, 카카오뱅크, 은행연합회, 토스뱅크 데이터 호스트, LS증권(`/tuhonGuide/`만 허용), KB국민은행·IBK기업은행(추정 호스트). 대신·유안타·광주은행(400), DB금융투자(302), 하이투자증권(연결 실패), BNK(404, 호스트 추정)는 확인 실패. 금융투자협회 공시(`dis.kofia.or.kr`)는 robots 요청이 오류 화면으로 리다이렉트되어 확인 실패다. 자세한 표는 `docs/product/HANDOFF.md` #245 표.

## 3. 상품 유형을 넓히는 제안

| 유형 | 지금 | 제안 | 필요한 결정 |
|---|---|---|---|
| RP·발행어음형 CMA | 12개 | 후보 출처가 열리는 대로 확장 | 없음(기존 범위) |
| 종금형 CMA | 없음 | 예금자보호 여부·금리 공시 출처가 확인될 때 추가 | 유형 값 추가 → 계약 |
| MMF·MMW형 CMA | 1차 범위 밖 | 실적배당이라 "약정수익률"과 구분해 별도 표기 | 정책(§)·계약. 과거 수익률 고지 규칙 |
| **ISA 계좌(중개형·신탁형·일임형)** | 없음 | ISA는 금리 상품이 아니라 **계좌**다. 약정수익률이 없어 CMA 표에 섞지 않고 별도 화면·모델로 둔다. 보여 줄 값은 수수료, 가입 조건(연령·소득), 비과세·분리과세 한도(세법 근거 필요), 제공 상품 유형 등 **객관 기준** | 별도 정책·계약·화면. 투자 권유로 읽히지 않게 정렬은 사용자가 고르게(`AGENTS.md` F10 규칙) |

## 4. 순서 제안

1. 위 1장 후보의 상품 화면을 하나씩 열어 공개 금리 위치와 로그인 필요 여부를 확인한다(읽기 전용). 결과를 이 표에 채운다.
2. 읽을 수 있는 출처부터 파서·시뮬레이션 테스트를 만들고, 한 출처씩 PR로 연결한다(전체 건수·코드 대조 가능한 곳 우선).
3. 유형 확대(종금형·MMF/MMW·ISA)는 정책·계약 승인 후에 한다. 승인 전에는 구현하지 않는다.

## 5. 리드가 정해 줄 것

- ISA는 CMA와 **별도 화면·모델**로 둬도 되는지, 아니면 이번 범위에서 뺄지.
- MMF·MMW형(실적배당)을 약정수익률 CMA와 같은 목록에 둘지.
- 다올처럼 robots 문법이 잘못된 호스트를 "규칙 없음"으로 읽어도 되는지(제안: 막지 않고 읽되 문서에 이유 기록).

## 하지 않는 것

- robots 제한·접근 차단·로그인·403/429 우회, 다른 봇 이름 사용.
- 기관 확인 없이 건수를 "시장 전체"로 표기.
- 정책·계약·fixture는 승인 전에 만들지 않는다.
