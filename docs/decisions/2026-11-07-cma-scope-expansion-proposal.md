# CMA 범위 확대 (승인)

- 날짜: 2026-11-07 · 상태: **승인(리드, 2026-11-08)**: ISA 제거, MMF·MMW 제외, 종금형은 확인된 상품부터, robots 문법 오류 호스트는 규칙 없음으로 읽고 이유를 남김, 기관 허락 요청은 보류. 정책·계약 변경은 별도 PR에서 한다. · 관련: #245, #144, #145, [1차 범위](2026-11-04-cash-catalog-phase1.md), [수집 결정](2026-11-04-official-cash-ingest.md)
- 요청(리드, 11-07): 법적으로 문제가 생기는 부분(robots 제한 우회 등)은 하지 않고, 가능한 범위에서 CMA 상품(ISA 등)을 최대한 많이 보인다.
- 근거: 11-07에 각 호스트 `robots.txt`를 한 번씩 읽은 결과(수집기와 같은 `User-Agent: FlexableWebCatalog/1.0`, `*` 그룹만 판독). 상품 화면의 데이터 위치는 아직 확인하지 않았다.

|---|---|---|
| 키움증권 `www.kiwoom.com` | `Allow: /` | CMA·RP 상품 안내 화면의 공개 금리 조회 경로 |

## 2. 하지 않는 곳 (robots 제한 또는 확인 실패, 우회하지 않음)

NH투자증권(리다이렉트 대상 `www.nhsec.com`도 `User-agent: *`에 `Disallow: /`), 한국투자, 하나증권, 신영, 카카오뱅크, 은행연합회, 토스뱅크 데이터 호스트, LS증권(`/tuhonGuide/`만 허용), KB국민은행·IBK기업은행(추정 호스트). 대신·유안타·광주은행(400), DB금융투자(302), 하이투자증권(연결 실패), BNK(404, 호스트 추정)는 확인 실패. 금융투자협회 공시(`dis.kofia.or.kr`)는 robots 요청이 오류 화면으로 리다이렉트되어 확인 실패다. 자세한 표는 `docs/product/HANDOFF.md` #245 표.

## 3. 상품 유형 (리드 결정 11-07 반영)

| 유형 | 결정 |
|---|---|
| RP·발행어음형 CMA | 후보 출처가 열리는 대로 확장 |
| 종금형 CMA | 네이버페이 CMA 안내(FAQ 13360, [11-04 기록](2026-11-04-parking-cma-data-sources.md))가 "약정수익률이 있는 RP형·발행어음형·종금형 일부"를 제공한다고 설명하므로 후보에 넣는다. 예금자보호 여부와 금리 공시 출처가 확인된 상품부터 추가하고, 유형 값은 계약 변경이 필요하면 승인 후 |
| MMF·MMW형(실적배당) | **넣지 않는다.** 네이버페이도 약정수익률이 있는 유형만 다룬다고 설명하고, 11-04 1차 범위도 MMF·MMW를 후속으로 뺐다. 네이버 목록 화면 자체는 브라우저 도구가 접근을 막아 직접 확인하지 못했다(리드가 화면을 확인해 달라면 알려 주세요) |
| ISA 계좌 | **제거**(리드 결정). 이 제안의 범위에서 뺀다 |

## robots 문법 오류 호스트 처리 (리드 결정 11-07)

다올투자증권처럼 `robots.txt`가 문법 오류(`Diallow:`)라 규칙이 읽히지 않는 호스트는 **규칙 없음으로 읽는다.** 이유: 기관이 막으려는 규칙이 파싱 가능한 형태로 존재하지 않고, 이 호스트는 텍스트 응답(HTTP 200)으로 정상 제공된다. 다만 그 호스트의 `/img/keditor` 같은 명백한 의도 경로는 호출하지 않는다. 연결할 때 이 이유를 출처 기록(`permission_reference`의 수집 판단 근거)과 결정 문서에 남긴다. HTML 응답 등 robots 형식 오류는 기존대로 실패로 처리한다.

## 4. 순서 제안

1. 위 1장 후보의 상품 화면을 하나씩 열어 공개 금리 위치와 로그인 필요 여부를 확인한다(읽기 전용). 결과를 이 표에 채운다.
2. 읽을 수 있는 출처부터 파서·시뮬레이션 테스트를 만들고, 한 출처씩 PR로 연결한다(전체 건수·코드 대조 가능한 곳 우선).
3. 유형 확대(종금형)는 정책·계약 승인 후에 한다. 승인 전에는 구현하지 않는다.

## 5. 남은 결정

- 네이버페이 CMA 목록 화면 확인(브라우저 접근 차단). 필요하면 리드가 화면의 상품 유형 구분을 알려 준다.

## 하지 않는 것

- robots 제한·접근 차단·로그인·403/429 우회, 다른 봇 이름 사용.
- 기관 확인 없이 건수를 "시장 전체"로 표기.
- 정책·계약·fixture는 승인 전에 만들지 않는다.
