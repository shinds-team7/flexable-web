# 파킹통장 금액별 계산 범위 제안 (미승인)

- 날짜: 2026-11-07 · 상태: **제안, 승인 전**. 병합해도 정책·계약이 되지 않는다. · 관련: Issue #247, [1차 범위](2026-11-04-cash-catalog-phase1.md)
- 근거: 웹 서버(`solpa.shinhanacademy.co.kr`)의 실제 파킹 목록 217개(2026-11-07 읽기 전용 조회)와 `conditions` 원문. 건수는 낱말·문형으로 센 근사치다.
- 영향: 이 제안이 승인되면 백엔드(계산)·계약(요청·응답)·정책(§)·화면이 바뀐다. 지금은 아무것도 구현하지 않는다.

`rateLimit`(최고금리 적용 가능 금액)이 값으로 채워진 상품은 0개다. 구조화된 구간 값이 서버에 없다는 뜻이다.

## 제안: 단계를 나눈다

1. **1단계(계산 가능한 것만)**: 사용자가 넣은 잔액에 대해 **기본금리로** 월·연 이자와 세후 이자를 계산한다. 대상은 "제한없음" 108개와 구간이 명확한 케이뱅크 4개, KDB 기본이율 6개. 우대·이벤트·최고금리는 계산에 넣지 않고 "충족 시 이 금액까지 더"라고 말하지 않는다. 세금은 [정기예금 §6](../policies.md)과 같은 15.4%(내림). 일 단위 윤년 처리는 정하지 않고 월 단위(÷12)로 한다.
2. **2단계(구간 구조화)**: 저축은행 구간 서술 50개(초과분 적용 예시가 있는 상품부터)와 제주 18개를 구간 값으로 구조화한다. 저축은행 쪽은 원문에 초과분 적용이 적힌 것만 대상으로 하고, 제주는 **구간 금리가 잔액 전체에 붙는지 초과분에만 붙는지**를 약관·상품설명서로 확인한 뒤에 한다. 확인 전에는 계산하지 않는다.
3. **계산하지 않음**: SC제일(월평균잔액·출금 조건), 구간이 문장에 없거나 우대 범위 금리라 값을 하나로 못 정하는 상품. 이유를 화면에 보인다.

## 리드가 정해 줄 것

- 1단계의 계산 단위: 월 복리 없는 **월 단순 이자(잔액 × 연이율 ÷ 12)**로 충분한지, 일 단위(÷365)로 할지.
- 1단계에서 "계산 불가" 상품을 목록에 그대로 두고 계산 버튼만 막을지, 아예 감출지.
- 2단계를 하려면 어떤 근거(은행 약관 PDF 등)를 쓸지.
- RP·발행어음 CMA(약정·재투자)는 이 제안 밖이며 별도 제안으로 다룬다.

## 하지 않는 것

- 최고금리를 전체 잔액에 적용하지 않는다.
- 우대 충족 여부를 판정하지 않는다.
- 정책·계약·fixture는 승인 전에 만들지 않는다.
