# 웹 오류 기록: 웹 DB 테이블 `error_events`

- 날짜: 2026-11-08 · 결정한 사람: 리드(채팅에서 앱 서버와 같은 방식으로 웹에도 두라고 요청, 서버 로그 7일은 유지·VM 기준 문서 승인) · 상태: **승인, 구현**
- 이슈: [#338](https://github.com/shinds-team7/flexable-web/issues/338)
- 영향: 웹 서버(V31 `error_events`, `POST /client-errors`, 서버 500 기록, 매일 30일 지난 기록 삭제, 탈퇴 삭제), 웹 화면(오류 보고, 오류 경계), API 계약, 개인정보처리방침 제2조·제4조, 앱 영향 없음
- 따르는 선례: 앱 저장소 `docs/decisions/2026-11-07-error-events.md`. 앱 서버에도 같은 이름의 테이블이 따로 있다(DB가 다르다).

## 결정

1. **테이블** `error_events`(V31): `event_day`(KST)·`fingerprint`(출처·종류·상태·코드·메서드·경로·가린 메시지·스택 첫 3줄의 SHA-256) 유니크. 같은 날 같은 오류는 한 줄로 묶고 `occurrences`만 올린다. 하루 새 줄은 500개까지. 앱 테이블과 다른 점: `source`는 `WEB`/`SERVER`, 원격 업데이트 id(`update_id`) 열이 없다.
2. **가리기**: 서버가 저장 전에 3자리 이상 숫자(쉼표·점 포함)와 이메일을 가린다. 경로는 쿼리를 버리고 숫자·긴 id 조각을 `{id}`로 묶는다. 요청·응답 본문은 받지 않는다.
3. **브라우저 보고** `POST /api/v1/client-errors`(로그인 없이 가능, 유효한 토큰이면 회원 번호, 형식이 맞으면 항상 204):
   - API 실패: 401과 사용자가 고칠 수 있는 예상 코드(`errorReportRules.ts`)를 뺀 모든 4xx·5xx. 연결 끊김은 보내지 않는다.
   - 화면 오류(라우터 오류 화면), 처리 못 한 브라우저 오류(`error`·`unhandledrejection`)
   - 한 번 페이지를 연 동안 20건, 같은 오류는 한 번만. 서버는 보낸 사람(회원 번호, 비로그인은 접속 IP)마다 10분에 30건까지만 저장한다(넘어도 204). IP는 서버 메모리에서 횟수 세기에만 쓰고 저장하지 않는다.
   - 앱 서버를 쓰는 배포(`VITE_API_URL` 있음)는 보내지 않는다.
4. **서버 500**은 `GlobalExceptionHandler`가 `common.ServerErrorSink`(구현 `errorlog.ErrorRecorder`)로 같은 테이블에 남긴다. 로그 파일 기록은 그대로이다. 기록 실패는 원래 응답에 영향을 주지 않는다.
5. **보관**: 매일 04:30(KST) 30일 지난 줄 삭제. 탈퇴 때 `UserWithdrawalListener`로 그 회원 번호의 줄 삭제. `user_id`에는 외래 키가 없어서(회원이 사라진 뒤에도 남는 기록이 아니라 탈퇴 때 지우는 기록) 백업 복원 뒤에는 `deploy/vm/README.md`의 절차로 없는 회원의 줄을 다시 지운다.
6. **서버 로그 7일(Docker 파일 로그)은 유지**한다. 접속 기록(IP)·서버 전체 로그는 방침의 "웹 접속·오류 대응"이며 이 테이블이 대신하지 않는다. 이 테이블은 오류만 가려 구조화해 30일 둔다.
7. **보는 방법**: 지금은 웹 VM의 DB에서 SQL로 본다([error-logs.md](../error-logs.md)). 화면·알림은 필요해지면 만든다.
8. **개인정보처리방침**: 제2조 "웹 접속·오류 대응" 항목 보강, 제4조에 "오류 기록 30일" 행 추가. **시행일은 2026-11-08(리드 결정)**, 변경 이력 줄을 더했다. 서버 배포 전에는 저장되지 않는다.
