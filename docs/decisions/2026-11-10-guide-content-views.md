# 금융 가이드 글별 조회수를 서버에서 센다

- 날짜: 2026-11-10 · 결정한 사람: 사용자(채팅에서 조회순 정렬과 0부터 집계를 요청)
- 이슈: [#393](https://github.com/shinds-team7/flexable-web/issues/393)
- 영향: 웹 서버(V36, `guide` 패키지, 공개 API 2개), 웹 프론트(메인 조회순·조회수 표시, 카테고리 많이 본 순, 글 상세 열람 기록), 개인정보처리방침
- 따르는 선례: 청년 소식 열람 집계(`news.NewsViewService`, V20)

## 결정

1. **세는 기준**: 글 상세를 열면 (글, 방문자, 날짜)당 한 번 센다. 방문자 값은 소식 열람 집계와 같은 브라우저 임의 UUID(`fx.news.viewer`)이고 계정·IP와 연결하지 않는다.
2. **시작값**: 18편 모두 0부터 센다. 지금까지 화면에 보이던 예시 조회수는 이어 쓰지 않는다.
3. **표 두 개**: `guide_content_views`(글별 합계, 계속 보관)와 `guide_content_view_log`(중복 확인용, 30일 보관). 소식 집계는 최근 7일 순위라 기록만 있으면 되지만, 조회수는 누적이라 30일이 지나도 합계가 남아야 한다.
4. **등록된 글만 센다**: V36이 글 18편을 합계 표에 넣고, 표에 없는 글은 404다. 아무 값이나 보내 표가 늘어나는 것을 막는다. 글을 추가할 때는 `src/data/financeGuide.ts`와 함께 새 마이그레이션으로 줄을 넣는다(`GuideContentViewApiTest`가 두 목록이 같은지 검사).
5. **순서**: 조회수가 같으면 그 탭의 추천 콘텐츠에 든 글을 먼저, 그것도 같으면 제목 가나다순으로 보여 준다. 서버에 닿지 못하면 모두 같은 조회수로 보고 같은 규칙을 쓰며, 카드의 조회수 숫자를 숨긴다.

## 받아들인 한계

방문자 값은 브라우저가 만드는 값이라 값을 계속 바꿔 보내면 조회수를 부풀릴 수 있다. 계정·IP와 연결하지 않기로 한 소식 집계와 같은 한계이고, 조회수는 정렬에만 쓰여 금액 계산이나 권한에 영향을 주지 않는다.
