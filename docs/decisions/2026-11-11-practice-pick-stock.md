# 과거 시장 연습에서 종목을 직접 고른다

- 날짜: 2026-11-11 · 결정한 사람: 사용자(Issue의 "정할 것"을 채팅에서 결정)
- 이슈: [#412](https://github.com/shinds-team7/flexable-web/issues/412)
- 영향: 웹 프론트(`/simulation` 과거 시장 연습 설정 화면), 웹 백엔드(`practice` 패키지), API 계약(`/practice/categories`, `/practice/start`)
- 바꾸는 결정: [투자 인사이트와 사건 퀴즈 시뮬레이션 분리](2026-10-26-investment-practice.md) 6번 "동일 업종의 후보 종목은 균등 무작위로 고른다", 완료 조건의 "무작위 종목 선정"

## 결정

1. **업종을 펼쳐 종목을 고른다.** 설정 화면의 업종 행은 펼치기·접기 버튼이고, 펼친 업종 아래에 그 업종의 후보 종목이 나온다. 한 번에 한 업종만 펼친다. 종목(또는 아래 무작위)을 골라야 [시뮬레이션 시작]이 켜진다. 처음에는 아무것도 고르지 않은 채 첫 업종만 펼쳐 둔다.
2. **무작위로 받기도 남긴다.** 펼친 업종 목록 맨 위에 "무작위로 받기"를 둔다. 고르면 지금처럼 그 업종 후보 중 균등 무작위다. 계약에서는 `stockCode`를 생략한 요청이다.
3. **정렬은 이름 순**(같으면 종목 코드 순)이다. practice 묶음과 종목 마스터에 시가총액이 없고, 시가총액 순은 수집 worker 변경이 필요해 이번 범위(#412 "하지 않을 일")를 벗어난다.
4. **후보 목록은 `/practice/categories` 응답에 담는다**(업종마다 `stocks[{code, name}]`, 개수는 `eligibleCount`와 같다). 업종별 엔드포인트를 따로 두지 않는다. 후보는 수백 개 수준이라 응답 한 번으로 충분하고, 펼칠 때마다 기다림·오류 상태를 따로 두지 않아도 된다.
5. **후보가 아닌 종목은 400이다.** `/practice/start`의 `stockCode`가 그 업종의 지금 후보가 아니면(다른 업종 종목, 후보에서 빠진 종목, 없는 코드) `400 VALIDATION_FAILED`(`fields.stockCode`)이고 다른 종목이나 예시 자료로 대체하지 않는다. 업종 후보가 0개면 `stockCode`와 관계없이 지금처럼 503이다.

## 이유

- 무작위만 있으면 관심 있는 회사로 연습할 수 없고, 같은 업종을 여러 번 해도 원하는 종목을 다시 만나기 어렵다.
- 재생 구간은 worker가 종목마다 미리 고정하므로([재생 구간 결정](2026-11-03-practice-event-window.md)) 종목을 고른다고 구간·사건 출제·매매·평가 규칙이 달라지지 않는다. 고른 종목의 구간을 그대로 재생한다.
- 회사 이름을 보고 고르면 그 회사의 과거 흐름을 미리 알고 시작할 수 있다. 결정 기록의 "공개 과거 자료를 외부에서 찾아보는 것까지 막는 시험 서비스는 아니다"와 같은 입장이고, 정답 채점·순위가 없는 연습이라 받아들인다. 미리 모르고 하고 싶은 사람을 위해 무작위를 남긴다.

## 바뀌는 것(문서·코드·설정)

- 계약: `/practice/categories` 업종에 `stocks` 필수, `/practice/start` 요청에 `stockCode`(선택)·summary/description.
- 백엔드: `PracticeDtos.Start.stockCode`, `Category.stocks`, `PracticeService.start`의 종목 확인. `ContractTest`에 고른 종목 시작·다른 업종 종목·없는 코드 400.
- 프론트: `Simulation.tsx` 업종 토글과 종목 라디오, `practice.css`, 랜딩 소개 문구.
- 문서: policies §5, PRD F1 추가 스펙, CHANGELOG.
- 바뀌지 않는 것: 재생 구간, 사건 출제, 매매·평가 계산, 세션 수명·상한, 가상 시뮬레이션·대회, 업종 분류·수집 worker, 개인정보 처리(고른 종목은 지금도 세션 메모리에 두는 "선정 종목"과 같다).
