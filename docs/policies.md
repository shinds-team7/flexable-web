# 정책 — 계산·상태 규칙

웹 서버가 계산하는 규칙과 입력→기대값 예시다. **예시 표는 [`tests/policy/`](../tests/policy/)의 테스트 케이스와 같은 내용**이고, 백엔드 테스트(`GoalPolicyTest`·`SimulationPolicyTest`·`PracticePolicyTest`·`DepositPolicyTest`, §7은 `GoalScenarioPolicyTest`, §8은 구현 뒤 `VirtualSimPolicyTest`)가 코드와 맞는지 확인한다. 표를 고치면 같은 PR에서 JSON도 고치고 `spec-change` 라벨과 [CHANGELOG](CHANGELOG.md) 한 줄을 붙인다. 정책에 없는 상황을 만나면 임의로 정하지 않고 알린다.

공통: 금액은 **원 단위 정수**, 나눗셈은 **내림**(목표의 필요 금액만 부족하게 보이지 않게 올림). 계산은 서버만 하고 화면은 결과를 그린다(ADR-3). 오류는 `400 VALIDATION_FAILED` + `fields`.

## 1. 시드머니

| 규칙 | 내용 |
|---|---|
| 적용값 | 웹 직접 수정값(`manual.total`)이 있으면 그 값 → 없으면 앱 연동 값(`status=available`의 `total`) → 둘 다 없으면 로그인 회원 0원. 비로그인 체험은 예시 4,270,000원(저장 안 함) |
| 직접 수정 범위 | 0 ~ 1,000,000,000원 정수. 회원당 하나, 다시 보내면 덮어쓴다. 지우면 앱 값으로 돌아간다 |
| 앱 연동 회원(#83, 2026-10-27) | 고치면 앱 서버에 총액을 보낸다(앱은 모아둔 돈 = 총액 − 반영한 돈 합). 반영되면 직접 수정값을 지우고 앱이 돌려준 값을 쓴다(`appSync.status=applied`). 앱이 거절(반영한 돈보다 작음)·예산 설정 전·장애면 웹에만 저장하고 안내한다(`failed`). 연동하지 않았으면 웹에만 저장(`appSync=null`) |
| 앱 값 | 앱 서버가 확정한 값 그대로다. 웹은 수입−지출을 계산하지 않는다(04 §5) |
| 목표(F7) | 10-26 F7 재정리 전까지 앱 값이 available이면 앱 값, 아니면 목표에 직접 넣은 값을 쓴다(직접 수정값은 쓰지 않음, decisions 2026-10-24 ②) |

| 입력 | 기대 |
|---|---|
| `PUT manual {total: 0}` | 200, 적용값 0원 |
| `PUT manual {total: 1000000001}` | 400 `VALIDATION_FAILED`, `fields.total` |
| `PUT manual {total: 12.5}` | 400 `VALIDATION_FAILED` |
| 앱 4,700,000원 + 수정 5,000,000원 | 적용값 5,000,000원 |
| 연동 회원, 앱 1,450,000원(반영 950,000) + 수정 2,000,000원 → 앱 반영 성공 | 앱 값 2,000,000원, `manual=null`, `appSync.status=applied` |
| 연동 회원, 수정 100,000원 → 앱 거절(반영 950,000원보다 작음) | 적용값 100,000원(웹만), 앱 값 1,450,000원 그대로, `appSync.status=failed` |

검사: `SeedMoneyManualApiTest`.

## 2. 투자 시뮬레이션(`simulation.SimulationEngine`)

**입력 범위**: 한 번에 넣는 금액 10,000~100,000,000원, 매달 넣는 금액 1,000~10,000,000원, 종목 1~3개. 시작일은 그 달 1일로 맞추고, 오늘 이후·10년 넘게 전은 400이다.

**비율**: 모두 비우면 균등하게 나눈다(소수 4자리 내림, 나머지는 첫 종목). 하나라도 넣었으면 모든 종목에 0보다 크게 넣고 합이 1이어야 한다.

| 입력 비율 | 기대 |
|---|---|
| 비움 ×3 | 0.3334 / 0.3333 / 0.3333 |
| 비움 ×2 | 0.5 / 0.5 |
| 0.5 / 0.3 / 0.2 | 그대로 |
| 0.5 / 0.4 | 400 "비율의 합이 100%가 되게 넣어 주세요" |
| 0.5 / 비움 | 400 "비율은 모든 종목에 0보다 크게 넣어 주세요" |

**배분**: 회차 금액 × 비율을 원 단위 내림하고, 남은 원은 첫 종목에 붙인다.

| 금액 · 비율 | 기대 |
|---|---|
| 100,000 · 0.5/0.3/0.2 | 50,000 / 30,000 / 20,000 |
| 100,001 · 0.3334/0.3333/0.3333 | 33,341 / 33,330 / 33,330 |

**납입과 평가**
- 시작 월부터 매달, 그 달 첫 거래일(시작일 이후) 종가로 산다. 모든 종목에 거래일이 있는 달만 센다.
- 한 번에(`LUMP_SUM`)는 첫 달에 전부 넣는다. 매달 나눠서(`SPLIT`)·지금 저축 속도로(`PACE`)는 매달 같은 금액을 넣는다.
- 수량 = 금액 ÷ 종가, 소수 8자리 내림(소수점 매수 가정). 평가액 = 수량 × 종가, 원 단위 내림.
- 시계열은 주(월~일)마다 그 주 마지막 거래일 종가로 평가한다. 휴장 주는 직전 종가를 쓴다.
- 기간 끝은 고른 종목들의 마지막 시세일 중 가장 이른 날이다.
- 배당·세금·수수료는 반영하지 않는다.

| 조건(종가: 1/2 1,000 · 1/9 1,100 · 2/2 800 · 2/6 900) | 넣은 횟수 | 넣은 돈 | 평가액 | 차이 | 수익률 |
|---|---|---|---|---|---|
| 매달 10,000원, 2026-01부터 | 2 | 20,000 | 20,250 | +250 | 0.0125 |
| 한 번에 20,000원, 2026-01 | 1 | 20,000 | 18,000 | −2,000 | −0.1000 |

| 조건 | 기대 |
|---|---|
| 한 번에 78,000원, 1/2 종가 61,500원에 사서 1/9 종가 70,000원 | 수량 1.26829268, 평가액 88,780원, 수익률 0.1382 |

**수익률**: 차이 ÷ 넣은 돈, 소수 4자리 **내림(음수는 더 작은 쪽)**. 넣은 돈이 0이면 0이다.

| 차이 · 넣은 돈 | 기대 |
|---|---|
| 648,830 · 2,808,000 | 0.2310 |
| −1 · 3 | −0.3334 |
| 5 · 0 | 0 |

검사: `SimulationPolicyTest`(이 표), `SimulationEngineTest`·`SimulationApiTest`.

## 3. 목표 계산(`engagement.GoalMath`)

현재 v1의 저축 산술 정책이다. 2026-10-29 [F7 개편](decisions/2026-10-29-goal-scenarios.md)은 실제 상품·종목·비중과 수익·위험 분포를 비교하도록 방향을 바꿨지만, 새 계산은 §7(`POST /goal/scenarios`, 11-03 MVP 확정)이다. 아래 규칙·fixture·현재 API(`/me/goal`)는 그대로 유지한다. v1 목표 화면은 11-03에 뺐다(#201, 웹 화면은 이 API를 부르지 않음).

- 남은 금액 = max(0, 목표 − 현재).
- 남은 개월 = 이번 달부터 기한까지의 달 수(지났으면 음수). 계산에는 최소 1을 쓴다.
- **필요 월 금액** = 남은 금액 ÷ 계산 개월을 **천 원 단위로 올림**한다. 이미 닿으면 0, 기한이 지나면 없음(`null`).
- 예상 개월 = 남은 금액 ÷ 저축 속도(올림). 예상 달 = 이번 달 + 예상 개월.
- 상태:

  | 상태 | 조건 |
  |---|---|
  | `REACHED` | 남은 금액 0. 기한보다 먼저 판정 |
  | `OVERDUE` | 기한이 지남 |
  | `NO_PACE` | 저축 속도 없음 |
  | `ON_TRACK` | 예상 개월 ≤ 계산 개월 |
  | `BEHIND` | 그 밖 |

- 부족액(`BEHIND`만) = 필요 월 금액 − 저축 속도. 하루 부족액은 그 ÷ 30을 **100원 단위로 올림**한다.
- 진행률(`ratioBp`) = 현재 × 10000 ÷ 목표(내림), 넘으면 10000이다.
- 입력: 종류 6개, 이름 1~20자, 금액 1만~10억 원, 기한은 다음 달부터 120개월 안이다.

이번 달 2026-10 기준:

| 목표 · 현재 · 속도 · 기한 | 상태 | 필요 월 금액 | 예상 개월(달) | 부족액(월/일) | 진행률 |
|---|---|---|---|---|---|
| 1,000만 · 400만 · 50만 · 2027-10 | ON_TRACK | 500,000 | 12(2027-10) | 0 / 0 | 4000 |
| 1,000만 · 400만 · 30만 · 2027-04 | BEHIND | 1,000,000 | 20(2028-06) | 700,000 / 23,400 | 4000 |
| 100만 · 0 · 없음 · 2027-01 | NO_PACE | 334,000 | 없음 | 0 / 0 | 0 |
| 500만 · 520만 · 10만 · 2027-10 | REACHED | 0 | 0(2026-10) | 0 / 0 | 10000 |
| 300만 · 100만 · 10만 · 2026-08 | OVERDUE | 없음 | 20(2028-06) | 0 / 0 | 3333 |

시나리오(지금 속도 유지·기한 맞추기·6개월 늘리기)와 점검표(25·50·75·100%)는 [goal-ai.md](product/goal-ai.md)가 정본이다. 검사: `GoalPolicyTest`(이 표), `GoalMathTest`.

## 4. AI 목표 안내

아래는 현재 v1 안내의 횟수·실패 정책이다. 새 F7의 제안·검증·데모 대체는 §7-6이고, AI 연결 시의 사용량·오류 정책은 AI 연결 작업에서 정한다. 기존 수치나 고지문을 새 투자 예측의 확정 정책으로 재사용하지 않는다.

- 무료 회원 하루 3회. 같은 facts의 AI 결과는 캐시라 차감하지 않는다. 넘으면 429 `TOO_MANY_ATTEMPTS` + `retryAfterSeconds`(다음 날 0시까지).
- AI가 응답하지 않아도 화면은 동작한다. 항상 기본 안내(`aiGenerated=false`)를 돌려주고 이유를 `fallbackReason`에 담는다.

  | `fallbackReason` | 언제 |
  |---|---|
  | `AI_UNAVAILABLE` | 키 없음. 차감하지 않음 |
  | `DAILY_CAP` | 서비스 전체 일일 상한 |
  | `AI_FAILED` | 시간 초과·4xx·5xx·JSON 아님 |
  | `AI_REJECTED` | 금지어·형식 검사 실패 |

- 사용 횟수는 7일 뒤 지운다(방침 제4조).

검사: `GoalApiTest`, 정본 [goal-ai.md](product/goal-ai.md).

## 5. 사건 퀴즈 투자 시뮬레이션

기존 §2는 투자 인사이트의 계산으로 그대로 유지한다. 아래 규칙은 신규 `/simulation` 전용이며 #88로 구현됐다. 결정·데이터 준비·세션 수명은 [결정 기록](decisions/2026-10-26-investment-practice.md)을 따른다. 테스트 입력 정본은 `tests/policy/practice.json`이고, 이를 실행하는 것은 `PracticePolicyTest`다.

- 종목 고르기: 업종을 펼쳐 그 업종의 후보 종목(이름 순, 같으면 코드 순) 중 하나를 고르거나 "무작위로 받기"(후보 중 균등 무작위)를 고른다. 고른 종목이 그 업종의 지금 후보가 아니면 400이고 다른 종목·예시 자료로 대체하지 않는다. 업종 후보가 0개면 503이다([종목 고르기 결정](decisions/2026-11-11-practice-pick-stock.md), #412).
- 투자금: 10,000~100,000,000원 정수. 추가 입금·차입·공매도 없음. 배당·수수료·세금 제외. 수량은 정수 주다. 가상 시뮬레이션의 레버리지 판(8-9)도 돈을 빌리지 않는다: 가격이 배율로 움직일 뿐이고 이 평가 식을 그대로 쓴다.
- 최초 매수: 첫 봉 시가에서 `floor(floor(투자금 × 50 / 100) / 시가)`주. 현금은 투자금에서 실제 매수 대금을 뺀 값이다. 0주도 허용한다.
- 매수: 선택 당시 현금에 비율(25/50/100%)을 곱해 원 단위 내린 예산을 잡고, 다음 봉 시가로 살 수 있는 정수 주만 산다. 나머지는 현금이다. 0주면 미체결이다.
- 매도: 선택 당시 보유 수량 × 비율(25/50/100%)을 내린 정수 주를 다음 봉 시가에 판다. 0주면 미체결이다. 유지는 비율 0이고 거래하지 않는다. 매수·매도에 비율 0이나 다른 비율을 보내면 400이다.
- 평가: 매일 종가 × 보유 수량 + 현금 = 총자산. 손익 = 총자산 − 최초 투자금. 수익률 = 손익 / 최초 투자금, 소수 4자리 내림(음수는 더 작은 쪽). 화면은 금액·수익률을 재계산하지 않는다.
- 첫 봉부터 구간 끝(120~250거래일)까지 순서대로 보여준다. 구간은 아래 "재생 구간 고르기"로 종목마다 정한다. 사건에서 멈추면 선택 전 다음 봉을 요청해도 409다. 미래 날짜·가격·주문 체결 가격을 클라이언트가 지정할 수 없다.
- 방향 판정: 공시를 보여줄 때의 마지막 종가와 그 뒤 **다섯 번째 거래일 종가**를 비교한다. 상승이면 긍정, 하락이면 부정 예상과 일치한다. 같으면 보합으로 양쪽 모두 채점 제외한다. 수익률 반올림 결과가 0이어도 원 가격으로 방향을 판정한다.
- 판정 문구는 "이후 5거래일 실제 등락"이다. 사건이 상승/하락을 일으켰다는 인과 판정이나 매매 권유가 아니다. 5거래일 자료가 없는 공시는 출제하지 않는다.

### 재생 구간 고르기

worker가 종목마다 한 번 고르고 세션은 고른 구간을 그대로 재생한다. 결정은 [재생 구간 결정](decisions/2026-11-03-practice-event-window.md)을 따른다.

- 출제 규칙: 공시는 접수일 당일 봉 뒤에 공개한다. 첫 봉 이전 공시와 첫 사건 전 14거래일을 채우지 못하는 공시는 빼고, 접수일·접수번호 순으로 접수번호를 중복 제거한다. 같은 재생 위치의 공시는 첫 건만, 직전 문제의 다섯 번째 후속 거래일 뒤의 공시만, 사건 뒤 5거래일이 있는 공시만 출제한다. 개수 상한은 없다(이전 최대 3건). 간격 규칙상 250거래일에서 최대 39개다.
- 탐색 범위: 최근 5년 일봉(이전 9개월).
- 후보 창: 연속된 유효 OHLC 120~250거래일. OHLC가 빠지거나 잘못된 봉이 하나라도 든 창은 쓰지 않는다.
- 고르기: 위 출제 규칙으로 **문제가 3개 이상**인 창만 쓴다. 120거래일부터 하루씩 늘려 그런 창이 처음 나오는 **가장 짧은 길이**를 쓰고, 그 길이에서 **문제가 가장 많은 창**, 같으면 **가장 최근 창**(첫 봉이 가장 늦은 창)이다. 공시 건수가 아니라 출제 수를 센다.
- 후보 없음: 250거래일 안에 문제 3개 이상인 창이 없거나 일봉이 120개 미만이면 그 종목은 이번 실행에서 저장하지 않는다. 직전 묶음은 수집 실패와 같이 지우지 않지만, 세션은 문제가 3개 미만인 묶음을 후보에서 뺀다.
- 저장하는 공시는 고른 구간의 첫 봉~마지막 봉 날짜 안의 것만이다. 응답 `totalDays`는 고른 구간의 길이다.

## 7. 목표 달성 시나리오(F7 v2, `POST /goal/scenarios`)

[F7 개편](decisions/2026-10-29-goal-scenarios.md)의 MVP 계산이다(11-03 확정, [#174](https://github.com/shinds-team7/flexable-web/issues/174)). 구현: [#175](https://github.com/shinds-team7/flexable-web/issues/175)(`goalscenario` 패키지). §3·§4(v1 `/me/goal`)는 그대로 둔다. 테스트 입력 정본은 `tests/policy/goal-scenarios.json`이고 `GoalScenarioPolicyTest`가 실행한다.

**역할**: 조합(상품 유형과 비중)은 **제안기**가 정하고, 서버는 제안을 검증한 뒤 숫자를 모두 계산한다. 제안기는 AI 키가 있으면 AI, 없거나 AI 제안이 검증에 실패하면 **데모 제안기**(아래 고정 조합)다. 응답의 `proposer`가 어느 쪽인지 알린다. AI가 말한 숫자(금액·확률·수익률)는 쓰지 않는다.

### 7-1. 입력

| 항목 | 규칙 |
|---|---|
| 목표 이름 | 앞뒤 공백을 뺀 1~20자. 계산에 쓰지 않고 응답에 그대로 돌려준다. 로그에 남기지 않는다 |
| 목표 금액 | 1,000,000~1,000,000,000원 정수 |
| 기한 | **6~60개월**(`months`, 11-10 #377. 11-11 #406에서 최대 3년 → 5년, #301을 하지 않기로 한 결정을 바꿈). 화면은 연(0~5)·월(0~11)로 받아 개월로 보낸다(5년이면 0개월만) |
| 월 납입 가능액 | **선택**(`monthlyBudget`, 11-10 #399). 천 원 단위, 10,000원~목표 금액 정수. 비우면 지금과 같이 계산하고 비교하지 않는다. 필요 월 금액 계산(7-5)은 바꾸지 않고 비교에만 쓴다 |
| 시작 금액 | 0원으로 고정(입력받지 않음) |

계산만으로는 저장하지 않는다(회원이 저장을 누른 결과만 7-8로 저장). 범위를 벗어나면 `400 VALIDATION_FAILED`.

### 7-2. 상품 유형

| 유형 | 고르는 규칙 | 계산 |
|---|---|---|
| `SAVINGS` 적금 | finlife 적금 중 **은행(1금융권)**, 정액적립식, 만기 = **기한 개월 이하인 만기 중 아래 조건에 맞는 상품이 있는 가장 긴 것**(11-10 #377, 예: 기한 18개월에 18개월 상품이 없으면 12개월), 가입 제한 "제한 없음", **가입 대상에 "실명의 개인"이 있는 상품**(저축은행·지역 상품과 사업자·법인 전용 상품 제외, 11-04 추가, #214), 월 납입 한도 없음(`maxLimit` null). 그중 기본금리가 가장 높은 상품, 같으면 상품 id 오름차순 첫 번째 | 적금 계산과 같다(C-12, 공시된 이자 방식, 기본금리, 회차 이자 내림, 세금 floor(세전 × 0.154)). 만기가 기한보다 짧으면 아래 "만기 뒤 남은 달" |
| `CMA` | 실데이터 전까지 **예시 금리 연 2.5%**(`isSample`, [CMA 결정](decisions/2026-10-31-parking-cma.md)) | 매달 초 넣은 뒤 그 달 이자 = floor(잔액 × 연이율 ÷ 12)를 잔액에 더한다. 기한 말 세금 = floor(총이자 × 0.154) |
| `KR_INDEX_ETF` 국내 대표 지수 ETF | `board=ETF` 중 이름이 `200`으로 끝나는 종목(예: KODEX 200) 중 **수익률 자료가 있는**(7-3) 시가총액 1위 | 아래 7-3 투자 계산. 비과세 |
| `US_INDEX_ETF` 미국 대표 지수 ETF | `board=ETF` 중 이름이 `S&P500`으로 끝나는 종목(국내 상장, 예: TIGER 미국S&P500) 중 **수익률 자료가 있는** 시가총액 1위 | 7-3 투자 계산. 기한 말 이익이 0보다 크면 floor(이익 × 0.154)를 뺀다 |
| `KOSPI_TOP5` 코스피 주식 | `board=KOSPI` 보통주(이름이 `우`·`우B`·`우C`로 끝나면 제외) 중 **수익률 자료가 있는** 시가총액 상위 5종목 | 이 유형 몫을 5종목에 같은 금액으로 나눠 7-3 투자 계산. 비과세 |

- 시가총액은 기준일(7-3)의 수집 값이다. 고른 상품의 이름·코드와 기준일을 응답에 담는다.
- 시가총액 순으로 보다가 61개 월말 종가가 모자란 상품(상장한 지 5년이 안 된 종목 등, 예: 2021-11 상장한 SK스퀘어)은 **건너뛰고 다음 순위**를 쓴다(11-04 추가, #206).
- 기한 이하 만기의 적금 후보가 없으면 `503 MARKET_UNAVAILABLE`(`field`: `SAVINGS`). 응답의 적금 상품에 만기 개월 `termMonths`를 담는다(다른 유형은 `null`).
- **만기 뒤 남은 달**(11-10, #377): 적금 만기가 기한보다 짧으면, 만기에 받은 돈(세후)을 CMA 예시 금리(연 2.5%)로 옮기고 남은 달 동안 적금 몫을 매달 초 여기에 넣는다. 매달 이자 = floor(잔액 × 연이율 ÷ 12), 기한 말 세금 = floor(이 부분 총이자 × 0.154). 원래 CMA 비중과는 **따로 계산해서 더한다**(합치면 이자 내림 횟수가 달라 몇 원 차이 남). 비중은 처음 정한 그대로이고, 만기 뒤에 바뀌는 건 적금 몫이 들어가는 곳뿐이다. 이때 가정에 "적금 만기가 기한보다 짧으면 만기에 받은 돈과 남은 달의 적금 몫을 CMA 예시 금리 연 2.5%로 계산했어요."를 더하고, 화면은 적금 아래에 만기와 남은 달을 적는다.
- **함께 볼 상품**(11-06, #309): 적금·지수 ETF는 위 규칙의 다음 순위를 최대 2개 응답의 `alternatives`에 담는다(적금은 1순위와 같은 만기에서 기본금리 순, 지수 ETF는 수익률 자료가 있는 시가총액 순). 금액·확률 계산에는 쓰지 않고 1순위 상품만 쓴다. 후보가 모자라면 있는 만큼만 담고 오류로 보지 않는다. CMA는 실데이터가 없고 `KOSPI_TOP5`는 5종목 전체를 계산에 쓰므로 비어 있다.

### 7-3. 투자 계산(지수 ETF·주식)

- **수익률 자료**: 기준일(수집된 마지막 거래일)이 속한 달의 **직전 달까지** 60개월. 월 수익률 = 그 달 마지막 거래일 종가 ÷ 전달 마지막 거래일 종가 − 1(61개 월말 종가가 필요하다). 배당·수수료·환율 따로 반영 안 함(국내 상장 상품 가격에 들어 있음).
- 61개 월말 종가가 없는 상품은 7-2에서 건너뛴다. 건너뛰고 나서 유형에 맞는 상품이 모자라면 `503 MARKET_UNAVAILABLE`(`field`: 유형 이름 `KR_INDEX_ETF`·`US_INDEX_ETF`·`KOSPI_TOP5`). 수집된 시세가 하나도 없을 때도 같다.
- **경로 만들기**: 60개월에서 연속 12개월 묶음(시작 위치 0~48, 49가지)을 무작위로 ⌈기한 개월 ÷ 12⌉번 골라 이어 붙이고 **앞에서 기한 개월만** 쓴다(18개월이면 2묶음 24개월 중 앞 18개월, 11-10 #377). 12·24·36개월은 바뀌기 전과 같은 경로다. 경로 **2,000개**. 난수는 `SplittableRandom(20261103)`에서 `nextInt(49)`를 경로 순서대로 뽑는다. **모든 상품과 모든 시나리오가 같은 2,000개 묶음 순서를 쓴다**(같이 오르내림 유지, 시나리오끼리 비교 가능).
- **납입과 평가**: 매달 초 그 달 몫을 넣고 그 달 수익률을 적용한다. 평가액 = Σ(그 달 몫 × 그 달부터 기한 말까지 (1 + 수익률)의 곱). 계산 중에는 소수(BigDecimal, 소수 10자리 이상)로 두고 기한 말에 원 단위 내림. 리밸런싱·중도 인출 없음.

### 7-4. 배분

- 시나리오 월 금액 × 비중(정수 %) ÷ 100 = 유형별 월 금액. 월 금액은 천 원 단위라 항상 나누어떨어진다. `KOSPI_TOP5`는 다시 5로 나누며 역시 나누어떨어진다(1,000 × 비중 ÷ 100 ÷ 5 = 2 × 비중).
- 유형별 월 금액의 합 = 시나리오 월 금액(금액 보존).

### 7-5. 결과

경로 p의 기한 말 금액 = 유형별 기한 말 금액(세후)의 합. 적금·CMA는 모든 경로에서 같다.

| 값 | 정의 |
|---|---|
| 필요 월 금액 `monthly` | 경로 2,000개 중 **80% 이상(1,600개 이상)** 이 기한 말 금액 ≥ 목표 금액이 되는 **가장 작은 천 원 단위 금액**. 1,000원부터 목표 금액까지 찾고, 없으면 `null`(`reachable=false`) |
| 넣은 돈 `paid` | 필요 월 금액 × 개월 수 |
| 달성 비율 `chanceBp` | 그 월 금액에서 목표에 닿은 경로 수 × 10000 ÷ 경로 수(내림) |
| 결과 범위 | 기한 말 금액을 오름차순 정렬한 v에서 하위 10% = v[⌈0.1n⌉−1], 중간값 = v[⌈0.5n⌉−1], 상위 10% = v[⌈0.9n⌉−1] (n = 2,000이면 199·999·1799번째) |
| 원금 손실 비율 `lossBp` | 기한 말 금액 < 넣은 돈인 경로 수 × 10000 ÷ 경로 수(내림) |
| 확정형 `fixed` | 투자 유형 비중이 모두 0이면 결과가 하나라 범위 대신 `fixedAmount`를 준다(`chanceBp` 10000, `lossBp` 0) |

- 필요 월 금액이 `null`이면 결과 범위·비율도 `null`이다. 화면은 "이 조합으로는 10번 중 8번 닿는 월 금액을 찾지 못했어요"를 보여 준다.
- 확률은 "정해진 가정 아래의 모형 추정"이다. 0%·100%라도 실제 가능성을 단정하지 않는 고지(`GOAL_SCENARIO_EST`)를 늘 붙인다.

**결과 문장 `resultText`**(11-10, [#391](https://github.com/shinds-team7/flexable-web/issues/391)): 서버가 정해 둔 문장에 그 시나리오의 계산값을 넣는다. AI(제안기)는 이 문장을 만들지 않고 숫자도 쓰지 않는다. 화면은 해설 카드의 "계산 결과" 소제목에 보여 준다.

| 경우 | 문장 |
|---|---|
| 투자 포함(`RANGE`) | 매달 {월 금액}씩 넣으면 10번 중 {N}번 목표에 닿아요. 잘 안 풀리면(하위 10%) {하위 10% 금액}이고, 원금보다 적게 남을 가능성은 {손실}예요. |
| 적금·CMA만(`FIXED`) | 매달 {월 금액}씩 넣으면 {기한} 뒤 {기한 말 금액}이 돼요(세후 이자 포함). |
| 닿지 못함(`reachable=false`) | 목표 금액 안의 월 금액으로는 10번 중 8번 목표에 닿지 못했어요. 기한을 늘리거나 목표를 조정해 보세요. |

- 표기는 화면과 같고 모두 내림이다. 월 금액은 원 단위 그대로(`1,067,000원`, 천 원 단위라 줄이지 않는다). 하위 10%·기한 말 금액은 만 원 미만을 내려 "1억 2,345만 원"·"1,125만 원"처럼 쓰고, 만 원이 안 되면 "9,999원"이다. N = `chanceBp` ÷ 1000(내림), 손실 = `lossBp` ÷ 100(내림)%. 기한은 "1년 6개월"·"2년"·"6개월".
- 저장한 시나리오(7-8)는 이 문장을 저장하지 않고, 조회할 때 저장된 월 금액·결과로 만든다(옛 저장본 포함).

**월 납입 가능액 비교**(11-10, [#399](https://github.com/shinds-team7/flexable-web/issues/399)): 필요 월 금액은 위 정의(10번 중 8번, 가장 작은 천 원 단위 금액) 그대로 찾고, 가능액을 넘는 금액도 끝까지 찾는다. 가능액이 있으면 시나리오마다 비교한다.

| 값 | 정의 |
|---|---|
| `withinBudget` | 필요 월 금액 ≤ 가능액이면 `true`. 필요 월 금액 > 가능액이거나 월 금액을 찾지 못했으면(`reachable=false`) `false`. 가능액이 없으면 `null` |
| `overBudgetBy` | `withinBudget=false`이고 `reachable=true`일 때 필요 월 금액 − 가능액(천 원 단위). 그 밖에는 `null` |
| 대안 문장 | `withinBudget=false`면 해설 "주의할 점과 맞는 사람"(`fit`) 칸 끝에 서버가 정해 둔 문장 "이 조합은 월 납입 가능액보다 많이 넣어야 해요. 목표를 낮춰보거나 월 납입 가능액을 늘려보세요."를 한 칸 띄우고 붙이고, 합친 해설(`explanation`)도 다시 만든다. 걸린 문장을 지워 `fit`이 빈 칸이면 이 문장만 남는다. 네 칸이 없는 옛 재사용 조합은 `explanation` 끝에 새 문단으로 붙인다. AI·데모·재사용 조합 모두 같다. 숫자를 넣지 않고, 목표를 얼마로 낮출지·가능액을 얼마로 늘릴지는 계산하지 않는다 |

- AI는 조합을 정할 때 필요 월 금액을 알 수 없어(서버가 나중에 계산) 대안 문장을 서버가 붙인다(사용자 결정, AI 추가 호출 없음).
- 저장한 시나리오(7-8)는 비교 값과 대안 문장을 붙인 해설을 그때 값 그대로 저장한다. #399 전 저장본은 `monthlyBudget`·`withinBudget`·`overBudgetBy`가 `null`이다.

### 7-6. 제안 검증과 데모 조합

**AI 제안기(11-04 추가, #215)**: OpenAI(`OPENAI_API_KEY`·`OPENAI_MODEL`, 목표 안내와 같은 키)가 조합을 낸다. 구조화 출력(JSON 스키마)으로 받고 `store: false`. 해설은 조합 이유·유형별 역할과 근거·다른 시나리오와의 차이·주의할 점과 맞는 사람의 필수 칸 네 개로 받아 응답에 칸별로 `explanationParts`(`reason`·`roles`·`comparison`·`fit`)로 내고(11-11 #402부터 AI는 `roles` 대신 유형별 칸 `typeRoles`를 내고 서버가 `roles`로 합친다, 아래 v10), 빈 칸을 뺀 나머지를 문단으로 합친 값도 `explanation`으로 낸다(11-10, #391. 화면은 칸마다 소제목을 붙여 보여 주고, `explanationParts`가 `null`인 옛 데이터는 `explanation` 한 문단으로 보여 준다). AI가 보낸 응답에서 한 칸이라도 비면 해설이 빈 것으로 보아 제안 전체를 버린다(11-06, #286). 프롬프트는 비중이 있는 유형마다 세 문장 이상으로 근거를 쓰고, 미래 등락을 예측하지 않고 지난 자료와 조건·위험으로 설명하도록 안내한다(11-06, #309. 11-10 #398에서 숫자 없는 전망을 허용하도록 바꿈, 아래 v9). 문장 수와 예측 여부는 서버가 검사하지 않는다. 월 납입 가능액을 받으면 프롬프트(`goal-scenario-v8`, 11-10 #399)는 그 돈으로 해 볼 수 있는 조합을 함께 생각해 비중을 정하되 위험을 밝히고, 어느 시나리오가 가능액 안에 든다거나 넘는다고 단정하지 않도록 안내한다(비교와 대안 문장은 서버가 7-5로 붙인다). 프롬프트 `goal-scenario-v9`(11-10 #398, 사용자 결정)는 `roles`를 비중이 있는 유형마다 **다섯 문장 안팎**으로 쓰게 하고, 유형마다 ① 넣은 이유(이 목표·기한·조합에서 맡는 역할) ② 근거(비중, 입력에 있는 금리·통계, 상품 특성, 함께 볼 상품과의 비교. 투자 유형은 비중과 월 평균·월 변동폭을 함께) ③ **전망**(업황·기업 실적·금리 흐름에 비춘 앞으로의 전망 한두 문장, 바로 다음 문장에 전망이 어긋날 때의 위험)을 담게 한다. 유형별로 담을 내용은 적금(목표 금액의 바닥, 정해진 금리·만기·세금, 금리 흐름, 중도 해지, 만기가 기한보다 짧으면 남은 달의 CMA 이어 가기), CMA(수시 입출금, 예시 금리, 기준금리 흐름), 국내 지수 ETF(국내 대표 기업 분산, 반도체·수출 대형주 비중, 업황·재평가 전망), 미국 지수 ETF(세계 대형 기업 분산, 대형 기술주 비중, 세금, 환율), 코스피 대형주(다섯 종목 집중, 대표 기업 실적)다. 투자 유형의 위험 문장 하나는 "지난 60개월 최대 하락 같은 구간이 기한 말 근처에 오면 기한 말 금액이 넣은 돈보다 적을 수 있다"처럼 기한 말과 잇는다. `fit`은 기한이 1년 이하면 회복을 기다릴 시간이 짧다는 점을, 2~3년이면 기한이 다가올 때 투자 몫을 적금·CMA로 옮기는 시점을 쓴다. 필요 월 금액·목표에 닿는 비율·기한 말 금액·예상 수익률은 결과 문장(7-5)이 보여 주므로 쓰지 말라고 예시와 함께 안내한다. 가입·매수 권유는 지금처럼 금지한다.
- **v10(11-11 #402)**: v9의 유형별 내용을 부탁이 아니라 응답 형식으로 받는다. AI는 `roles` 문자열 대신 `typeRoles`(유형 다섯 개마다 `reason` 넣은 이유·`basis` 근거·`outlook` 전망, 모두 필수, 비중 0인 유형은 빈 문자열)를 낸다. 칸별 분량은 넣은 이유 1~2문장(유형 이름으로 시작), 근거 2문장, 전망 2문장(전망 1 + 위험 1)이고, 다섯 유형의 모범 예시를 프롬프트에 넣는다(숫자 자리는 〈비중〉·〈월 평균〉처럼 표시). 서버는 비중이 있는 유형만 적금 → CMA → 국내 → 미국 → 코스피 순서로 유형마다 한 줄로 합쳐 `explanationParts.roles`를 만든다. 빈 칸은 빼고, 세 칸이 다 빈 유형은 줄을 빼며, 칸 끝에 마침표가 없으면 붙인다(다음 칸과 한 문장으로 묶여 함께 지워지지 않게). 모든 유형이 비면 `roles`가 비어 제안 전체를 버린다. `typeRoles`가 없는 응답은 `roles` 문자열을 그대로 쓴다. 응답 계약과 문장 검사는 그대로다.
- **v11(11-11 #406)**: 기한 최대 5년에 맞춰 `fit`에 4~5년 안내만 더한다(기간이 길어 떨어진 뒤 회복을 기다릴 여유가 더 있지만 마지막 1~2년에는 투자 몫을 적금·CMA로 옮기는 시점을 생각해 보라, 적금 만기가 기한보다 짧아 남은 기간을 CMA로 이어 가는 몫이 커진다). v10의 유형별 칸·분량·모범 예시·전망 규칙은 그대로다.
- 전망의 근거는 **AI의 학습 지식**뿐이다(서버는 뉴스·업황 자료를 보내지 않는다). 전망 문장에는 숫자를 쓰지 않게 하고, 숫자 검사는 그대로라 숫자를 붙인 전망("연 10% 수익이 기대돼요")이나 통계 수치와 같은 문장의 "기대"·"예상"·"전망"은 지운다. 숫자 없는 전망 문장, 문장 수, 위험 문장이 뒤따르는지는 서버가 검사하지 않는다.
- 화면은 AI 조합(`proposer=AI`, 저장본 포함)의 해설 카드에 고지 "전망은 AI가 학습한 일반적인 내용이에요. 최신 뉴스나 실적을 확인한 것이 아니고 수익을 보장하지 않아요."를 해설 카드 맨 아래(계산 결과 아래)에 보여 준다. 데모 조합에는 전망이 없어 붙이지 않는다. 해설 칸 안의 줄바꿈마다 문단을 띄워 보여 준다. 프롬프트는 `roles`를 유형마다 한 문단으로, 유형 이름("적금은"·"CMA는"·"국내 지수 ETF는"·"미국 지수 ETF는"·"코스피 대형주는")으로 시작하게 하고, 화면은 문단 첫머리가 그 시나리오에 비중이 있는 유형의 이름 바로 뒤 "은/는"이면 유형 소제목(화면의 유형 이름)을 붙인다(11-11 #402). "적금·CMA는"처럼 여러 유형을 묶어 시작하는 문단과 이름으로 시작하지 않는 문단은 소제목 없이 보여 주고, 데모 조합에는 소제목을 붙이지 않는다.

| 규칙 | 내용 |
|---|---|
| 받는 사람 | **로그인한 회원만**(요청에 토큰). 비회원은 데모 조합(`fallbackReason=GUEST`) |
| 보내는 것 | 목표 금액·기한(개월), 월 납입 가능액(입력한 경우, 11-10 #399. 없으면 `null`), 유형 5개의 설명(고른 상품 이름, 적금 만기 개월과 만기 뒤 남은 달을 CMA로 계산한다는 것 포함), 적금·CMA 금리, 투자 유형의 지난 60개월 월 수익률 평균·표준편차·최대 하락(코스피 5종목은 같은 비중 평균), 함께 볼 상품의 이름·금융회사·금리와 같은 통계. **목표 이름·이메일·회원 번호는 보내지 않는다** |

AI를 부르기 전에 예약한다. 호출 실패·규칙 위반으로 AI 조합을 못 받으면 **회원 몫은 되돌리고** 전체 횟수는 그대로 둔다(비용 상한). 전체 상한에 걸려도 회원 몫은 되돌린다. 동시에 들어온 같은 조건 요청은 각각 부를 수 있다 |
| 재사용 | **같은 회원**이 같은 목표 금액·기한·월 납입 가능액(없음끼리 같음, 11-10 #399)·자료 기준일로, **지금과 같은 프롬프트 버전**으로 만든 조합(11-11 #406)이 있을 때 다시 보면 검증을 통과한 이전 AI 조합을 다시 쓰고 횟수를 차감하지 않는다(해설은 네 칸을 따로 저장한다. 11-10 배포 전에 저장된 조합은 합친 문단만 있어 `explanationParts=null`이다. `aiReused=true`. 화면은 남은 횟수 옆 물음표에 "같은 조건으로 만든 AI 조합은 횟수가 차감되지 않아요." 안내). 다른 회원과 공유하지 않는다. 날짜에서 7일 뒤 삭제, 탈퇴하면 즉시 삭제. 프롬프트 버전이 다르면(버전을 저장하기 전에 만든 조합 포함) 재사용하지 않고 AI를 새로 불러 회원 횟수를 차감하고, 새 조합으로 같은 조건의 행을 덮어쓴다(11-11 #406) |

| 응답 | 회원이면 `aiUsage`(하루 횟수·남은 횟수), 비회원이면 `null`. `aiReused`(재사용 여부) |
| 보관 | 회원·날짜별 횟수와 재사용 조합은 날짜에서 7일 뒤 삭제(탈퇴하면 즉시). 서비스 전체 횟수는 회원 정보 없이 남긴다 |

**검증**: 제안 하나는 시나리오 3개이고, 시나리오마다 제목·한 줄 설명·해설과 유형별 비중을 가진다. 아래 중 하나라도 어기면 **제안 전체**를 버리고 데모 조합을 쓴다(`proposer=DEMO`, `fallbackReason`). 단 해설의 숫자·보장 표현 규칙은 **걸린 문장만 지우고** 나머지를 쓴다. 다 지워져 비면 제안 전체를 버린다(11-06, #286). 지우기는 네 칸마다 따로 하고, 한 칸이 다 지워지면 그 칸은 빈 문자열(화면에서 그 소제목을 숨김), **네 칸이 모두 비면** 제안 전체를 버린다(11-10, #391). 로그 위치는 칸을 나누지 않고 `#2.explanation`으로 쓴다. 제목·설명은 지금처럼 한 번 걸리면 제안 전체를 버린다.

- 시나리오 수 정확히 3개(11-06, #309)
- 유형은 7-2의 다섯 개만, 같은 유형 중복 없음
- 비중은 0~100 정수, 합 100, 0보다 큰 유형이 1개 이상
- 제목 1~20자, 설명 1~40자. 해설은 비어 있으면 안 되고 글자 수는 검사하지 않는다(11-05, #278). 해설을 포함한 응답 전체는 토큰 상한 6000(`TRUNCATED`)과 호출 제한 시간 90초(`TIMEOUT`)를 넘으면 `AI_FAILED`다
- **숫자는 서버가 확인할 수 있는 것만**(11-04, #243): AI에게 보낸 상품(함께 볼 상품 포함)·대표 지수 이름 속 숫자(예: S&P 500, 코스피 200), 기한 안의 기간(년·개월·달), AI에게 보낸 목표 금액·월 납입 가능액(표기는 "1,500만 원"·"1500만원"·"15,000,000원" 모두 같은 값, 가능액은 11-10 #399)·적금(함께 볼 상품 포함)·CMA 금리·세율 15.4%와 같은 숫자, AI에게 보낸 유형별·함께 볼 상품의 통계(월 평균·변동폭·최대 하락)를 소수 첫째·둘째 자리나 정수로 반올림한 값과 같은 %(부호 무시. 같은 문장에서 숫자 앞의 가장 가까운 "평균"·"변동"·"하락"(앞에 없으면 뒤의 가장 가까운 단어, 11-11 PR #401 리뷰)의 값이어야 하고, 그 문장에 "기대"·"예상"·"전망"·"노려"·"노리"·"목표 수익"이 없어야 한다. 정수는 11-10 #398부터 허용하며, "평균"·"변동"·"하락"이 숫자 바로 앞 8글자(띄어쓰기 뺌) 안에 있고 숫자 바로 앞이 "연"이 아닐 때만이다. 예: "최대 하락 23%")와 그 자료 기간("지난·최근·과거 60개월"·"5년", 11-05 #278), 그 시나리오의 비중과 같은 %(11-10 #398부터 바로 앞이 "연"이거나 같은 문장에 "기대"·"예상"·"전망"·"노려"·"노리"·"목표 수익"이 있으면 지어낸 수익률로 보고 막는다. 예: CMA 10%일 때 "연 10% 수익이 기대돼요"), 그 시나리오의 비중을 두 개 이상 더한 %(숫자 바로 앞에 "나머지"·"합쳐"·"합해"·"합계"·"합친"·"더해"·"더한"·"모두"·"전체"가 있고, 문장 처음부터 숫자 바로 뒤까지 "수익"·"이익"·"확률"·"가능성"·"달성률"·"상승"·"성장"·"예상"·"기대"·"전망"이 없으며, 숫자 바로 앞이 "연"이 아닐 때, 11-06 #286. 11-10 #398부터는 합쳤다는 말 대신 이 시나리오의 유형 이름 두 개 이상을 숫자 바로 앞 20글자(띄어쓰기 뺌, 앞 숫자 뒤부터) 안에 나열하고 그 유형 비중의 합이 숫자와 같아도 된다. 유형 이름은 "적금"·"CMA"·"국내 (대표) 지수 ETF"·"국내 ETF"·"미국 (대표) 지수 ETF"·"미국 ETF"·"코스피 대형주"·"코스피 주식"·"코스피 상위"이고 "지수 ETF"·"국내·미국 지수 ETF"는 국내·미국 두 유형이다. 예: "적금·CMA 80%". 수익·확률·예상을 뜻하는 말과 "연"은 위와 같이 막는다), 다섯 이하의 종목·개·가지 수, 금융권 구분("1금융권"·"제1금융권"·"2금융권"·"제2금융권", 11-10 #398). 그 밖의 금액·%·배수·횟수(예상 수익률, 매달 넣을 돈, 확률 등)는 AI가 새로 만든 숫자로 보고 막는다. 유형 코드(`KOSPI_TOP5` 등)도 막는다
- **보장 표현은 단정만 막는다**: "무조건", 부정이 뒤따르지 않는 "보장"·"확실"(예: "원금 보장", "수익이 보장돼요", "확실히 올라요"). "보장되지 않아요"·"보장하지 않아요"·"보장할 수 없어요"·"보장이 없어요"·"불확실"·"확실하지 않아요"는 허용한다. 부정은 "보장"·"확실" 바로 뒤(띄어쓰기 무시)에 정해 둔 말이 올 때만 본다. 11-10 #398에 더한 말: "보장" 뒤 "받지 못"·"받지 않"·"받을 수 없"·"해 주지 않"·"할 수는 없"·"될 수는 없"·"된 게 아니"·"된 것이 아니"·"되는 것이 아니"·"되지도 않"·"하지도 않"·"은 되지 않"·"도 없"·"되는 상품이 아니"·"형 상품이 아니", "확실" 뒤 "하다고 할 수 없"·"하다고 볼 수 없"·"하지도 않"(예: "수익을 보장받지 못해요", "원금 보장형 상품이 아니에요"). 문장 아무 곳의 부정을 찾지 않는다("원금이 보장돼서 손해가 없어요"는 막는다)
- **월 납입 가능액 충족을 단정하지 않는다**(#400 리뷰): 한 문장 안에 가능액을 가리키는 말("가능액" 또는 AI에게 보낸 가능액과 같은 금액)과 충족을 단정하는 말(띄어쓰기 무시 "충분"·"넉넉"·"여유"·"감당"·"안에 들"·"안에서"·"안으로"·"넘지 않"·"맞출 수 있")이 함께 있으면 막는다(`TEXT_BUDGET`, 해설은 그 문장만 지운다). 필요 월 금액은 제안을 받은 뒤 서버가 계산해 AI는 알 수 없고, 가능액 밖이면 서버 대안 문장(7-5)과 어긋나기 때문이다. "매달 50만 원으로 해 볼 수 있어요"처럼 참고만 하는 문장은 허용한다
- 걸리면 어긴 규칙·몇 번째 시나리오·칸만 서버 로그에 남긴다(예: `TEXT_NUMBER #2.explanation`). 원인을 찾을 때만 `GOAL_SCENARIO_AI_LOG_REJECTED=true`(기본 꺼짐)로 **걸린 칸의 문구**도 남긴다(최대 2000자, 목표 금액·기한이 들어 있을 수 있음). 해설에서 문장만 지운 경우도 같은 규칙으로 규칙·위치를 남기고, 옵션을 켠 동안에는 **지운 문장**도 남긴다. 다른 칸의 문구, 통과한 문장, 목표 이름·이메일·회원 번호는 어느 경우에도 남기지 않는다
- 호출 실패(`AI_FAILED`)는 원인 분류만 서버 로그에 남긴다(`TIMEOUT`·`NETWORK`·`HTTP_상태코드`·`TRUNCATED`·`REFUSED`·`BAD_RESPONSE`·`NO_KEY`). 응답 본문·API 키는 남기지 않는다
- 호출이 성공하면 숫자만 한 줄 남긴다(11-10 #398): `goal scenario AI call: version=goal-scenario-v11 promptTokens=… completionTokens=… elapsedMs=…`. 성공한 호출 수를 세어 문장 지움 비율을 보려는 것이다. 목표 금액·기한·월 납입 가능액·회원 정보·응답 문구는 남기지 않는다. 재사용(차감 없음)은 부르지 않으므로 남지 않는다

## 8. 가상 시뮬레이션(`/virtual-sim/*`)

`/simulation`의 가상 시뮬레이션 탭 규칙이다. 결정·AI 생성·자동 검사·표시는 [결정 기록](decisions/2026-11-04-virtual-simulation.md)을 따른다. 테스트 입력 정본은 `tests/policy/virtual-simulation.json`이고, 이를 실행하는 것은 `VirtualSimPolicyTest`다. 가상 종목·사건 글은 AI가, 숫자는 모두 서버가 정한다. 등락·갭·꼬리는 **bp 정수**(1bp = 0.01%)이고 나눗셈은 내림(음수는 더 작은 쪽)이다.

- **평가는 §5를 그대로 쓴다.** 투자금 10,000~100,000,000원, 첫 봉 시가 50% 최초 매수, 다음 봉 시가 정수 주 체결, 종가 평가, 수익률 소수 4자리 내림. 테스트는 `practice.json`의 `tradeSequence`·`insufficientCash`·`negativeRounding`을 다시 읽는다. **사건의 매매는 비율 대신 수량을 직접 입력한다(8-7, 11-04 사용자 결정).**
- **예상 버튼은 없다. 매매 방향이 예상이다**: 매수 = 오른다(`POSITIVE`), 매도 = 내린다(`NEGATIVE`), 유지 = 예상 없음. 채점 없음.
- **일반 세션은 채점하지 않는다(8-6, 11-05 사용자 결정).** 판정 뒤 `movement`와 유형 통계만 준다.
- **구간·문제 수**: 길이 120~250거래일, 문제 3~5개(가상 종목의 공개 가능한 사건 유형이 적으면 그 수까지, 3개 미만이면 후보 아님). 유형은 공개 가능한 유형 전체에서 서로 다른 유형을 균등하게 뽑아 위치에 섞어 놓는다(11-05). 경향 있는 유형 수는 후보 조건이 아니다(11-10, [룰셋 측정 기준 결정](decisions/2026-11-10-vsim-ruleset-reaction-window.md) 4. 대회 판은 8-8 판별 규칙으로 따로 거른다).
- **시드**: 같은 시드·룰셋·가상 종목·시작 날짜면 같은 구간·사건 위치·OHLC다. 시드는 응답에 넣지 않는다.
- **레버리지 판은 8-9를 따른다**(11-11 사용자 결정, #419): 일반 판만, 회원만 2·3배. 기초 종목 봉을 배율 가격으로 바꿔 매매·평가하고, 판정 뒤 정보는 기초 종목 기준에 레버리지 기준 등락을 더한다.
- **대회 판은 8-8을 따른다**(11-05 사용자 결정): 회원만, 배치고사로 시작 판을 정하고 같은 판 안에서 잔액을 이어 가며, 하루 목표 달성 점수를 주마다 더해 승급·강등하고, 사건 4개 고정·판별 변동성 등급과 유형 고르기·대회 판 채점 없음. 위 구간·문제 수 규칙 중 문제 수와 유형 균등 출제는 일반 유형에만 적용된다.

### 8-3. 룰셋(worker, 실데이터)

- 하루 등락 `r = floor((오늘 종가 − 전날 종가) × 10000 / 전날 종가)`. 예: 10,000 → 10,250은 250, 10,000 → 9,820은 −180, 3 → 2는 −3,334, 7,777 → 7,800은 29, 같으면 0.
- 사건 유형 분류(`vsim-types-v4`)는 DART 공시 제목에서 공백·가운뎃점을 지우고 결정 기록 표의 순서대로 처음 맞는 낱말을 쓴다. 줄바꿈 없는 공백(U+00A0)도 공백으로 보고 지운다. `해지`·`철회`·`취소`가 있으면 분류하지 않는다. `증권발행실적보고서`(증권 발행 결과 서류)·`실적공시예고`(실적 발표 일정 안내)도 "실적"이 들어 있지만 분류하지 않는다(v3, 11-09 #349). `영업실적등에대한전망`(회사가 내놓은 실적 계획)·`실적발표일정`(일정 안내)·`소액공모실적보고서`(공모 결과 서류)도 분류하지 않는다(v4, 11-10 #375). 자기주식은 `자기주식취득`·`자기주식처분`으로 나누고, 시설·지분 투자는 `처분`이 있으면 분류하지 않는다. 화면 제목은 유형마다 서버가 정한 실제 공시 제목 형식이다.
- 표본: 급변동 사건과 상관없이 수집 대상 종목의 최근 5년 DART 공시 전체(`dart_disclosures`, 5년을 다 받은 종목만). 급변동 사건에 붙은 공시(`event_sources`)는 공시 뒤 5거래일이 사건 자체의 움직임이라 쓰지 않는다(결정 기록 "배경").
- 유형별 경로(`vsim-rules-v3`, 11-10 [룰셋 측정 기준 결정](decisions/2026-11-10-vsim-ruleset-reaction-window.md)): 분류된 공시(접수번호 중복 제거, **정정 공시 제외**)마다 접수일 당일 봉(휴일이면 직전 거래일)을 기준 봉으로, **기준 봉 당일(전날 종가 → 기준 봉 종가)과 1~5번째 후속 거래일**의 `r` 6개. 기준 봉 전날 봉이 없거나 후속 5거래일이 없으면 뺀다. 정정 공시는 제목 앞 대괄호 표시에 "정정"이 있는 공시다(8-8 "정정 공시"와 같은 판정). 유형마다 500개까지(넘으면 `floor(j × n / 500)`번째), 30개 미만인 유형은 쓰지 않고, 쓸 수 있는 유형이 3개 미만이면 룰셋을 만들지 않는다.
- 거래량 배수(룰셋 요약에 기록만, 가격 생성에는 쓰지 않음): 유형마다 "후속 5거래일 평균 거래량 ÷ 기준일 전 20거래일 평균 거래량"의 중앙값(소수 1자리 내림). 기준일 전 봉이 20개 미만이거나, 그 거래량 합이 0이거나, 그 20거래일·후속 5거래일 중 거래량이 비어 있으면 그 공시는 중앙값에서만 빼고 경로에는 남긴다. 남는 값이 없으면 `null`이다.
- 유형별 상승 비율(판정 뒤 결과 화면에 보임): 500개로 추리기 전 전체 경로 `n`개 중 **공시 직후**(`floor`로 이은 종가가 아니라 실제 기준 봉 전날 종가 → 다음 거래일 종가, 배치고사 반응 창과 같은 구간)가 오른 수 `m`으로 `floor(m × 10000 / n) / 10000`. 예: `n` 340, `m` 227이면 0.6676. 중앙값·25·75% 분위도 같은 구간의 bp다.
- 변동성 등급: 종목별 `floor(Σ|r| / 개수)` 오름차순(같으면 종목코드 순) `i`번째 → `floor(i × 3 / 종목 수)`.
- 분위표(등급마다 `r`·`g`·`u`·`d`): 정렬한 값 `v`(개수 `n`)에서 `q_i = v[floor(i × (n − 1) / 1000)]`, `i = 0..1000`. 생성기는 `i`를 균등하게 뽑는다. `r`은 분류된 공시(정정 제외)의 기준 봉과 후속 5거래일을 뺀 `daily_prices`, `g`·`u`·`d`는 `practice_datasets` 유효 OHLC 봉에서 전날 종가 대비로 잰다.

### 8-4. 봉 만들기

전날 종가 `P`(첫 봉은 시작가 `P_0`, 5,000~200,000원 100원 단위)와 뽑은 `r`·`g`·`u`(≥0)·`d`(≥0)로:

- `상한 = floor(P × 13000 / 10000)`, `하한 = max(1, ceil(P × 7000 / 10000))`
- `종가 = clamp(floor(P × (10000 + r) / 10000), 하한, 상한)`, `시가 = clamp(floor(P × (10000 + g) / 10000), 하한, 상한)`
- `고가 = clamp(max(시가, 종가) + floor(P × u / 10000), max(시가, 종가), 상한)`, `저가 = clamp(min(시가, 종가) − floor(P × d / 10000), 하한, min(시가, 종가))`
- 사건 봉과 그 뒤 1~5번째 봉의 `r`은 그 유형에서 뽑은 경로의 값 6개(`vsim-gen-v3`. 경로가 5개인 v2 룰셋으로 시작한 대회 판을 정산할 때는 사건 뒤 1~5번째 봉만), 그 밖의 `r`과 모든 `g`·`u`·`d`는 등급 분위표에서 뽑는다. 모든 봉은 `1 ≤ 저가 ≤ min(시가, 종가) ≤ max(시가, 종가) ≤ 고가`.

### 8-6. 경향과 판정 뒤 정보

- 판정 뒤에는 유형의 상승 비율과 하락 비율 `floor(내린 수 × 10000 / n) / 10000`(둘 다 공시 직후 구간, 8-3)을 함께 준다. 보합 경로는 어디에도 들지 않으므로 하락 비율은 `1 − 상승 비율`과 다를 수 있다. 경향(시장 조정 측정)과 비율(원 가격)은 기준이 달라 어긋날 수 있으므로, 화면 문장에는 반대 비율을 쓰지 않고 원 가격 비율로 "반대"를 말하지 않는다(11-10). 일반 세션 판정 뒤 경향과 다르게 움직이면 `UP`은 "시장 움직임을 뺀 수익률이 공시 직후에 공시 없는 날보다 평균 조금 높았던 유형이지만, 이번에는 내렸어요.", `DOWN`은 "시장 움직임을 뺀 수익률이 공시 직후에 공시 없는 날보다 평균 조금 낮았던 유형이지만, 이번에는 올랐어요."를 쓴다. `categoryDownShare` 칸과 계산은 그대로다.
- **경향은 고정 목록이다(`vsim-rules-v3`, 11-10 [룰셋 측정 기준 결정](decisions/2026-11-10-vsim-ruleset-reaction-window.md) 1)**: 공시 반응 측정 v2의 반응 창 "근거 있음"(시장 조정, BH q<0.10, 앞·뒤 기간 재현) 유형인 공급 계약·자기주식 취득·시설·지분 투자는 `UP`, 나머지는 `MIXED`다. 배치고사 근거 유형과 같은 목록이다. 상승 비율·경로 수로 정하지 않으므로, 시장 조정 측정과 원 가격 비율의 차이 때문에 `UP`이어도 상승 비율이 0.5 아래일 수 있다. 이전(v2) 기준 "`n ≥ 100`이고 비율 ≥ 0.55면 `UP`, ≤ 0.45면 `DOWN`"은 없앴다.
- 경향은 대회 판 출제(8-8 판별 유형 고르기)와 판정 뒤 통계 표시(배치고사 결과의 유형 통계 포함)에 쓴다. 배치고사 출제·채점에는 쓰지 않는다(11-09 [반응 창 결정](decisions/2026-11-09-placement-reaction-window.md)). 배치고사 결과에는 채점 구간과 같은 구간의 유형 통계만 싣는다: 반응 창 채점은 v3 룰셋의 공시 직후 통계, 5거래일 채점은 5거래일 통계. 11-10 전 룰셋으로 출제한 반응 창 문제는 경향·비율·수를 `null`로 준다.
- `trendOutcome`·`outcome`: 일반·대회 모두 늘 `null`이다(11-05, 결정 기록 "변경 기록 11-05"). 점수가 없다.
- 실제 방향은 `movement`(`UP`·`DOWN`·`FLAT`)로 준다. 11-10부터 **공시 직후**(사건 봉 전날 종가 → 다음 봉 종가) 원 가격 비교다. 두 숫자 `reactionReturnRate = (다음 봉 종가 − 사건 봉 전날 종가) / 사건 봉 전날 종가`(공시 직후), `nextWeekReturnRate = (다섯 번째 후속 봉 종가 − 다음 봉 종가) / 다음 봉 종가`(그다음 주)를 함께 주고 소수 4자리 내림(음수는 더 작은 쪽)이다. `subsequentReturnRate`(사건 봉 종가 → 다섯 번째 후속 봉 종가)는 호환을 위해 남고 화면은 쓰지 않는다. 그다음 주는 다음 봉 종가 체결을 가정한 비교라 다음 봉 시가에 체결된 매매의 수익률과 다를 수 있다고 결과 화면에 밝힌다.
- `movement`·세 등락·유형 통계는 다섯 번째 후속 거래일 봉을 공개할 때 정하고, 그 전에는 `null`이다.

**공시 주요 내용**(배치고사 문제, Issue #289 사용자 결정): OpenDART 주요사항보고서 주요정보(DS005)가 있는 유형만, 서버(worker)가 DS005 한 행에서 항목을 최대 4개 만든다. 절대 금액·주식 수·가격 대신 비율과 규모 구간만, 회사·상대방·주관사 이름과 날짜 칸은 읽지 않는다. 글 칸은 정해 둔 낱말이 있을 때 정해 둔 이름(예: "주주배정 후 일반공모", "장내 매수", "관계 없음")으로만 내고 원문은 내지 않는다. 항목이 하나도 없으면 `details = null`이고 유형 설명만 보인다. 방향·과거 경향·상승 비율은 넣지 않는다(결과에서만). 정정된 공시: DS005는 마지막 정정본의 접수번호로만 돌려주므로, 응답에 없는 공시는 같은 종목·같은 API에서 제목이 같은(앞의 `[기재정정]` 같은 표시 제외) 나중 정정본 중 180일 안의 것을 접수번호 순으로 보고 응답에 있는 첫 행(정정된 값)을 쓴다. 사이에 정정 표시 없는 같은 제목 공시가 있으면 다른 공시로 보고 멈춘다. 이미 받은 원 공시도 정정 공시를 받을 때 같은 응답으로 다시 평가한다(응답에 원본이 있으면 원본 값). **공급 계약**(단일판매·공급계약체결, 자율공시 포함, 종속회사·자회사의 주요경영사항 제외)은 DS005가 없어 worker가 **원공시의** 공시서류원본파일 본문 글에서 매출액 대비(%)와 계약 기간 길이 두 칸만 뽑는다(아래 표, Issue #375). 원문은 저장하지 않고 계약 금액·상대방·날짜는 내지 않는다. 규칙 버전 `vsim-details-v3`(v2 행은 DS005 항목이 같아 다시 받기 전까지 그대로 쓴다). **화면 줄글**(문제·결과 화면, AI 요약이 없을 때, Issue #387): 항목마다 값을 말하는 문장 뒤에 그 숫자·이름의 뜻을 푸는 읽는 법 한 문장을 붙이고(예: 매출액 대비 → "이 숫자는 계약 하나가 회사의 1년 매출에 견줘 얼마나 큰지를 보여 줘요.", 같은 문장은 한 번만), 끝에 회사를 가린 방식 안내를 붙인다. 안내는 유형·항목에 맞춘다: 공급 계약은 계약 금액·상대방·날짜를 빼고 매출액 대비 %와 기간 길이만 보인다고 쓰고, 다른 유형은 규모 항목이 있으면 "금액은 규모 구간", 주식 수 항목(새 주식 수·늘어날 주식·교환 대상 주식)이 있으면 "주식 수는 기존 대비 %"만 말한다. 공시 주요 내용이 없는 문제(AI 요약만 있거나 아무것도 없을 때)는 공시 줄글 상자 밖에 **"읽는 법" 줄로 유형별 한 문장**(「공시 읽는 법」 유형별 확인할 것에서 가져옴, 예: 배당 → 시가배당률과 배당 종류)을 보인다(결과 화면도 같다). 줄글 안에 붙이면 예시·AI 요약 출처 안내 뒤에 와 그 글의 일부로 읽히기 때문이다. 읽는 법 문장도 방향·경향·평가·권유를 말하지 않고, 문제 화면 문구는 「공시 읽는 법」과 같은 금지 표현(`PlacementGuideTextTest` GUIDE_BANNED)으로 검사한다.

### 8-9. 레버리지 판(일반 판, 회원만)

일반 판을 시작할 때 배율 1(기본)·2·3 중 하나를 고른다(11-11 사용자 결정, [결정 기록](decisions/2026-11-11-vsim-leverage.md), #419). **레버리지 ETF 방식**이라 돈을 빌리지 않는다: §5 "추가 입금·차입·공매도 없음"은 그대로이고 차입·이자·반대매매가 없다. 기초 종목(8-4로 만든 가상 종목 가격)의 하루 등락률에 배율을 곱해 매일 다시 맞춘 가격으로 매매할 뿐이다. 운용보수·괴리·세금은 넣지 않는다. 테스트 입력은 `virtual-simulation.json`의 `leverage`다.

- **누가**: 1배는 로그인 없이, 2·3배는 회원만(비회원 `401`). 배율은 판 중간에 바꿀 수 없고, 인버스는 없다. 요청에서 생략하면 1이다.
- **대회 판에는 없다**: 대회 판 시작에 1이 아닌 배율이 오면 `400`이다.
- **가격**: 기초 종목 전날 종가 `C`, 레버리지 가격 전날 종가 `L`, 그날 기초 종목의 시가·고가·저가·종가 `X` 각각에 `X_L = max(1, floor(L × (C + k × (X − C)) / C))`. 첫 봉의 `C`·`L`은 시작가 `P_0`. 하루 상하한이 ±30%(8-4)라 3배여도 하루 최대 −90%이고 `C + k × (X − C) > 0`이다. 식이 `X`에 대해 단조라 `1 ≤ 저가 ≤ min(시가, 종가) ≤ max(시가, 종가) ≤ 고가`가 유지된다. 1배는 기초 봉과 완전히 같다.
- **매매·평가**: §5 평가, 8-7 수량 매매·주문 상한·부분 체결, 첫 봉 시가 50% 최초 매수를 레버리지 가격에 그대로 쓴다. 차트·체결 가격·자산도 레버리지 가격이다.
- **판정 뒤 정보**: `movement`, 공시 직후·그다음 주 등락, 유형 통계는 기초 종목 기준 그대로다(유형 통계가 기초 움직임에서 왔다). 2·3배 판은 같은 두 구간의 레버리지 가격 등락(소수 4자리 내림)을 함께 준다.
- **결과 비교**: 2·3배 판이 끝나면 같은 구간(첫 봉 시가 → 마지막 봉 종가)의 기초 종목 수익률과 레버리지 가격 수익률(소수 4자리 내림)을 나란히 준다. 사용자의 손익·수익률은 §5 그대로 서버 값이다.
- **고지**: 배율을 고를 때와 결과 화면에 위험 고지(결정 기록 9)를, 차트·결과에 "레버리지 N배 · 가상" 배지를 보인다. 실제 상품의 수익을 보여 주거나 투자를 권하지 않는다.
- **저장**: 일반 판처럼 세션 메모리에만 두고 세션이 끝나면 지운다.

| 배율 | 기초 종목 종가 | 레버리지 가격 종가 | 구간 수익률(기초 → 레버리지) |

## 9. 청년미래적금 만기 계산(`policysavings.YouthFutureCalculator`, **구현됨 · 가정 2건 확인 전**)

`GET /savings/policy/{code}`·`POST /savings/policy/{code}/simulate`의 계산이다([계약](contracts/web-api.yaml), 계획 [#113](https://github.com/shinds-team7/flexable-web/issues/113), 결정 [11-06](decisions/2026-11-06-youth-future-savings-rules.md)). 근거는 신한은행 공식 상품설명서(준법감시인 사전심사필 제2026-12748-1호, 2026-06-22 기준) p.4~10이고, **특정 은행 한 곳의 설명서라 모든 은행에 일반화하지 않는다**. 은행마다 달라질 수 있는 값(기본·우대금리, 기여금 이자 여부)은 입력으로 받는다. 리드가 2026-11-07에 이 절의 규칙과 가정 2건(일수 ÷365, 기여금 입금일 = 납입한 달 말일)을 그대로 승인해 구현했고, 상태는 `UNVERIFIED`다(공식 확인 전이라 `VERIFIED`로 바꾸지 않는다).

원문에서 확인한 것(신한 기준): 기본금리 연 5.0%, 우대 최대 연 3.0%(만기 전 중도해지는 우대 없음), 최고 연 8.0%(p.4~6). 이자는 만기일시지급이고 입금건별로 입금일부터 해지일 전날까지의 예치일수로 계산한다(p.6~7). 연 납입 한도 600만 원, 곧 매월 50만 원(p.8). 정부기여금은 가입 시 확정되는 유형에 따라 일반형 6%·우대형 12%이고, **정부기여금에도 기본금리를 적용하며** 그 이자는 해당 월 기여금을 진흥원이 은행에 입금한 날부터 만기일 전날까지 계산한다(p.4·9~10). 이자소득은 비과세이고(p.9), 만기 이후 해지한 가입자에게 기여금을 지급한다(p.9).

## 10. 파킹·CMA 분류 태그(`cashcatalog.CashTags`, `GET /parking/products`·`/cma/products`의 `tags`)

상품 유형·우대조건 필터(이슈 [#297](https://github.com/shinds-team7/flexable-web/issues/297))를 위해 서버가 상품마다 `tags`를 붙인다(결정 [11-07](decisions/2026-11-07-cash-tags.md), 리드 승인). 파킹·CMA 목록의 출처(은행 공식 페이지·저축은행중앙회 표 등)는 가입 방식·우대조건을 구조화해서 주지 않아 finlife `join_way`·`spcl_cnd` 같은 분류 값이 없다. 그래서 **상품명과 공시 조건 원문(`conditions`)에 아래 낱말이 있으면 태그를 붙인다.**

| 태그 | 화면 이름 | 낱말(띄어쓰기 무시) |
|---|---|---|
| `YOUTH` | 청년 | 청년, 사회초년생 |
| `MILITARY` | 군인 | 군인, 장병 |
| `NON_FACE_TO_FACE` | 비대면 가입 | 비대면, 방문없이 |
| `SALARY_LINK` | 급여 연동 | 급여, 월급 |
| `AUTO_TRANSFER` | 자동이체 | 자동이체 |
| `CARD_USE` | 카드 사용 | 카드 |

- 태그는 **원문에 낱말이 있다는 뜻**이다. 가입 자격이 되는지, 우대가 적용되는지, 금리가 오르는지는 판정하지 않는다(화면은 "원문에 ○○ 문구가 있는 상품"으로 말한다).
- 낱말 앞뒤 문맥(예: "청년이 아닌")은 보지 않아 틀린 태그가 붙을 수 있다. 정확한 조건은 원문 `conditions`로 확인한다.
- 태그 순서는 위 표의 순서이고, 낱말이 없으면 빈 배열이다. 저장하지 않고 조회 때마다 계산하므로 낱말 표를 바꾸면 바로 반영된다.
- **특판 태그는 두지 않는다**: 실제 목록(2026-11-07 파킹 217개·CMA 12개)에서 "특판"은 삼성증권 CMA 두 상품의 "특판·일반약정식 발행어음과 구분해요" 설명에만 나와 둘 다 오탐이고, 진짜 특판 상품은 없었다. 특판 상품이 목록에 들어오면 문구를 보고 낱말을 정해 더한다.
- 로고는 이 절과 무관하다(은행 로고 이미지는 쓰지 않고 글자 아이콘만 쓴다, 2026-11-08 결정).
- 예시는 [`tests/policy/cash-tags.json`](../tests/policy/cash-tags.json)이고 `CashTagsPolicyTest`가 낱말 표와 예시를 코드와 맞춘다. 규칙 버전은 `cash-tags-v1`이다.


## 11. 파킹통장 이자 계산(`cashcatalog.ParkingCalculator`·`ParkingTiers`, `POST /parking/simulate`, 규칙 `parking-calc-v2`)

리드 승인(11-07·08, [결정](decisions/2026-11-07-parking-calc-scope-proposal.md))의 1단계(기본금리, `BASE_RATE`)와 2단계(원문에 구간별 적용이 적힌 상품, `TIERED`)다. 예상 이자를 서버가 계산한다. 테스트 입력 정본은 [`tests/policy/parking-calc.json`](../tests/policy/parking-calc.json)이고 `ParkingPolicyTest`가 실행한다.

| 규칙 | 내용 |
|---|---|
| 금리 | `BASE_RATE`는 공시 **기본금리**(`baseRate`)만 쓴다. `TIERED`는 원문에서 읽은 구간별 금리를 쓴다(아래 "구간 모드"). 최고금리·우대·이벤트는 어느 모드에서도 넣지 않는다 |
| 이자 | 세전 이자 = floor(잔액 × 연이율(%) × 일수 ÷ 36500). 일 단위이고 윤년도 365로 계산한다. 복리·재투자·이자 지급 시점의 원가는 반영하지 않는다 |
| 세금 | floor(세전 이자 × 0.154). §6과 같다 |
| 입력 | 잔액 1~10,000,000,000원, 일수 1~3,650일(정수). 벗어나면 400 `VALIDATION_FAILED` + `fields` |
| 계산 대상 | 목록의 `calculable`이 true인 파킹통장. CMA는 항상 false(별도 제안) |
| 계산 불가 | `calculable=false`이고 `calcReason`에 이유. 이 상품에 simulate를 부르면 400(`fields.productId`에 이유). 없는 상품은 404 |

**계산 가능 판정**(공시 원문으로 판단하며 상품 목록 저장 방식은 바꾸지 않는다): 기본금리가 있고, 아래에 해당하지 않으면 계산 가능이다.

| 이유(`calcReason`) | 조건 |
|---|---|
| 공시에 기본금리가 없어 계산할 수 없어요 | `baseRate`가 null |
| 최고금리를 받는 금액에 제한이 있어 구간별 계산이 필요한 상품이에요 | 저축은행 공시 줄 "최고금리 적용 가능 금액(공시값):" 이 "제한없음"이 아님 |
| 금액 구간에 따라 금리가 달라져 지금은 계산하지 않아요 | 원문(고정 안내 문장 제외)에 **어디서든 막는** 문구 "N원 이하·초과·미만", "이하분·초과분", "차등", "금액별", "잔액별", "구간", "기간별", "거치기간", "기간에 따른"이 있거나, **우대·실적·수수료·가입 조건이 아닌 줄**에 "N원 이상", "평균잔액", "월평균", "N일·개월·년 이상"이 있음. "금액구간에따른제한없음"은 구간이 없다는 뜻이라 지우고 본다 |
| CMA 이자 계산은 아직 제공하지 않아요 | CMA 목록 |

- 낱말 판정이라 구간이 없는 상품을 잘못 막을 수 있다. **막는 쪽으로 틀리게** 정했다. 틀리게 계산해 보여 주는 것보다 계산하지 않는 쪽이 안전하다. 우대 실적("체크카드 전월 5만원 이상 사용")·수수료 면제("전월 평균잔액 100만원 이상") 같은 조건 줄은 금리 구간이 아니라서 "N원 이상"·평균잔액만으로는 막지 않는다(우대·실적·사용·이용·입금·결제·이체·수수료·면제·급여·연금·카드·충족·서비스·거래·가입·대출 중 하나가 같은 줄에 있을 때). 예치 기간에 따라 이율이 달라지는 문구("거치기간에 따른 이율", "3개월이상 0.80%")는 막는다.
- 2026-11-08 웹 서버 실제 목록 217개를 이 판정에 넣은 결과는 아래 "구간 모드" 끝의 숫자가 정본이다(결정 문서의 "약 54%"는 낱말·문형으로 센 근사치였다).
- **20% 규칙**: 계산 불가가 전체의 20% 이하면 목록에서 감춘다. 지금은 41%라 감추지 않고 계산 버튼 대신 이유를 보인다.
- **2단계(구간 모드)**: 아래 "구간 모드"에서 읽을 수 있는 상품은 위 판정보다 먼저 `TIERED`로 계산한다.

**구간 모드(`calcMode=TIERED`)**: 원문(고정 안내 문장 제외)의 줄이 아래 모양에 정확히 맞고 구간이 빈틈없이 이어질 때만 구간표로 읽는다. 하나라도 어긋나면 구간표가 아니다.

| 규칙 | 내용 |
|---|---|
| 줄 모양 | "N원 이하(분) [연] R%", "A원 초과 ~ B원 이하(분) [연] R%", "A원 초과(분) [연] R%"(`:`가 있어도 됨). 줄머리의 `-`·`①`·`1)`·`기타사항:`는 무시. 금액은 "1억원·5천만원·5백만 원·5,000만원·10억"처럼 읽는다 |
| 구조 | 끝이 있는 구간(이하)이 하나 이상, 마지막 "초과" 줄이 정확히 하나. 끝 금액은 위로 갈수록 커지고, "A원 초과"의 A는 바로 아래 구간의 끝과 같아야 한다. 적힌 순서와 상관없이 끝 금액으로 정렬 |
| 적용 방식의 근거 | 원문에 **"초과분"** 낱말이 있거나 **"예시 … 적용"** 문장이 있어야 한다. 둘 다 없으면 구간 금리를 전체 잔액에 붙이는지 알 수 없으므로 계산하지 않는다 |
| 계산 | 각 구간 안에 들어간 금액에만 그 구간 금리를 곱한다. 세전 이자 = floor(Σ(구간 안 금액 × 연이율) × 일수 ÷ 36500), 구간마다 내리지 않고 합친 뒤 한 번 내림. 세금은 같다 |
| 응답 | `calcMode=TIERED`, `tiers`(구간), simulate 응답의 `parts`(구간별로 들어간 금액, 합 = 잔액). 화면은 구간별 표를 함께 보인다 |
| 읽지 않는 것 | 우대금리(마케팅 동의·실적 등)는 구간표에 넣지 않는다. 구간표가 둘이거나 구간이 끊겨 있으면 구간표가 아니다 |

- 2026-11-08 웹 서버 실제 목록 217개 중 **구간 모드 17개**(저축은행 16개와 케이뱅크 플러스박스)가 새로 계산 가능해졌다. 판정을 다듬은 뒤(우대 실적 줄·평균잔액 면제 조건·"금액구간에따른제한없음"을 구간으로 오해하지 않게 하고, 예치 기간별 이율은 막음) 합계 **계산 가능 128개(59.0%)**(기본금리 111 + 구간 17), 계산 불가 89개(41.0%: 기본금리 없음 29, 최고금리를 받는 금액 제한 36, 금액 구간 문구 24)다. 여전히 20%를 넘어 목록에서 감추지 않는다.
- 일부 구간표는 원문 그대로의 금리가 직관과 다르다(예: OK짠테크통장Ⅱ는 5,000만 원 초과분이 그 아래 구간보다 높다). 원문대로 계산하고 화면에 구간별 금리와 들어간 금액을 보여 사용자가 확인할 수 있게 한다.
- 제주은행처럼 구간 금리를 전체 잔액에 붙이는지 원문에 없는 상품은 계속 계산하지 않는다(제주은행에 서면 확인을 요청하지 않기로 했으므로 계속 제외한다, 2026-11-08 결정).

| 입력(잔액 · 일수 · 기본금리) | 기대(세전 → 세금 → 세후) |
|---|---|
| 10,000,000원 · 31일 · 3.00% | 25,479 → 3,923 → 21,556 |
| 10,000,000원 · 365일 · 2.85% | 285,000 → 43,890 → 241,110 |
| 1,234,567원 · 30일 · 0.01% | 10 → 1 → 9 |
| 1원 · 1일 · 5% | 0 → 0 → 0 |
| 50,000,000원 · 90일 · 2.50% | 308,219 → 47,465 → 260,754 |
| 10,000,000,000원 · 3,650일 · 20% | 20,000,000,000 → 3,080,000,000 → 16,920,000,000 |

화면에는 `BASE_RATE`면 "공시 기본금리만 쓴 예상 세전 이자이고 우대·이벤트·금액 구간은 반영하지 않았어요", `TIERED`면 "원문의 구간별 금리를 구간 안의 금액에만 적용했고 우대·이벤트는 반영하지 않았어요"와 "금리가 바뀌면 달라져요, 세금은 15.4%"를 함께 보인다.


## 12. CMA 예상 이자 계산(`cashcatalog.CmaCalculator`, `POST /cma/simulate`, 규칙 `cma-calc-v1`)

리드 승인(11-08, [결정](decisions/2026-11-08-cma-calc-proposal.md))이다. RP형·발행어음형 CMA의 예상 이자를 서버가 계산한다. 테스트 입력 정본은 [`tests/policy/cma-calc.json`](../tests/policy/cma-calc.json)이고 `CmaPolicyTest`가 실행한다.

| 규칙 | 내용 |
|---|---|
| 수익률 | 공시 **약정수익률**. 상품에 하나만 정해져 있으면 `AGREED_RATE`, 원문에 보유 기간별 표가 있으면 `PERIOD_RATE`(입력한 일수가 속한 기간의 수익률) |
| 이자 | 세전 이자 = floor(잔액 × 약정수익률(%) × 일수 ÷ 36500). 일 단위이고 윤년도 365. **재투자(복리)는 반영하지 않는다**: 수익률이 그대로 유지된다고 가정한 예상이다 |
| 세금 | floor(세전 이자 × 0.154). §6·§11과 같다 |
| 입력 | 잔액 1~10,000,000,000원, 일수 1~3,650일. `PERIOD_RATE`는 마지막 구간(유진 자산관리형 180일)을 넘으면 400(`fields.days`): 그 뒤에는 재투자하는 날의 새 수익률이 적용되기 때문 |
| 가입 한도 | 상품별 한도(예: 유진 누적 20억 원)는 계산에서 다루지 않고 안내 문구로 둔다 |
| 화면 고지 | 항상 "원금 손실 가능성이 있고 예금자보호 여부는 상품마다 달라요, 수익률은 바뀔 수 있어요, 재투자 미반영, 세금 15.4%"를 보인다. 수익 보장·추천 표현을 쓰지 않는다 |

**계산 가능 판정**(공시 원문으로 판단, 저장 방식은 바꾸지 않는다):

| 결과 | 조건 |
|---|---|
| `PERIOD_RATE` | 원문에 "N일 ~ M일 : R%" 줄이 두 줄 이상이고 1일에서 시작해 빈틈없이 이어짐 |
| 계산 불가: 보유 기간에 따라 수익률이 달라져 지금은 계산하지 않아요 | 기간 구간 표시("N- M일")가 있지만 위 모양으로 읽을 수 없고, 기간별 수익률이 서로 다름. 모든 기간의 수익률이 같으면(신한 명품 CMA: 공개 응답에서 "1- 27일" 2.45%·"28일" 2.45%) 기간과 상관없이 하나로 보고 `AGREED_RATE`로 계산한다. "적용금액: 1 원이상"처럼 최소 가입 금액 줄은 금액 구간으로 보지 않는다 |
| 계산 불가: 공시된 약정수익률이 하나로 정해져 있지 않아 계산하지 않아요 | 기본금리가 없거나 기본금리와 최고금리가 다름(한화: 범위만 공시) |
| 계산 불가: 금액 구간에 따라 수익률이 달라져 지금은 계산하지 않아요 | §11 파킹 판정과 같은 금액 구간 문구(우리WON CMA Note: 구간 금리를 전체 잔액에 붙이는지 원문에 없음) |
| `AGREED_RATE` | 위에 해당하지 않음 |

- 2026-11-08 웹 서버 실제 목록 12개 중 `AGREED_RATE` 10개(KB 2, SK, 메리츠, 미래에셋, 삼성 2, 신한, 현대차, 유진 자유형), `PERIOD_RATE` 1개(유진 자산관리형), 계산 불가 1개(한화). 교보·우리투자·다올 반영 뒤 15개 중 계산 가능 13개(교보·다올 `AGREED_RATE`, 우리WON 계산 불가)로 86.7%이다. 계산 불가는 한화·우리WON 2개(13.3%)이고 리드 결정(11-08)에 따라 파킹의 20% 규칙을 적용하지 않고, "계산할 수 없어요"와 이유를 안내하며 목록에 그대로 둔다.
- 신한은 11-08 공개 응답에서 두 기간 수익률이 같음을 확인해 `AGREED_RATE`로 계산한다(기간별로 달라지면 다시 계산 불가가 된다).
