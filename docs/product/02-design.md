## 2. 디자인 원칙

1. **겁주지 않는다.** 하락은 경보가 아니라 지나간 사건이다. 손실 숫자 옆에는 항상 "그때 무슨 일이 있었고, 그 뒤 어떻게 됐는지"를 같이 보여준다. 빨간 경고 배너, 깜빡임, "지금 안 하면 손해" 같은 문구는 쓰지 않는다.
2. **숫자보다 이야기.** 결과 화면 맨 위는 차트가 아니라 한 문장이다. "3년 전부터 매달 남긴 돈을 넣었다면, 지금 가치는 계산 결과로 표시해요(예시). 넣은 돈보다 142,000원 많아요." 숫자는 그 문장을 받치는 근거로 내려간다.
3. **내 돈에서 출발한다.** 모든 시뮬레이션의 기본값은 앱에서 모은 돈(총액)과 모으는 속도(월평균)다. 처음에는 기록 기준 월평균을 쓴다. 직접 입력은 전체 수정 패널에서 바꾸고, 방식에 맞는 금액 하나만 보여준다.
4. **앱과 한 가족.** 블루(`#0046FF`)는 누를 수 있는 것(기본 버튼·선택·링크·포커스)에만 쓴다. 차트 선에는 쓰지 않는다. Navy(`#00236E`)는 한 줄로 그리는 내 돈 선(합계 자산선)과 진한 면이다. 범주색으로는 쓰지 않는다(§6-2). Navy 면 위에는 흰색(14.33:1) 또는 Light Blue(8.63:1) 글자만 쓴다. Royal(`#2878F5`)은 하락 기준색이며 작은 글자에는 쓰지 않는다. Sky·Light Blue는 진행 막대·안내 면·그림 전용, 글자는 Navy다. 같은 글꼴·반경·캐릭터를 유지한다. 팔레트 사용은 제휴 표시가 아니다. 로고·“신한” 명칭·인증 배지는 쓰지 않는다.
5. **솔직하게 표시한다.** 과거 데이터·추정·예시·AI 요약을 화면에서 숨기지 않는다. "입력한 기록 기준", "과거 시세로 계산한 가상 결과예요. 앞으로도 그렇다는 뜻은 아니에요", "투자 권유가 아니에요"는 작은 회색 글씨가 아니라 읽히는 크기(13px, 보조 잉크)로 둔다. 계좌 연결·실제 매수처럼 없는 기능을 떠올리게 하는 말과 모양(주문 버튼 등)은 쓰지 않는다.

**한 곳에만 힘을 준다.** 이 사이트에서 기억에 남아야 할 것은 "사건 핀이 박힌 내 돈 차트" 하나다. 나머지 화면(표·카드·폼)은 조용하게 두고, 핀과 사건 패널에만 표현을 쓴다.

### 3-3. 화면 사이 연결 규칙

- 홈의 "이 돈을 굴렸다면" 세 칸 → 각 시뮬레이션을 **조건이 채워진 채로** 연다(URL 쿼리에 조건을 담아 새로 고침·공유해도 같은 결과).
- 타임머신·적금 결과의 "섞어보기에 담기" → 섞어보기의 새 줄로 들어간다.
- 플러스 잠금 표시 → 그 자리 팝오버(설명·가격·닫기)를 먼저 연다. [플러스 알아보기]를 누르면 `/plus`의 해당 설명으로 이동한다.
- 소식 카드 → 원문(기관 공고)으로 바로 가는 링크가 카드 안에 있다. 상세 페이지는 요약·대상·마감·원문 링크만.

## 4. 전역 레이아웃

### 4-1. 상단 내비 vs 좌측 내비

| 기준 | 상단 바 | 좌측 사이드바 |
|---|---|---|
| 최상위 메뉴 수 | 5개(홈·굴려보기·소식·플러스·내 정보)면 한 줄에 충분 | 10개 이상일 때 유리 |
| 차트 가로 폭(1440 기준) | 본문 1280 전부 사용 → 타임머신 차트 약 896px(기존 3단 약 572px) | 사이드바 240을 빼면 차트 약 330px, 3단이 무너짐 |
| 랜딩·로그인과의 연속성 | 랜딩도 상단 바라 로그인 전후 모양이 같다 | 로그인 후에만 사이드바가 생겨 화면이 바뀐 느낌 |
| 레퍼런스 | 토스증권 PC(상단 탭 + 오른쪽 레일) | 업무용 대시보드(Monarch 등) |

→ **상단 바 64px**. 굴려보기에 들어가면 바로 아래 **하위 탭 줄 48px**(주식 타임머신 · 적금 비교 · 섞어보기)이 붙는다. 상단 바 오른쪽에는 **시드머니 칩**("내 시드머니 470,000원")을 늘 두어 어느 화면에서든 "내 돈 기준"임을 보여준다. 칩을 누르면 정의와 계산 근거(입력한 기록 기준) 팝오버.

### 4-2. 그리드

- 기준 화면 1440px. 본문 최대 폭 1280px, 좌우 여백 80px(1440 기준), 12단 그리드, 단 사이 24px.
- 일반 화면(홈·소식·플러스·내 정보): 12단 중 8 + 4(오른쪽 레일).
- 타임머신: 차트 위 본문 전체 폭에 문장형 조건 바. 그 아래 **[차트 1fr] [레일 360px]** 2단, 간격 24px. 조건 300px 열을 없애 1440 기준 차트 약 572px → 약 896px.
- 적금 비교·섞어보기: **[조건 또는 조합 편집기 300px] [본문 1fr] [레일 360px]** 3단 유지.
- 세로 리듬은 4pt 배수. 섹션 사이 32px, 카드 안 여백 24px, 클릭 대상 높이 40px 이상(표 행 48px).

### 4-3. 오른쪽 레일의 용도(화면마다 한 가지)

| 화면 | 레일 내용 | 기본 상태 |
|---|---|---|
| 홈 | 오늘의 청년 돈 소식 3개(마감 임박 먼저) + 최근 프리셋 | 늘 보임 |
| 주식 타임머신 | **사건 목록 ↔ 종목 사건 상세 / 기준금리 카드** | 사건 목록(시간순). 핀을 누르면 상세로 바뀌고 "목록으로" 버튼 |

## 5. 화면별 상세

> 괄호 안은 `wireframes.html`의 화면 이름. 와이어프레임 위쪽 툴바의 "상태" 스위치로 빈·로딩·오류 상태를, "사용자" 스위치로 무료·플러스를 바꿔 볼 수 있다.

### 5-1. 랜딩 `/` (랜딩)

**목적**: 처음 온 사람(특히 심사위원)이 10초 안에 세 가지를 안다. ① 앱에서 아낀 돈을 ② 지난 주식·적금에 넣어보는 실험이고 ③ 차트의 사건을 누르면 이유를 알려준다.

| 시간 | 눈이 가는 곳 | 화면 요소 |
|---|---|---|
| 0–3초 | 왼쪽 큰 제목 | "아낀 돈, 그때 굴렸다면 얼마였을까?" + "앱에 기록한 수입·지출로 남긴 돈을 지난 주식·적금에 넣어봐요. 진짜 돈은 움직이지 않아요." |
| 3–7초 | 예시 차트 | 47만원을 3년 전에 한 번에 넣었다면(예시). 지수 ETF·은행 평균 적금·넣은 돈 세 줄 + ▲▼ 핀·끝 라벨 |
| 7–10초 | 버튼 | 신한 블루 [로그인 없이 첫 결과 보기]가 주 버튼. 아래 [카카오 로그인] [Google 계정으로 로그인]은 같은 크기 |

```text
┌ 상단 바: 로고 · 굴려보기 · 청년 돈 소식 · 플러스 · [로그인] ┐
│ 아낀 돈, 그때 굴렸다면 얼마였을까?                         │
│ [로그인 없이 첫 결과 보기]                                │
│ [카카오 로그인] [Google 계정으로 로그인](같은 크기)         │
│ 체험을 시작하면 기본 조건은 ‘지금 저축 속도로’로 바뀌어요  │
│ 예시: 47만원을 3년 전에 한 번에 넣었다면                  │
│ ━ 지수 ETF(Navy) ─ 은행 평균 적금(회색) ┅ 넣은 돈(회색)   │
│ ▲▼ 사건 핀 · 선 끝 라벨                                  │
├ 앱에서 모으고, 웹에서 굴려봐요 → 기능 소개 → 플러스 안내 ──┤
│ 이렇게 만들었어요(Navy 면·흰 글자)                        │
│ 푸터: 약관 · 개인정보처리방침 · 고객지원 · 앱 받기         │
└──────────────────────────────────────────────────────────┘
```

- 기능 소개는 같은 모양 카드 3개를 늘어놓지 않는다. 한 줄에 하나씩, 글과 작은 화면 조각을 좌우로 번갈아 둔다.
- 랜딩·공유는 390px 폰 화면부터 완성한다. 공유 링크는 카카오톡으로 폰에서 열린다.
- 체험 버튼 아래에 “체험을 시작하면 기본 조건은 ‘지금 저축 속도로’로 바뀌어요”를 한 줄로 쓴다.
- 지수 ETF는 Navy 실선, 은행 평균 적금은 회색 실선, 넣은 돈은 회색 점선(이자 없이 모아 둔 경우). 끝 라벨과 ▲▼ 핀을 함께 둔다. 평균 적금 계산 가정은 본 화면과 같게 쓴다. 기획팀이 가정 하나로 정하는 중이며 세부는 **미확인**이다.
- “이렇게 만들었어요” 줄은 Navy 면 + 흰 글자. 계좌 연결·실제 투자 여부에 미리 답한다.
- 움직임은 첫 진입 때 예시 차트 선이 한 번 그려지는 것 하나뿐(동작 줄이기 설정이면 생략). 섹션마다 떠오르는 효과는 쓰지 않는다.
- 상태: 로그인한 사람이 `/`에 오면 홈으로 보낸다. 예시 차트는 정적 JSON이라 서버 장애와 상관없이 뜬다.

### 5-2. 로그인 `/login` (로그인)

- 가운데 카드 하나(폭 400). 위에서부터: 고양이 자리 → "앱과 같은 계정으로 로그인하면 앱에서 모은 돈을 그대로 불러와요" → **카카오 로그인** → **Google 계정으로 로그인** → 얇은 구분선 → "이메일로 로그인" 연한 버튼(누르면 그 자리에서 이메일·비밀번호 칸이 펼쳐짐) → 약관·개인정보 안내 한 줄.
- 두 소셜 버튼은 **폭 100%·높이 48px·반경 12px로 같다.** 브랜드 블루를 소셜 버튼에 쓰지 않는다. 세부는 9장.
- 상태: 소셜 창에서 취소 → "로그인을 취소했어요. 다시 하려면 버튼을 눌러 주세요". 콜백 실패 → "카카오에서 로그인 정보를 받지 못했어요 [다시 로그인]". 같은 이메일 충돌(`email_in_use`)은 "이미 가입된 이메일이에요. 처음 가입한 방법으로 로그인해 주세요". 계정 합치기는 해커톤 범위 밖. 폐쇄망에서는 이메일 시연 계정으로 로그인한다.

### 5-3. 홈 = 내 시드머니 대시보드 `/home` (홈)

> **2026-10-20 변경(사용자 결정, [decisions](decisions.md) 2026-10-20 ②): 시드머니는 앱에서 사용자가 확정한 값이다.** 시드머니 = 가입 때 입력한 **모아둔 돈** + 수입일 전날마다 사용자가 반영한 금액(매달 저축할 돈 / 실제로 모은 돈 전부 / 직접 입력). 웹은 [앱 연동하기]로 `{ total, base, monthlyGoal, lastEntry, updatedAt }`만 받는다([04 §5-2](04-service-boundaries.md)). `monthlyPace`(저축 속도)는 앱의 **매달 저축할 돈**(`monthlyGoal`)으로 바꿔 읽는다. `current`·`todaySaved`·`cycles[]`·`estimate`·`savingsTransferEstimate`는 앱이 보내지 않으므로 쓰지 않는다. 웹의 직접 수정(수정값 우선)은 웹 DB에 그대로 둘 수 있다. 아래는 이전 정의 기록이다.
> 이 화면의 보조 위젯 ①`current`·②`todaySaved`와 '거래 1건 → 웹 숫자 변화' 시연은 새 정의에서 데이터가 없다. 대체 장면은 [04 §10](04-service-boundaries.md)에서 정한다.

**목적**: 확정된 남긴 돈과 이번 주기 진행 상황을 구분하고 굴려보기로 넘어간다. 예시는 사회초년생 지수, 시드머니 **470,000원**, 월 저축 속도 **78,000원**으로 통일한다.

- 히어로(기존 잉크 숫자, Navy 면 아님): 내 시드머니 470,000원(예시) + [직접 수정]. 확정값은 **끝난 정산 주기별 수입 − 지출(고정지출 포함)의 누적**이다. 팝오버에는 계산 근거·기준일·입력한 기록 기준 고지(`SEED_BASIS`)를 둔다.
- 직접 수정: 금액 입력 → [저장] / [취소]. 저장하면 수정값을 우선 사용하고 **직접 입력** 배지. [기록 기준으로 되돌리기]로 자동 계산값을 다시 사용한다.
- Sky 진행 막대 + 숫자 라벨 ① `current`: 이번 주기 남기는 중 ○원 · 확정 전 + 주기 시작일·수입·지출. **거래 1건 입력 → 이 숫자 변화**를 시연한다. 확정 시드머니가 즉시 바뀌는 장면으로 설명하지 않는다.
- 작은 칩 ② `todaySaved`: 오늘 아낀 돈 ○원 · 표시용. 시드머니에 더하거나 누적하지 않는다. 주간 합계는 추가하지 않는다.
- 추이: 누적 선 / 주기별 남긴 돈 막대. 직접 입력액은 기록 기반 추이를 고쳐 쓰지 않고 따로 표시한다. 메타: 정산 주기마다 평균 78,000원씩 남겼어요(예시).
- 이 돈을 굴렸다면: 같은 납입 조건·기간의 대표 지수 / **은행 평균 적금(한국은행)** / **이자 없이 모아 둔 경우(0%)**. 과거 비교에 현재 상품 최고금리를 쓰지 않는다.
- 레일: 오늘의 소식 3개 + 최근 프리셋. 웹 목표 1개는 Should(§5-10), 앱 홈 목표 표시는 범위 밖.
- 빈 상태: 앱에 수입·지출을 기록하면 정산 주기가 끝날 때마다 남긴 돈이 쌓여요 + [앱 받기] [금액을 직접 넣고 굴려보기]. 진행 중 주기만 있으면 확정액 0원과 `current`를 구분한다.
- 로딩: 숫자 뼈대·빈 축. 오류: 앱 기록을 불러오지 못했어요 [다시 시도] [직접 금액으로].

### 5-4. 주식 타임머신 `/lab/stocks` (주식 타임머신) — 핵심 화면

**목적**: “앱에서 모은 돈을 그때 넣었다면 지금 얼마인가”와 “그 사이 어떤 일이 있었나”를 함께 본다.

```text
┌ 본문 전체 폭 문장형 조건 바 ───────────────────────────────────────────┐
│ [3년 전 ▾]부터 [매달 78,000원씩 ▾] [대표 지수 ETF ▾]에 넣었다면        │
│                                               [조건 전체 수정]       │
│ 36회 · 넣은 돈 2,808,000원 · 2023.10 ~ 2026.10 · 기준일 2026-10-16 (예시) │
└──────────────────────────────────────────────────────────────────────┘
┌ 차트 1fr ──────────────────────────────────────┐┌ 레일 360 ────────────┐
│ 결과 금액 / 넣은 돈 / 차이 ▲ +금액·비율(예시) ││ 사건 목록 ↔ 상세     │
│ [합계|종목별] [표로 보기]                      ││ 이 기간 내 돈 변화   │
│ ━ 내 자산(Navy)   ┅ 넣은 돈                   ││ (넣은 돈 제외)       │
│ ▲▼ 종목 사건 핀 · 선택 구간 옅은 음영          ││ 또는 기준금리 카드   │
│ x축 아래 시장 줄 24px: [지수] [%]             ││                      │
│ 과거 시세로 계산한 가상 결과예요.             ││                      │
│ 앞으로도 그렇다는 뜻은 아니에요(항상 13px)    ││                      │
│ [세금·수수료·배당 빠짐] [소수점 매수 가정]     ││                      │
└───────────────────────────────────────────────┘└──────────────────────┘
```

**문장형 조건 바·입력**

- 문장 바는 항상 **지금 보이는 결과의 조건**이다. 밑줄 칸은 버튼이며 ▾를 붙인다. 누르면 그 자리 팝오버, [적용]을 누르면 다시 계산한다.
- 종목·비율·직접 입력 금액은 [조건 전체 수정] 패널(서랍)에서 편집한다. **편집 중 값과 표시 중 결과를 분리**하고 [다시 계산]으로 반영한다. 취소하면 결과·문장은 그대로다.
- 계산은 첫 방문·기본 조건에서 처음 한 번 자동 실행한다. 그 뒤에는 [적용] / [다시 계산]으로만 실행한다. 계산 중에는 이전 결과를 투명도 0.4로 유지한다.
- 문장 아래 **영수증 줄**: “36회 · 넣은 돈 2,808,000원 · 2023.10 ~ 2026.10 · 기준일 2026-10-16 (예시)”. 회차·총액·실제 기간·기준일을 보인다. 날짜 보정이 있으면 실제 시작일을 쓴다.
- 1024–1279px: 문장 2줄 + 레일 서랍. <1024px: 문장 요약 + [조건 전체 수정] 시트. 일정이 밀리면 **요약 바 + 접는 폼**이 최소안이다. **대표 승인: W1부터 문장형이 프론트 기본안**.
- 적금 비교·섞어보기는 3단을 유지한다. 섞어보기 왼쪽은 조건이 아니라 조합 편집기다.

| 항목 | 컨트롤 | 기본값 | 규칙 |
|---|---|---|---|
| 언제부터 | [1년 전][3년 전] + 날짜 직접 지정(무료, 3년 안) | 3년 전 | 시세는 3년 스냅숏. 5년 칩은 해커톤에서 숨기고 데이터가 늘면 설정값으로 다시 연다 |

> 모은 날짜 그대로 넣기는 없다. 모은 금액(총액)과 모으는 속도(월평균)를 과거로 보내는 방식이다. 47만원 총액과 7.8만원 월 금액을 같은 입력처럼 보이지 않게 한다.

**요인 = 시장 줄 + 기준금리 카드**

- 01 기획서의 시장 사건(코스피200 대용 급변·한국은행 기준금리 변경일)은 **x축 아래 높이 24px 시장 줄**에 둔다. 18px Navy 둥근 네모(반경 4) + 흰 기호(금리 %, 급변은 지수 기호), 날짜 위치로 1px 점선 연결. 종목 ▲▼ 원형 핀은 선 위아래 그대로다.

- 카드: **기준금리 변경** / 변경 전 → 후(3.50% → 3.25%, **예시**) / 효력일 / 근거(한국은행 통화정책방향 결정문).
- 고정 설명: “같은 기간의 기준금리와 평가액을 함께 봐요. 기준금리는 은행 적금 금리와 다른 숫자예요.”
- [이 기간 은행 평균 적금 보기 →]는 적금 비교 ‘그때 들었다면’ 탭을 같은 기간으로 연다. **2026-10-20 팀 회의로 과거 시점 비교를 뺐으므로 이 버튼의 목적지는 미정이다(버튼을 뺄지 다른 곳으로 보낼지 디자인·기획이 정한다).** “다른 요인도 함께 작용했을 수 있어요”를 고정한다. 인과를 단정하지 않는다.
- 금리 값·효력일·지원 기간 안 변경 횟수는 **미확인**. 개발·콘텐츠 담당이 한국은행 공식 자료로 채운다.
- **Should(대표 승인)**: 시장 줄 위치에 기준금리 계단선 띠 + 메인 차트 십자선 연동. Must가 끝나고 11/1 전 검증까지 마칠 때만 한다. 와이어프레임에는 그리지 않는다.
- 시장 핀도 시간순 로빙 묶음에 포함. aria-label 예: “시장 사건, 기준금리 변경, 3.50%에서 3.25%로(예시)”.

### 5-5. 적금 비교 `/lab/savings` (적금 비교)

**목적**: 같은 납입 조건으로 비교한다. 상품을 지목하는 추천 문장·순위 열·내 조건 금리는 만들지 않는다.

- 탭 없이 [지금 가입하면] 한 화면(2026-10-20 팀 회의). 기본 월 납입은 지수의 저축 속도 78,000원(예시), 직접 변경 가능.
- 조건 300px(월 금액·기간·정액/자유·금융권) + 상품 표 + 상세 360px. 금융권은 체크 [은행] [저축은행] [정책 적금]. 처음에는 은행·저축은행만 켜고, 정책 적금을 켜면 상품 표 아래에 정책 적금 카드가 붙는다. 은행·저축은행을 모두 끄면 표 없이 정책 적금 카드만, 셋 다 끄면 "금융권을 하나 이상 골라 주세요". 정렬은 **기본금리 / 최고금리 / 기간**만(초기 기본금리 내림차순). 표 위에 광고로 순서를 바꾸지 않아요·공시 기준월.
- 표 열: 상품·은행 / 기본금리 / 최고금리 / 만기 세후 수령액(기본금리 기준) / 비교 체크. 우대조건은 상세의 **읽기 전용 원문**이며 체크하거나 금리를 계산하지 않는다. 가입 버튼 없음.
- 결과 문장: 같은 조건으로 계산한 상품 ○개예요. 상품명 지목·가장 많은 건 ○○ 같은 문장 없음. 금액 열은 오른쪽 정렬·고정폭 숫자.
- 과거 시점 비교([그때 들었다면], 은행 평균 적금 한 줄)는 2026-10-20 팀 회의로 뺐다.
- 비교는 설정값(무료 2 / 유료 5). 만기 세후 이자 가로 막대 + 기간 동안 내 돈 선. 4·5번째 계열은 색에 더해 선 무늬·끝 라벨·표를 제공한다.
- 기간 동안 내 돈 선은 세로축을 **넣은 돈 위에 쌓인 세전 이자**로 그린다(원금까지 더하면 상품 차이가 1~2%라 선이 겹친다). 기준선은 이자 없는 통장 0원 회색 점선, 툴팁에 그 달까지 넣은 돈을 함께 쓴다. 색은 비교에 넣을 때 받은 칸을 유지한다(다른 상품을 빼도 바뀌지 않음). 표로 보기에서는 달마다 표.
- 서버 결과를 표시하고 금액만 원 단위 내림. 적금 세후는 단순 15.4% 추정 고지, 은행 실제 계산과 다를 수 있다. 계산 가정은 응답 assumptions로 표시한다.
- 정책 적금 카드(청년미래적금): 월 납입은 왼쪽 조건 금액을 쓰고 월 최대 50만원을 넘으면 맞춘 뒤 안내, 기간은 36개월 고정(다른 기간이면 안내). 카드 안에서 일반/우대형과 적용 금리만 **직접 입력**한다. 36개월·월 최대 50만원·기여율 6%/12%는 기획 리뷰의 예시이며 공식 규칙 확정 전 **[미확인]** 표시. 자격 자동 판정 없음, 자격 체크리스트는 카드 안 접기.
- 정책 결과: 원금 / 정부기여금 / 이자 / 합계, 같은 납입 조건의 은행 평균 적금과 나란히. 기여금 적립 시점·기여금 이자·중도해지 규칙은 **[미확인]**. 시연은 만기 기여금 일시 지급·기여금 이자 없음 **[가정]**을 입력과 결과에 함께 명시한다. 공식 안내 링크는 기획 제공값만 연결하며 없으면 확인 중. 가입 버튼 없음.
- 상태: 결과 0개는 조건 변경 안내. 공시 오류는 마지막 성공 데이터와 기준월·재시도. 정책 필수 입력 누락은 해당 칸 안내, 계산 규칙 미확정은 추정 배지로 구분한다.

- 조합 탭(무료 A/B, 유료 최대 A~E; 설정값). “그냥 통장”(이자 0%) 선과 넣은 돈 점선은 같은 경로이므로 **회색 점선 하나 “넣은 돈(이자 없이 모은 경우)”**으로 합친다. 조합은 새 범주색 1~5번 순서다.
- 줄마다 종류 아이콘(주식/적금/통장), 이름, 슬라이더 + 숫자 칸(5% 단위). 합이 100이 아니면 비율 막대 끝에 "20% 남았어요" / "10% 넘었어요" + [나머지는 통장에]. 빨간 경고 대신 안내 문구.
- 비율 막대: 가로 누적 막대, 칸 사이 2px 틈.
- 비교 표의 "가장 크게 줄었던 때": "−18%(2022.10, 예시)"처럼 날짜와 함께. MDD·변동성 같은 용어 금지. 근거가 확정되지 않은 흔들림 등급은 제외한다.
- **프리셋**: 저장(기본 이름은 구성 요약 "적금 70 · 주식 30"), 불러오기, 이름 바꾸기, 삭제, **공유 링크**.
  - 공유 링크는 기본으로 **비율과 상품만** 담고 금액은 뺀다. "금액도 보여주기"를 켜야 금액 포함(무료 선택).
  - 공유 페이지 `/p/:id`: 읽기 전용 결과 + [내 시드머니로 해보기](로그인 유도). 공유가 곧 유입 경로.
  - 기본 프리셋에 "안전형·공격형" 같은 이름을 쓰지 않는다(투자 성향 권유처럼 읽힘). 구성 요약 이름만.
- 상태: 줄 0개 → "타임머신이나 적금 비교에서 '섞어보기에 담기'를 누르거나 여기서 바로 더해요". 프리셋 0개 → "조합을 저장하면 다음에 바로 불러올 수 있어요". 한도는 설정값: 무료 비교 2개·프리셋 3개, 유료 비교 5개·프리셋 50개. 공유 링크와 금액 공개 선택은 무료. 5계열은 선 무늬·끝 라벨·표로 구분한다.

### 5-7. 오늘의 청년 돈 소식 `/news` (청년 돈 소식)

**목적**: 청년이 당장 돈을 아끼거나 받을 수 있는 소식을 매일 몇 개씩. 앱 사용자가 웹에 다시 올 매일의 이유.

- 맨 위 "오늘의 한 장"(큰 카드 1개) + 아래 카드 목록(3열 → 2열 → 1열).
- 필터 한 줄: 분야 칩 [전체][교통][주거][금융][일자리][생활·문화] · 지역 선택 · 정렬 [마감 임박순|새로운 순] · "지금 신청할 수 있는 것만".
- 카드(위→아래): 분야 칩 + 마감 배지 → 제목(쉬운 말, 2줄 이내) → **얼마 아끼나 한 줄**(굵게) → 대상(나이·지역·소득 요약) → 출처 기관 + "공고문 보기 ↗" → 저장.
- 카드에는 오늘 할 일 1개·계산해 보기 링크(해당 시 정책 적금 탭)·기준일 `asOf`·정정 시각을 추가한다. 나이대·지역 맞춤 필터는 전부 무료, 브라우저에만 저장한다.
- 마감 배지: 7일 이내 "D-3"(주황 배경 + 시계 아이콘 + 글자), 당일 "오늘 마감", 상시 "상시". 끝난 소식은 목록에서 내리고 저장함에만 "마감됨"으로 남긴다. 색만으로 구분하지 않는다.
- 상세 `/news/:id`: 요약 3줄, 누가·얼마·언제까지·어떻게, 공고문 원문 링크(크게), "신청 기간은 바뀔 수 있어요. 공고문에서 꼭 확인하세요", 같은 분야 소식 3개.
- 상태: 필터 결과 0개 → "이 분야에는 지금 소식이 없어요 [필터 지우기]". 로딩 → 카드 뼈대 6개. 오류 → "소식을 불러오지 못했어요 [다시 불러오기]".
- 소식 출처(온통청년 API·직접 정리 등)는 기획·개발 결정. 화면에는 늘 출처 기관명과 원문 링크.

### 5-8. 플러스 `/plus`와 잠금 표시

**해커톤 대표 가치**: 정책 마감 리마인더 **등록 시연**(실제 발송 없음)·저장 한도 확대·광고 없음. 상단은 Navy 면 + 흰 글자다.

| 해커톤 화면의 혜택 | 무료 | 플러스 |
|---|---|---|
| 정책 마감 리마인더 등록 시연 | 잠금 | 제공(발송 없음) |
| 저장 한도 확대(종목 / 비교 / 프리셋) | 3 / 2 / 3 | 5 / 5 / 50 |
| 광고 없음 | 기본 화면 | 제공 |

첫 결과·사건 본문·근거·기간 칩·날짜 지정·적금·정책 적금·공유 금액 선택·웹 목표 1개는 무료다. 유료 잠금은 해당 자리 팝오버(무엇이 열리는지·가격·알아보기·닫기)로만 보인다. 결과 전체를 가리는 결제 유도 모달은 없다.

- 가격: 연 9,900원 기본 / 월 990원 선택. 결제 전·결과에 모의 결제·실제 청구 없음을 표시한다.
- 한도는 공통 설정값. 실제 해지·환불·결제 정책은 **미확인**, 출시 전 확정한다.

**출시 후 경계(발표 자료)** — decisions 7·13·17: 월간 내 돈 리포트(내 기록 해설만)·정밀 모드(배당 재투자·수수료·세금)는 해커톤 화면·혜택 표에서 뺀다. 출시 전 계산 규칙·콘텐츠·운영 검증 뒤 별도로 다룬다.

### 5-9. 내 정보 `/me` (내 정보)

- 계정: 이메일·로그인 방법. 표시 이름·계정 합치기는 범위 밖.
- 앱 기록: 앱 기록 기준 시각(마지막 거래 기록일)·시드머니 계산 근거. 계좌 연결처럼 보이는 설정은 없음.
- 구독: 현재 플랜·모의 결제 표시·[해지 확인]. 실제 결제일은 제공하지 않는다.
- 화면: 테마·핀 무늬·안내 다시 보기. 해커톤은 라이트·데스크톱 우선, 다크·중간 폭 서랍은 Could(토큰 유지).
- 로그아웃·계정 삭제·약관·개인정보처리방침.

### 5-10. 웹 목표 `/goal` (Should)

무료 목표 1개. 목표 이름·금액·기한 입력 → [저장] → 목표 금액·확정 시드머니·진행률·남은 금액. 수정·삭제 제공. 미입력·기한 경과·저장 오류는 해당 입력 옆 안내. 목표 진행은 웹에서만 표시한다. 앱 홈 표시 문구 없음.

### 5-11. 공유 결과 `/p/:id`

랜딩과 함께 **390px 폰부터 완성**한다. 공유 링크는 카카오톡으로 폰에서 열린다. 공유 머리는 Navy 면 + 흰 글자. 1단: 구성 요약 → 비율 → 금액 공개 여부 → 읽기 전용 결과 → `SIM_PAST`·소수점 매수 가정 → [내 돈으로 해보기]. 기본은 **비율·상품만** 공개하며 서버 저장 payload에서 금액을 제거한다. 금액 비공개면 금액 축·툴팁·표·메타에도 금액 없음. 공개 선택은 무료.

공유 생성 화면: 금액 공개 체크(기본 꺼짐)·미리보기·링크 복사·공유 중단. 존재하지 않음/중단됨은 안내와 체험 링크. 비로그인도 열람 가능, 내 돈으로 실행은 체험 또는 로그인. OG는 고정 이미지와 제목·설명, 매번 그래프 이미지 생성은 Could.

### 5-12. 결제 결과 `/billing/result` (모의)

연 9,900원 기본 / 월 990원 선택 → **모의 결제 확인 화면**(선택 요금·실제 청구 없음·계속/취소) → 완료/실패/취소 결과. 완료는 시연용 플러스 적용·돌아가기, 실패는 사유 예시·재시도·요금 선택, 취소는 변경 없음. 내 정보의 해지 확인 → 유지/모의 해지 완료. 각 화면에 실제 청구 없음 표시.

### 5-13. 리마인더 등록 시연·출시 후 경계

리마인더: 정책·마감일·수신 이메일(없으면 직접 입력)·수신 동의·저장/해제. 실제 발송 없음. 무료는 해당 자리 팝오버. 월간 리포트·정밀 모드는 §5-8의 출시 후 경계(발표 자료)로만 적고 해커톤 화면에는 넣지 않는다. 소식 맞춤은 나이대·지역을 브라우저 필터로만 사용하며 건너뛰기 가능하다.

- 숫자·글자는 이 색을 쓸 수 있다(4.5:1 이상). 단 **항상 ▲▼ 기호와 +/− 부호를 같이** 붙인다.
- Royal `#2878F5`는 하락 기준색이다. 흰 바탕 4.12:1이라 작은 글자는 금지한다. 실제 `--fall`은 글자 대비 때문에 `#1F6FE0` 유지(Royal과 OKLab ΔE 3.9, 사실상 같은 색). 블루는 누를 수 있는 것에만 쓴다. 합계 자산선은 Navy, 범주 1번은 Sky 계열 `#2E9BE6`이다.
- 상태색(오류 빨강 `#D92D20`)과 상승색이 같은 값이다. 오류 메시지에는 항상 아이콘 + 문장을 붙이고, 차트 안에서는 오류색을 쓰지 않는다.

**고정 회색**: 넣은 돈(원금) 점선·적금 비교 기준 실선. 섞어보기는 “넣은 돈(이자 없이 모은 경우)” 점선 하나. 색은 `#8A93A8`(라이트, 흰 바탕 3.08:1) / `#8A93A8`(다크, 5.56:1). 눈금선 `#E4E8F0` / `#263049`, 1px 실선, 가로만.

**무늬(선택)**: 내 정보 > 화면 > "사건 핀 무늬 더하기"를 켜거나 인쇄·강제 색상 모드일 때만, 원금 위 면은 45°, 아래 면은 135° 빗금. 기본은 끔.

### 6-3. 선·축·라벨

- 선 2px(내 자산은 2.5px), 끝은 둥글게. 점선은 원금(기준선)에만 쓴다(4 4). 눈금선은 점선 금지.
- 면은 계열색 10%. 진한 면 덩어리 금지.
- y축 눈금은 한국식 단위: `0`, `50만`, `100만`, `1억`. 고정폭 숫자. 왼쪽 정렬 대신 오른쪽 끝 정렬.
- x축은 기간에 따라 `2021`, `2021.07`, `10.17`.
- 직접 라벨은 선 끝에만(종목명 + 지금 금액). 점마다 숫자 금지. 선 끝 라벨이 겹치면 세로로 밀지 말고 가는 연결선을 쓰거나 범례로 넘긴다.
- 범례는 2계열 이상일 때만, 차트 위 왼쪽. 선 범례는 짧은 선 모양(네모 아님).
- 글자는 계열 색을 입지 않는다. 라벨·값·범례는 잉크 색, 옆의 색 표시가 계열을 알려준다.

### 6-4. 사건 핀

**모양**

| 종류 | 표시 | 위치 |
|---|---|---|
| 급등 | 지름 18px 원, `--rise` 채움, 흰 ▲, 바탕색 2px 고리 | 선의 해당 날짜 지점 **위로 14px**, 지점과 1px 줄기로 연결 |
| 급락 | 같은 크기, `--fall` 채움, 흰 ▼ | 지점 **아래로 14px** |
| 시장(기준금리·코스피200 대용 급변) | 18px Navy 둥근 네모(반경 4) + 흰 %(금리) / 지수 기호 | x축 아래 24px 시장 줄, 날짜에 1px 점선 연결 |
| 참고(상장·분할 등) | 같은 크기, 회색 테두리 원, 잉크 "i" | 지점 위 |
| 묶음 | 지름 22px 원, 잉크 채움, 흰 숫자(개수). 모두 같은 방향이면 그 방향 색 | 묶인 핀들의 가운데 날짜 |
| 선택됨 | 잉크 3px 테두리 + 위아래로 이어지는 세로 안내선(1px, 잉크 40%) | — |

- 클릭·hover 대상은 보이는 모양보다 크게: 32px 투명 영역. 시장 핀과 종목 원형 핀은 모양부터 다르다.
- 핀 선택 시 사건 구간 `startDate~endDate`에 옅은 음영을 칠한다. 금리 카드는 §5-4의 고정 문장·근거·같은 기간 적금 링크를 따른다. 기준금리 계단선 띠는 Should이며 와이어프레임에는 그리지 않는다.
- **묶는 기준**: 화면에서 두 핀의 가로 간격이 24px 미만이면 하나로 묶는다(기간을 바꾸면 다시 계산). TC2000의 "한 봉에 기사가 여럿이면 개수 표시"와 같은 생각.
- **개수 상한**: 한 화면에 핀은 최대 8개(묶음은 1개로 셈). 넘치면 등락폭이 큰 순으로 고르고, 차트 아래에 "이 기간 사건 12개 중 큰 8개를 표시했어요. 전부는 오른쪽 목록에서" 한 줄. 레일 목록에는 전부 나온다.
- 사건 후보는 03 detector v1(시장 보정 60일 z≥3·일간 ±4%, 5일 누적·시장 사건) 기준과 합의한다. 시연은 사전 검수한 스냅숏만. 사건 전체를 한 번 받아 묶음·확대는 클라이언트에서 처리한다.
- 움직임: hover 시 1.15배(140ms, ease-out). 동작 줄이기 설정이면 크기 변화 없이 고리만 두꺼워진다.

**툴팁 규칙**

- 값이 먼저, 이름이 나중: 첫 줄 등락률(▲ +12.3%, 17px 굵게) → 사건 한 줄(15px) → 날짜·기간(13px 보조) → "이 기간 내 돈 변화(넣은 돈 제외) +38,000원" → 출처 이름(13px 흐림) → "눌러서 이유 보기".
- 폭 240~280px, 카드 바탕, 반경 12, 떠 있는 그림자. 핀 위에 뜨고, 위 공간이 없으면 아래, 오른쪽 끝이면 왼쪽으로 뒤집는다.
- 키보드 포커스에도 같은 툴팁이 뜬다. 툴팁에만 있는 정보는 없다(레일 목록·표 보기에 모두 있음).
- 사건 제목·출처는 외부 데이터이므로 `textContent`로 넣는다(HTML 문자열 결합 금지).

**상세 패널 규칙**

- 레일 안에서 열린다(모달 아님). 차트를 가리지 않는다. 1024–1279px에서는 서랍, 그보다 좁으면 아래 시트.
- 순서 고정: 제목 → 날짜·등락 → 이 기간 내 돈 변화(넣은 돈 제외) → 무슨 일 → 시장 반응 → 그 뒤에는 → 근거 → 고지 → 이전/다음(§5-4 필드 계약).
- 사실과 풀이를 칩으로 나누고, AI가 쓴 부분엔 "AI 요약" 칩. 출처 없는 문장은 넣지 않는다.
- 링크는 새 창, 매체명과 날짜를 같이.

**키보드·스크린리더**

- 차트 컨테이너: `role="group"`, `aria-label="내 자산 변화 차트, 2023년 10월부터 2026년 10월, 사건 5개(예시)"`. 그 아래에 "표로 보기" 버튼.
- 핀: `<button aria-label="급등, 2026년 3월 9일, 대표 지수 반등, 6% 상승(예시). 눌러서 자세히">`. 로빙 tabindex(하나만 0, 나머지 -1), ←/→/Home/End, Enter·Space, Esc.
- 시장 핀도 같은 로빙 tabindex 묶음 안에서 시간순으로 이동한다. aria-label 예: “시장 사건, 기준금리 변경, 3.50%에서 3.25%로(예시)”.
- 선택이 바뀌면 레일 제목으로 알림(`aria-live="polite"`).
- 표로 보기: 달별(날짜·내 자산·넣은 돈·차이) 표 + 사건 표(날짜·종류·제목·등락률·출처).

### 6-5. 차트 라이브러리 비교와 추천

| | **visx** | Recharts | lightweight-charts | ECharts |
|---|---|---|---|---|
| 그리는 방식 | SVG, React 컴포넌트 조각 + d3 스케일 | SVG, 완성형 컴포넌트 | 캔버스 | 캔버스/SVG 선택 |

| 금융 차트 기능(확대·이동) | 직접 | 기본 Brush | 매우 좋음 | dataZoom 좋음 |
| 라이선스 | MIT(개발 확인) | MIT(개발 확인) | Apache-2.0 + **TradingView 저작자 표시·링크 의무** | Apache-2.0 |
| 팀이 익히는 비용 | 중간(d3 개념 필요) | 낮음 | 낮음~중간 | 중간(옵션 객체가 큼) |
| 판정 | **추천** | 대안(일정이 빠듯하면) | 비추천 | 비추천 |

- **추천: visx.** 이 서비스의 차트는 "선 2~5개 + 핀 + 툴팁 + 키보드"가 전부다. 확대·이동 같은 트레이딩 기능은 필요 없고, 핀을 우리 마음대로(묶음·위아래 위치·포커스) 그려야 한다. 스케일을 그대로 받아 HTML 버튼을 올리는 방식이 가장 단순하고, SVG라 다크 모드 토큰이 그대로 먹는다.
- **대안: Recharts.** 일정이 급하면 홈 추이·적금 막대 같은 단순 차트는 Recharts로 먼저 만들고, 타임머신 핀 레이어만 따로 얹는다. 단 라이브러리 두 개를 섞으면 축·툴팁 모양이 달라질 수 있으니 공통 축·툴팁 컴포넌트를 먼저 만든다.
- **lightweight-charts 비추천 이유**: 저작자 표시·링크를 화면에 넣어야 하고, 캔버스라 핀 접근성을 따로 만들어야 하며, 보기 모양이 트레이딩 앱 쪽이라 "겁주지 않기"와 거리가 있다.
- **ECharts 비추천 이유**: 기능은 충분하지만 색·글꼴을 JS 옵션으로 따로 관리하게 되어 디자인 토큰과 갈라지고, 핀 포커스는 어차피 직접 만들어야 한다.
- 데이터가 많을 때(일별 10년 × 5종목 ≈ 1만 2천 점): 3년 넘는 기간은 주별로 줄여 그린다(방식은 개발 결정). 선은 계열당 path 하나라 SVG로 충분하다(개발 확인).
- 최종 선택은 `03-architecture.md`와 맞춘다.

2026-10-20 개편: SOLID 2.0 기준(단일 블루 강조, 흰 캔버스 + 옅은 회색 2단, 8~12px 모서리, 1px 테두리 + 미세한 그림자, 여유 밀도)으로 바꿨다. 값의 정본은 `src/styles/tokens.css`이고, `global.css`의 짧은 이름(`--brand`, `--card` 등)은 기존 코드를 위한 별칭이다. 새 코드는 `--color-*`·`--radius-*`·`--density-*`를 쓴다. 다크는 내 정보에서 고를 때만.

### 7-3. 간격·모서리·깊이·움직임

- 간격(4pt): 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80.
- 밀도(comfortable): 버튼·입력 `--density-control` 48px(작은 버튼 40), 카드 안쪽 `--density-pad` 28px, 카드 사이 `--density-gap` 24px, 표 한 줄 `--density-row` 56px.
- 모서리: 카드·모달 `--radius-soft` 12 > 버튼·입력·칩·안쪽 타일 `--radius-soft-sm` 8 > 막대·코드 `--radius-xs` 4. 알약(999) 모양은 쓰지 않는다. 로그인 버튼 세 개(카카오·Google·이메일)는 `--radius-login` 12로 같이 맞춘다(카카오 규정 "radius 12px"). 높이 48, 1px 테두리, 이메일 버튼은 흰 면 + `--color-border-strong`.
- 깊이: 카드는 1px 테두리 + `--shadow-subtle`(`0 1px 2px rgba(17,24,39,.05)`). 떠 있는 것(툴팁·팝오버·서랍·모달)만 `--shadow-overlay`(`0 8px 28px rgba(17,24,39,.14)`, 다크 `rgba(0,0,0,.5)`).
- 상단 바: 메뉴 링크·시드머니 칩·아바타·[로그인] 높이를 `--density-control-sm` 40으로 맞춘다. 지금 있는 메뉴는 바탕 없이 브랜드 글자만(밑줄 없음), hover는 `--color-bg-subtle`. 아바타도 원 대신 `--radius-soft-sm`.
- 확인 창: 되돌릴 수 없는 동작 전에 `ConfirmDialog`로 묻는다. 제목은 질문, 본문은 결과, 버튼은 [취소] [동작 이름] 같은 폭.
- 움직임: `cubic-bezier(0.23, 1, 0.32, 1)`, 눌림 140ms, 나타남 280ms, 사라짐 200ms. 사용자가 누른 것에만 반응. `prefers-reduced-motion`이면 이동·크기 변화 없이 투명도만.

## 11. 구현 인수 기준

- 웹 목표·공유·모의 결제 화면은 §5-10~12와 IA에 함께 연결한다. 정책 적금은 적금 비교의 금융권 선택지와 소식 카드의 계산해 보기(`/savings?policy=1`)에서 접근한다.
- 사용자·플랜 전환 때 사건 본문과 근거 수는 같아야 한다. 첫 결과·기간 지정은 무료다.
- 문장 바는 표시 중 조건만 보인다. 슬롯·서랍 편집 취소 시 결과 불변, 적용 때만 재계산·이전 결과 흐림. 방식별 금액 하나와 영수증 회차·실제 기간을 확인한다.
- 5년 칩 숨김·3년 안 날짜·시장 핀 로빙·사건 구간 음영·금리 카드 동일 기간 링크·상시 고지·펼치는 가정을 확인한다.
- 랜딩·공유 390px 우선. 홈 세 값의 모양, 섞어보기 기준선 하나, 정책 계산 가정 접힘, 플러스 시연 혜택만 확인한다.
- 다크 범주색은 **미정**, 공식 CI·금리 자료는 **미확인**. 라이트 범주색은 검증 스크립트 재검증을 마쳤다(§6-2). 금리 계단선 띠는 Must 완료 후 11/1 전 검증까지 가능한 경우만 Should다.
- 상용 출시 전 실제 상품 규칙·출처·결제 정책 확인은 대표 질문으로 남긴다.

  - 화면: 랜딩 · 로그인 · 홈 · 주식 타임머신 · 적금 비교(지금/과거/정책) · 섞어보기 · 청년 돈 소식 · 플러스 · 내 정보 · 웹 목표 · 공유 결과 · 모의 결제 결과 (주소 `#stocks`처럼 해시로도 이동)

  - 사용자: 무료 / 플러스 / 비로그인 체험. 잠금 칩·조합 C~E·적금 비교 개수·프리셋 개수가 바뀐다
  - 테마: 시스템 / 밝게 / 어둡게
  - "첫 방문 안내 초기화": F5 입력 모달을 다시 띄운다. [첫 결과 보기] 뒤 첫 핀 메모 1개, 4단계는 [사용법 보기]로만 연다
