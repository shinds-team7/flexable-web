# 웹 개발 인수인계

2026-10-27 갱신. 구현 상태는 `main`의 `0151809`(#96 홈 영상·#97 머지) 기준으로 코드·계약·마이그레이션과 GitHub Issue·PR을 대조했다. 운영 반영과 실제 데이터 확인은 별도로 적는다. **앱 연동 실기기 통합 확인은 10-26 리드 확인으로 완료 처리했다.** 이번 문서 정리에서 실기기 검증을 다시 수행한 것은 아니다.

개발 기준은 [PRD](../PRD.md)·[정책](../policies.md)·[웹 API 계약](../contracts/web-api.yaml)·[변경 이력](../CHANGELOG.md)·[결정 기록](../decisions/README.md)이다. 이 문서에 남은 제안이나 Issue만으로 정책·계약을 바꾸지 않는다.

## 다음 작업 순서

1. 최신 main을 받은 뒤 CHANGELOG와 변경 문서를 읽고, 스펙 변경이 머지됐으면 적용할 차이부터 정리한다.
2. 투자 인사이트 스펙 PR #90은 리드 승인 기록이 있고 최신 main과 충돌이 없는 미머지 상태다. 최종 CI·리드 확인 뒤 머지하고, 그다음 #89 구현을 시작한다. #89·#94 담당은 `rhkrqkq`이며, #89가 시장 띠 응답 틀과 국내 지수를 먼저 만들고 #94가 해외 지수·환율·금을 추가한다.
3. #48(청년 소식 자동 게시·AI 요약)은 #93으로 main에 머지됐다. solpa 반영(V15·`GEMINI_API_KEY`)과 남은 확인은 아래 각 절을 따른다.
4. 홈 히어로 고양이 영상은 #96(Issue #95)으로 main에 머지됐다. 남은 것은 사용자가 만드는 새 영상으로 교체하는 일과 Safari·Firefox 재생 확인이다.
5. 기존 앱 연동 실기기 확인은 완료다. #83(웹 수정 → 앱 쓰기)은 10-27에 구현 PR을 올렸다(아래 표). #89 개편, F7 기획·F3 범위 결정은 아래 조건에 따라 이어간다.
6. solpa 실제 배포 커밋·Flyway 버전 확인과 반영은 운영 담당이 별도로 한다. 앱 실기기 완료만으로 최신 main 배포 완료를 추정하지 않는다. 10-27 반영 명령을 리드에게 전달했고 결과는 아직 받지 못했다(아래 solpa 절).

## solpa 운영 반영과 확인

운영 주소는 `https://solpa.shinhanacademy.co.kr`, 구성은 Ubuntu VM의 web·api·MySQL 8.4·선택 worker다. 명령 정본은 [VM README](../../deploy/vm/README.md)다. **main 머지는 Vercel 자동 배포 경로이고 solpa 반영은 수동이다.** Vercel의 `VITE_API_URL`은 웹 백엔드 사용 여부와 함께 배포별로 확인한다. Vercel 화면만으로 웹 서버 기능 완료를 판정하지 않는다.

마지막 배포 문서 기록은 10-23 #50(`2c3c1eb`, Flyway V8)이다. 10-27 바깥에서 본 것: `/api/v1/health`는 UP이고, `/api/v1/youth-news`가 `summary` 필드(V15 이후 응답)를 주지만 값은 null이었다(`GEMINI_API_KEY` 입력 전). 그러니 V8 기록보다는 최신이지만 정확한 커밋·Flyway 버전은 VM에서 확인해야 한다. 10-27 리드에게 반영 명령(현재 커밋·Flyway 조회 → `GEMINI_API_KEY` 입력 → `./backup.sh` → `git pull` → `docker compose --profile worker up -d --build` → health·Flyway·요약 로그 확인)을 전달했다. **10-26 현재 VM 커밋·Flyway 버전은 이번 정리에서 확인하지 않았다.** 앱 연동 실기기 확인은 완료됐지만, 그것만으로 #53·#47·#88 등 최신 main 전체가 VM에 반영됐다고 기록하지 않는다.

## 결정 대기: 발표·광고·출석과 꾸미기

10-25 강사 피드백은 방향을 정한 뒤 결정 기록·01·[bm-ideas](bm-ideas.md)에 반영한다. 시연 전 자동으로 개발 범위에 넣지 않는다.

- [ ] **계좌 연결 로드맵**: 발표의 향후 계획으로만 설명한다. 현재 직접 입력/선택과 구분하고, 연결 방식·시점은 확정하지 않는다. 실제 구현할 때 제휴 API·허가 등 방식과 금융 정보 처리 범위를 확인하고 방침을 함께 고친다.
- [ ] **무료 화면 광고**: 일반 광고를 BM·매출 시나리오에 넣을지, 해커톤에서는 자리 시안만 보일지 정한다. “광고” 표시와 편집 콘텐츠 구분, 결과 주변 특정 상품 광고·가입 건별 대가 제한을 지킨다. 도구 도입으로 쿠키·외부 전송이 생기면 방침을 함께 고친다. 플러스의 광고 없음과 연결한다.
- [ ] **출석 포인트·캐릭터 꾸미기**: 웹 독립 포인트 / 앱 단계 조회 / 통합 중 앱 담당과 저장 주체부터 정한다. 기존 앱 캐릭터 점수(0~400, Lv.1~5)를 웹 출석 포인트와 같은 것으로 취급하지 않는다. 현금·상품권·금융상품 교환이나 수익률 보상에는 쓰지 않는다. 홈 캐릭터/출석·내 정보 꾸미기·유료 아이템과 F6의 관계를 정하고, 저장 항목이 생기면 방침을 함께 고친다.
