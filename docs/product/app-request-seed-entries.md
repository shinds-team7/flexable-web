# 앱 요청: 웹 연동 API에 주기별 반영 기록 추가 (2026-10-20)

> **2026-10-24 상태:** 웹 쪽(아래 5)은 10-21 #33으로 구현됐다. 앱 쪽 완료 기준(4)의 체크 상태는 이 저장소 코드로 확인할 수 없어 그대로 두었다. HANDOFF 10-21 기록상 앱 API는 main에 머지됐고 운영 배포와 실기기 통합 확인은 남아 있다([HANDOFF](HANDOFF.md)).

> 앱(flexable-app) 담당에게 전달하는 요청서다. 결정 근거는 [decisions ④-3](decisions.md), 정보 범위는 [04 §5-2](04-service-boundaries.md#5-2-연동으로-받을-수-있는-정보-최소-범위). 계약의 정본은 앱 `docs/API.md` "웹사이트 연동"이며, 앱에서 확정한 내용으로 이 문서를 고친다.

## 1. 왜 필요한가

웹 홈의 '시드머니가 쌓인 모양'(꺾은선)은 주기마다 시드머니가 어떻게 늘었는지 보여 준다. 지금 웹 연동 API는 확정 합계·모아둔 돈·마지막 반영 1건만 주므로 이 그래프를 그릴 수 없다. 사용자 결정(2026-10-20)으로 **사용자가 반영을 마친 주기별 기록**을 웹에 넘긴다.

## 2. 무엇을 넘기나

- 수입일 직전 반영 창에서 사용자가 세 방법(`GOAL` 매달 저축할 돈 / `ALL` 남은 돈 전부 / `MANUAL` 직접 입력, 0원 포함) 중 하나로 **반영을 마친 주기마다 1건**. 앱 사용자 API `POST /budget/seed-money/entries`로 저장된 확정 기록 그대로다.
- 넘기지 않는 것(지금과 같음): 반영 대기(`pending`)·반영 창의 후보 금액(`goalAmount`·`allAmount`)·거래·카테고리·예산 상세.
- 반영하지 않고 넘어간 주기는 기록이 없다. 앱이 0원 기록을 만들어 채우지 않는다(웹이 빈 주기로 그린다).

## 3. 계약 제안

기존 `GET /internal/v1/web-links/{linkId}/seed-money`에 필드 두 개를 **더한다**(기존 필드 유지 → 웹 현재 버전과 호환).

```json
{
  "total": 1450000,
  "base": 500000,
  "monthlyGoal": 300000,
  "lastEntry": { "cycleEnd": "2026-09-25", "choice": "ALL", "amount": 950000, "createdAt": "2026-09-24T20:10:00+09:00" },
  "updatedAt": "2026-09-24T20:10:00+09:00",
  "startedOn": "2026-08-26",
  "entries": [
    { "cycleEnd": "2026-09-25", "choice": "ALL", "amount": 950000, "totalAfter": 1450000, "createdAt": "2026-09-24T20:10:00+09:00" }
  ]
}
```

| 필드 | 내용 |
|---|---|
| `entries[]` | 반영을 마친 기록 **전부**, `cycleEnd` 오름차순(오래된 것부터, 그래프 순서). 앱 사용자 API `GET /budget/seed-money`의 `entries`(최근 12개, 최신순)와 범위·순서가 다르다. 기록이 없으면 `[]`. 월 1건이라 수년치도 수십 건이므로 페이지 없이 준다 |
| `entries[].cycleEnd` | 그 정산 주기의 마지막 날(`YYYY-MM-DD`, 앱 `pending.cycleEnd`와 같은 값) |
| `entries[].choice` | `GOAL` · `ALL` · `MANUAL` |
| `entries[].amount` | 그 주기에 옮긴 금액(원 단위 정수, 0 이상) |
| `entries[].totalAfter` | **그 반영 직후의 시드머니 합계**(= `base` + 그 기록까지의 `amount` 합). 웹은 금액을 계산하지 않으므로(웹 ADR-3) 앱이 준다 |
| `entries[].createdAt` | 반영한 시각(+09:00) |
| `startedOn` | 그래프 시작점: 앱에서 예산 설정을 처음 저장한 날(모아둔 돈이 시작된 날). 어떤 값으로 정할지는 앱에서 확정(예: 예산 설정 생성일 또는 `daily_budgets` 첫 날짜) |

- 불변식: 마지막 기록의 `totalAfter` == `total`, `lastEntry` == 마지막 기록(있을 때). 기록이 없으면 `total` == `base`.
- `base`를 나중에 고칠 수 있다면 `totalAfter`를 어느 `base` 기준으로 줄지 정해 문서에 적는다(제안: 현재 `base` 기준으로 다시 계산해 내려줌 → 마지막 `totalAfter`와 `total`이 항상 같음).
- 오류는 지금과 같다: 연동 없음 404 `LINK_NOT_FOUND`, 예산 설정 전 404 `BUDGET_NOT_SET`, 키 오류 401.
- 반영 기록은 수정·삭제가 없다는 전제다. 생기면 `updatedAt`이 바뀌어야 웹이 다시 받는다.

## 4. 완료 기준(앱)

- [ ] 위 필드 추가와 앱 `docs/API.md` "웹사이트 연동" 갱신
- [ ] 테스트: 기록 0건(`entries: []`, `total == base`), 여러 건 오름차순·`totalAfter` 누적, 마지막 `totalAfter == total`, `MANUAL` 0원 포함, 건너뛴 주기 없음 처리, `pending`·후보 금액 미포함, `LINK_NOT_FOUND`·`BUDGET_NOT_SET` 기존 동작 유지
- [ ] 앱 개인정보처리방침에 웹 연동 시 제공 항목(앱 이메일·로그인 방법·확정 시드머니·주기별 반영 기록) 반영 여부를 웹과 함께 결정
- [ ] 배포 뒤 웹 담당에게 배포 시각과 응답 예시(가짜 데이터) 전달

## 5. 웹이 이어서 할 일(참고)

- [x] `applink`: 받은 `entries`를 연동과 함께 저장·삭제(앱 장애 때 마지막 값 표시). 기존 필드만 오는 앱 버전도 처리(V6 `app_link_entries`, #33)
- [x] `seedmoney`: `GET /api/v1/me/seed-money`로 홈·상단 바의 예시 시드머니를 연동 값으로 교체(#33. 비로그인 체험은 계속 예시)
- [ ] 실기기 확인: 앱에서 반영 → 웹 홈 그래프에 다음 조회 때(최대 1분 캐시) 반영
