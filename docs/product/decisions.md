② **시드머니 정의 변경(확정 1 대체)**: 시드머니 = 앱 가입 때 받는 **모아둔 돈** + 수입일 전날마다 사용자가 반영한 금액. 앱은 가입 때 모아둔 돈과 **매달 저축할 돈**(기존 앱의 '보호 금액'과 같은 정보, 이름만 바꿈)을 받는다. 수입일 전날 앱이 알림을 보내고, 누르면 반영 창에서 ① 매달 저축할 돈 ② 실제로 모은 돈 전부(매달 저축할 돈 + 이번 달 남은 생활비) ③ 직접 입력 중 하나를 고른다. 반영한 돈은 앱의 생활비 잔액에서 빠지고, 응답하지 않으면 다음 수입일 전날까지 기다린다. 웹은 이 확정값을 [앱 연동하기]로 받는다. 이에 따라 `current`·`todaySaved`·주기별 계산·추정은 웹으로 오지 않고, 시뮬레이션의 '지금 저축 속도로' 월 금액은 매달 저축할 돈을 쓴다. 시연 대본의 '거래 1건 → 웹 숫자 변화' 장면은 다시 정한다(04 §10). 계약은 [04 §5-2](04-service-boundaries.md).

③ **적금 비교는 한 화면으로(팀 회의).** [그때 들었다면](한국은행 평균 적금 한 줄로 과거 시점 비교)은 뺀다. [정책 적금] 탭은 따로 두지 않고 [지금 가입하면]의 금융권 선택지(은행·저축은행·**정책 적금**)로 합친다. 정책 적금을 고르면 상품 표 아래에 조건 직접 입력 카드가 붙는다. 확정 6의 과거 비교·별도 정책 적금 화면을 대체하며, 정렬만·순위 없음·가입 버튼 없음·자격 판정 없음은 그대로다. 한국은행 평균 적금 금리는 정책 적금 결과의 비교 줄과 F1 비교선(`AVERAGE_SAVINGS`)에 계속 쓴다.

④ **앱 연동 세부(웹 구현 뒤 결정)**: (1) 웹 회원당 앱 연동은 하나, 이미 연동돼 있으면 교체하지 않고 해제 후 다시 연동한다. 시드머니 출처를 하나로 두고, 조용히 교체할 때 앱 쪽에 쓸 수 없는 연동이 남지 않게 한다. (2) [앱 연동하기]는 가입 단계로 강제하지 않고, 홈에 [다음에 할게요]로 닫을 수 있는 안내를 한 번 띄운다. 웹만 쓰는 사용자도 있고 코드를 앱에서 받아야 해서다. (3) 앱 API에 **주기별 반영 기록**을 추가한다. 수입일 직전 반영 창에서 세 방법 중 하나로 반영을 마친 주기마다 1건이며, 홈의 '시드머니가 쌓인 모양'에 쓴다. 누적 합계는 앱이 기록마다 준다(웹은 계산하지 않음). 04 §5-2의 정보 범위를 넓힌 결정이다. (4) 개인정보처리방침은 연동 화면 공개 전에 반영한다(⑤). (5) 앱 서버의 IP 허용 목록은 보류하고 서비스 키만 쓴다.

⑤ **개인정보처리방침은 웹·앱이 각자 둔다.** 웹과 앱은 같은 운영자(우리 팀)지만 계정·서버·DB가 따로라 처리하는 개인정보가 다르다. 웹 방침은 구현 기준으로 쓰고(계획 기능은 도입 전 개정), 운영자·문의처 등 공통 문구는 앱과 같게 둔다. 같은 운영자 안의 이동이라 앱→웹 연동은 제3자 제공으로 보지 않는다(최종 법적 확인은 담당). 이전 규칙 "약관·방침 원문은 앱 웹 하나만"을 대체한다. 이용약관은 당분간 앱 것을 쓴다. 세부는 [privacy-web](privacy-web.md).

### 데이터 저장·자동 갱신 합의

적금·시세는 웹 DB에 최초 적재 후 스케줄러로 갱신한다. 등록 종목의 신규 뉴스는 저장·표시·AI 입력이 허용되는 제공처에서 수집하고, 중복·종목 관련성·중요도를 확인해 사건 핀으로 제공한다. AI 해석은 초안으로 저장한 뒤 검수·승인분만 공개한다. API 페이지 조회와 DB 저장 단위는 나누고, 금리 변경 이력·과거 시세 정정·실패 재개·마지막 성공 데이터 유지를 설계한다.

웹 DB 엔진·호스팅·용량·백업 구성은 미정으로 정리한다. 기존 MySQL·RDS·VM 내 DB 표기는 확정 사양이 아니다. **이번 합의는 목표 구조 결정이며 자동 갱신의 해커톤 포함 여부는 미정**이다. 일정이 별도로 바뀌기 전에는 확정 17의 1회 적재 범위를 유지한다. 상세와 미정 항목은 [웹 데이터 저장·자동 갱신 계획](05-data-refresh.md).
