# 제안: 액티브·패시브 투자 구분(시안)

> **상태: 제안 — 팀 동의 전.** 이 문서와 시안 화면은 논의용이다. 아래 "결정할 것"에 팀이 동의하면 [decisions.md](decisions.md)에 기록하고, 01·02·README §5와 코드에 반영한다. 그 전까지 기존 기획(01 F0~F9)이 정본이다.
>
> 작성: 2026-10-25. 시안 코드는 브랜치 `feat-active-passive-prototype`(Vercel 미리보기)에 있다.

## 1. 왜

- 지금 웹은 종목을 고르는 투자 시뮬레이션이 중심이라 **액티브 투자에 치우쳐 있다.** "주식은 무섭다"는 사회초년생에게 입구가 하나뿐이다.
- 사회초년생에게 널리 알려진 패시브 방식은 "월급 → 계좌 구조(CMA·ISA·연금저축·IRP) → 지수에 꾸준히 → 3~5년 한 바퀴 겪기 → 액티브는 반반에서 시작해 조절"로 요약된다.
- 사용자 대부분은 **액티브와 패시브라는 개념 자체가 생소하다.** 그래서 기존 화면 안의 탭 하나로 넣지 않고, 상위 카테고리부터 둘로 나눠 각 쪽이 자기 말과 자기 숫자를 쓰게 한다.
- 목표 비율: 기능·화면 기준으로 액티브와 패시브를 **반반 정도.**

## 2. 정보 구조(IA)

메뉴 이름은 지금 이름을 유지하고, 두 상위 카테고리 아래로 기능을 편입한다.

```text
상단 메뉴
├─ 액티브 투자 ▾ (골라서 투자)
│   ├─ 액티브 투자란?        /active          새로 만듦
│   ├─ 투자 시뮬레이션        /invest          기존(지난 기록으로 배우기)
│   └─ 분산 투자             /active/diversify 새로 만듦(지금 가진 종목 점검)
├─ 패시브 투자 ▾ (시장 전체에 꾸준히)
│   ├─ 패시브 투자란?        /passive         새로 만듦
│   ├─ 지수 시뮬레이션        /passive/index   새로 만듦
│   ├─ 계좌 설계             /passive/plan    새로 만듦
│   ├─ 계좌 알아보기          /passive/accounts 새로 만듦(CMA는 여기)
│   └─ 적금 모아보기          /savings         기존, 자리만 옮김
├─ AI 계획 수립              /goal            기존
├─ 청년 금융 소식             /news            기존
└─ 플러스                   /plus            기존

반반 실험 /mix  — 두 카테고리를 잇는 화면. 메뉴에는 두지 않고
                 '~란?' 두 화면·지수 시뮬레이션 결과에서 연결한다.
```

- 데스크톱: 카테고리를 누르면 하위 메뉴 패널(항목 이름 + 한 줄 설명)이 열린다. 좁은 화면(1023px 이하): 메뉴 목록 안에 카테고리 제목과 하위 항목을 펼쳐 보여 준다.
- 색으로 두 카테고리를 나누지 않는다(강조 색은 브랜드 블루 하나). 라벨·아이콘·화면 구성으로 나눈다. 액티브는 사건 중심, 패시브는 시간 축·계좌 중심이다.
- 용어 "액티브/패시브"는 그대로 쓴다. 개념을 익히는 게 목적이므로 늘 짧은 풀이("골라서 투자" / "시장 전체에 꾸준히")를 붙인다.

## 3. 적금의 자리

**제안: 패시브 아래의 별도 하위 항목으로 두고, CMA와는 분리한다.**

- CMA와 적금은 쓰임이 다르다. CMA는 월급 다음 날부터 투자 계좌로 옮기기 전까지 **언제든 꺼낼 수 있게 머무는 돈**이다. 적금은 **쓸 날짜가 정해진 돈**(1~2년 안의 이사·등록금 등)을 만기까지 묶어 두는 상품이다. 그래서 CMA는 "계좌 알아보기"에 넣고, 적금은 따로 둔다.
- 패시브 아래에 두는 이유: 둘 다 "정해 두고 꾸준히"라는 같은 태도이고, 패시브 화면의 비교 기준선("적금이었다면")과 이어진다.
- 정책 적금(청년미래적금)은 정부 기여금이 있어 청년에게만 의미가 큰 비교 대상이다. 그래서 적금 화면을 줄이지 않고 지금 기능을 그대로 유지한다.
- 다른 안: (b) 적금을 지수 시뮬레이션 안의 비교선으로만 축소하거나, (c) 상단 메뉴에 그대로 남겨 메뉴를 6개로 둔다.

## 5. 문구·규제 원칙(01 §7 그대로)

- **추천하지 않는다.** 원 자료의 "S&P 500 ETF를 사라", "MMW형이 낫다", "IRP는 증권사에서", "적극 투자를 권한다" 같은 문장은 화면에 쓰지 않는다. 대신 사실(한도·세율·수수료 유무·꺼낼 수 있는지)을 나란히 보여 주고, 고르는 것은 사용자에게 맡긴다.
- 계좌 설계의 단계 배분은 "많이 알려진 방식의 예시"로만 보여 준다. 사용자에게 배분을 정해 주지 않는다.
- 첫 방문 안내는 "어느 쪽부터 볼래요?" 선택만 둔다. 성향 테스트로 한쪽을 골라 주면 추천이 되므로 두지 않는다.
- 과거 계산 화면(지수 시뮬레이션·반반 실험)에는 `SIM_PAST`, 계좌 설명에는 `PRODUCT_CARD` 고지를 붙인다.
- 계좌를 읽어 오지 않으므로 "계좌 연결"이라는 말은 쓰지 않는다. 분산 투자의 "내가 가진 종목"도 사용자가 직접 고른다.
- **분산 투자는 추천으로 읽히기 가장 쉬운 화면이다(01 §7 R1).** 그래서 다음을 지킨다.
  - "이 종목을 담으세요", "부족한 업종" 같은 말을 쓰지 않는다. "같이 덜 움직인 쪽"이라는 지난 기록의 사실로만 쓴다.
  - 목록 순서는 늘 기준(시가총액 순 등)을 적는다. 순위·점수·매수 버튼은 두지 않는다.
  - 고지 문구를 새로 정한다(예: "같이 덜 움직였다는 건 지난 기록이고 앞으로도 그렇다는 뜻이 아니에요. 특정 종목을 사라는 뜻이 아니에요."). 채택 전에 법률 확인(01 §12 Q3)이 필요하다.
- 쓰지 않는 말(01 §7-2): 적립식 → "매달 넣었다면", MDD → "가장 많이 줄어 있던 때", 포트폴리오 → "조합", 매수 → "넣었다면".

## 6. 사실 확인 목록(화면에 올리기 전)

시안의 수치·문장은 2026-10 기준으로 아직 확인하지 않았다. 원 자료와 다르거나 바뀌었을 수 있는 항목:

| 항목 | 시안 문구 | 확인할 것 |
|---|---|---|
| ISA 한도 | 연 2,000만 원 · 총 1억 원 | 한도 확대 논의의 입법 여부, 비과세 한도(일반 200만·서민형 400만), 초과분 9.9% |
| 연금저축 인출 | 꺼낼 수 있지만 공제받은 원금·수익에 16.5% | 원 자료의 "출금 불가"는 부정확하다. 세액공제를 받지 않은 원금은 비과세로 인출되는 점 포함 |
| IRP 중도 인출 | 정해진 사유 말고는 해지 | 법정 사유(무주택자 주택 구입, 6개월 이상 요양 등) 목록 |
| 세액공제 | 연금저축 600만 + IRP 합산 900만, 16.5%/13.2%(총급여 5,500만 원 기준) | 2026년 귀속 기준 유지 여부 |
| 금현물 | 매매차익 비과세, 실물 인출 시 부가세 10% | KRX 금시장 현행 규정 |
| CMA | 예금자보호 아님, MMW 대면 개설 필요한 곳 있음 | 종금형 CMA 예외, 증권사별 현황. 금리는 화면에 숫자로 쓰지 않는다 |
| 청약 | 월 2만~50만 원 인정, 무주택 세대주 소득공제 | 2026년 인정 한도·공제 조건, 부분 인출 허용 여부 |
| IRP 수수료 | 금융사마다 계좌 수수료가 다름 | "증권사는 무료" 같은 단정 대신 금융사별 비교로 쓸지 |

## 7. 결정할 것(팀 논의용)

1. 상위 카테고리를 액티브/패시브로 나누는 IA에 동의하는가?
2. 적금 자리: (a) 패시브 아래 별도 항목(제안) / (b) 지수 시뮬레이션 비교선으로 축소 / (c) 상단 메뉴 유지
3. 반반 실험의 자리: 메뉴 밖에서 연결(제안) / 상단 메뉴에 추가 / 액티브·패시브 양쪽 하위 메뉴에 추가
4. 범위와 순서: 해커톤 전 **① 두 '~란?' 화면 + 메뉴 재구성 ② 지수 시뮬레이션**까지 하고, ③ 계좌 설계·계좌 알아보기는 사실 확인 뒤에 할지
5. 계좌 설계에서 사용자 금액 입력을 받을지. 받으면 서버 계산 API를 만들고, 총급여를 저장하면 개인정보처리방침을 고친다(AGENTS.md 규칙)
6. 기존 F3(조합·프리셋·공유)을 반반 실험으로 대체할지
7. 분산 투자: 화면 범위(세 기준 모두 / 섹터 분산 먼저), 가진 종목을 로그인 회원에게 저장할지, '같이 움직인 정도' 계산 기간(1·3·5년)과 업종 분류 출처(KRX 업종)
